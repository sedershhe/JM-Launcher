## 一、返回值总则

| 项 | 约定 |
| --- | --- |
| JSON 类型 | 除特别说明外，C# 可调用入口**返回 Python `str`**，内容是 `json.dumps(..., ensure_ascii=False)` 的结果（UTF-8，中文不转义） |
| 成功形态 | `{"ok": true, ...业务字段}`；`ok` 恒为布尔 `true` |
| 失败形态 | `{"ok": false, "error_code": "<错误码>", "error_message": "<中文原因>"}` |
| 异常 | 入口函数**不向 C# 抛 Python 异常**（内部已 catch 并转失败形态） |
| DTO 纪律 | C# 反序列化为强类型 DTO；不得把 Python `dynamic` 对象漏到 UI 层 |
| 字段大小写 | 全部 `snake_case`（Python 原名）；C# 反序列化用 `PropertyNameCaseInsensitive=true` |

### 1.1 错误码表（`error_code`）

| 错误码 | 含义 | 典型来源 |
| --- | --- | --- |
| `INVALID_ARGUMENT` | 参数不合法 | 空关键词、空编号列表、空目录、空回调 |
| `NOT_FOUND` | 本子不存在或已下架 | jmcomic `MissingAlbumPhotoException` |
| `NETWORK_ERROR` | 网络请求失败 | `ConnectionError` / `RequestRetryAllFailException` |
| `TIMEOUT` | 网络超时 | `TimeoutError` |
| `RESPONSE_INVALID` | 服务返回内容异常 | `ResponseUnexpectedException` / `JsonResolveFailException` |
| `DOWNLOAD_PARTIAL` | 部分图片失败 | `PartialDownloadFailedException` |
| `JM_ERROR` | 禁漫接口异常（兜底） | `JmcomicException` 基类 |
| `PERMISSION_DENIED` | 文件权限不足 | `PermissionError` |
| `FILE_NOT_FOUND` | 文件/目录不存在 | `FileNotFoundError` |
| `FILE_EXISTS` | 同名文件已存在 | `FileExistsError` |
| `ARCHIVE_INVALID` | ZIP 打不开 / 条目数不符 / 无图片 | `BadZipFile`、校验失败、ZIP 浏览插件 |
| `ARCHIVE_CLOSED` | 压缩包句柄已关闭（读取前必须先打开） | `archive_reader` 读取已 `close` 的包 |
| `PAGE_OUT_OF_RANGE` | 图片页码超出压缩包范围 | ZIP 浏览页面 `image_index` 越界 |
| `IMAGE_INVALID` | 图片不可解码 / 0 字节 / 像素无效 | Pillow、ZIP 校验失败 |
| `INVALID_DATA` | 数据格式不合法 | `ValueError`/`TypeError`/`KeyError`/`JSONDecodeError` |
| `IO_ERROR` | 其它读写失败 | `OSError` |
| `OUT_OF_MEMORY` | 内存不足 | `MemoryError` |
| `NOT_IMPLEMENTED` | 未实现 | `NotImplementedError` |
| `NOT_AVAILABLE` | 功能当前不可用 | 数据源不支持登录等 |
| `INVALID_CREDENTIALS` | 账号或密码不正确 | jmcomic 登录响应 `code != 200`（按异常类型转换，不读文案） |
| `NOT_LOGGED_IN` | 尚未登录，且内存中没有可自动登录的凭据 | `account_login` / `ensure_login` 无凭据 |
| `CANCELLED` | 下载已取消 / 在途登录结果被主动作废 | `CancelledError`；账号凭据在登录途中被修改 |
| `BATCH_NOT_FOUND` | 找不到下载批次 | 取消/查询未知 `batch_id` |
| `UNKNOWN_ERROR` | 未分类异常 | 兜底 |

> 错误分类按**异常类型**完成，不按消息关键词（旧缺陷 #2）。C# 只认
> `error_code`，`error_message` 仅用于展示；错误文案已做凭据脱敏。

## 三、逐函数契约

### 3.1 `health_check() -> dict`

成功（恒为 dict，不抛异常）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | 全部依赖可用为 true |
| `python_version` | str | 如 `3.13.7` |
| `python_executable` | str | 当前解释器路径（仅展示） |
| `platform` | str | 平台描述 |
| `backend_version` | str | 与 `version()` 一致 |
| `packages` | dict[str, str \| null] | 依赖名 → 版本 / `"available"` / null |
| `errors` | list[str] | 缺失依赖的错误描述 |

### 3.2 `version() -> str`

返回后端版本字符串，当前 `"0.3.0"`。

### 3.3 `bootstrap(plugins_dir: str, disabled_json: str = "") -> str`

参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `plugins_dir` | str | 插件目录 |
| `disabled_json` | str | 禁用列表 JSON 数组字符串；**空串表示沿用 `%APPDATA%/JML/plugins/disabled.json`（唯一真源）**；非空表示本次调用显式指定（不落盘，首启迁移用） |

成功：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |
| `loaded` | list[LoadedPlugin] | 成功装配的插件 |
| `failed` | list[FailedPlugin] | 失败项（含 discover 坏目录、被停用项、依赖被阻断项） |
| `services` | dict[str, int] | 装配后注册表快照：服务名 → 版本 |

`LoadedPlugin`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | str | 插件 id |
| `name` | str | 显示名 |
| `version` | str | 插件版本 |
| `description` | str | 插件说明（manifest 可缺省，缺省为空串） |
| `pages` | list[Page] | `{id:str, title:str, template:"list"\|"browser"\|"action"\|"form"}` |
| `development_sample` | bool | 是否测试插件 |
| `enabled` | bool | 恒 true（已加载即启用） |
| `blocked_reason` | str | 恒空串 |

`FailedPlugin`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | str | 插件 id（坏 manifest 用目录名） |
| `reason` | str | 中文原因；被停用为 `插件已停用`，依赖被停用为 `缺少依赖插件 xxx（该插件已停用）` |
| `enabled` | bool | false = 被停用（区别于真正的加载失败） |
| `blocked_reason` | str | 与 `reason` 同值，供界面统一读取 |

被停用插件**不 import、不 setup**，进入 `failed` 且 `enabled=false`。
依赖它的插件同样不加载，`reason` 明确写"缺少依赖插件 xxx（该插件已停用）"。
流程级失败时 `failed` 含 `{"id":"(host)","reason":"..."}`。

失败（缺目录、依赖环等）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | false |
| `loaded` | list | `[]` |
| `failed` | list[FailedPlugin] | 至少一项 |
| `services` | dict | `{}` |
| `error_code` | str | 见错误码表 |
| `error_message` | str | 中文原因 |

线程/幂等：同步执行；**成功结果幂等缓存**，第二次调用（任意
`plugins_dir`、禁用列表未变）原样返回首次成功结果的 JSON（不重复装配）。
禁用列表变化时**只重算状态、不重新 import/setup**（决策 #7：重启生效）：
新停用项移入 `failed`（`enabled=false`），依赖方标注"缺少依赖插件"；
重新启用项若本次进程未加载则提示"插件已启用，重启后加载"。
**失败结果不缓存**：修好插件目录后可再次调用重试。

### 3.4 `list_plugins(plugins_dir: str, disabled_json: str = "") -> str`

返回结构与 `bootstrap` 同构（`loaded` / `failed` / `services` / `ok`，
元素同样带 `enabled` / `blocked_reason`），但**不 import、不 setup、不注册服务**；
`services` 只是当前注册表快照。被停用插件进入 `failed`（`enabled=false`），
依赖它们的插件以"缺少依赖插件 xxx"失败。`disabled_json` 语义同 3.3。
失败时额外带 `error_code` / `error_message`。同步执行。

### 3.4.1 `set_plugin_enabled(plugin_id: str, enabled: bool) -> str`

把启用/停用状态写入 **唯一真源** `%APPDATA%/JML/plugins/disabled.json`
（被停用 id 的 JSON 数组，原子写：临时文件 + `os.replace`）。

成功：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |
| `plugin_id` | str | 被操作的插件 id |
| `enabled` | bool | 操作后的状态 |
| `status` | str | `enabled` / `disabled` |

失败：

| 场景 | error_code |
| --- | --- |
| 空 id | `INVALID_ARGUMENT` |
| id 不在最近一次扫描结果里 | `NOT_FOUND` |
| disabled.json 写盘失败 | `IO_ERROR` |

生效范围（决策 #7）：**只更新状态与后续 bootstrap/scan 结果，不热加载、
不卸载当前进程里已 import 的插件；重启后真正生效。**

### 3.4.2 `get_plugin_management_state(plugins_dir: str) -> str`

插件管理界面专用：只扫描 manifest，不 import 插件；结合最近一次
bootstrap 的装配结果与当前 disabled.json 推导状态。

成功：

```json
{"ok": true, "plugins": [
  {"id": "zip_web", "name": "ZIP 网页浏览", "version": "0.1.0",
   "description": "...", "enabled": true, "status": "loaded",
   "reason": "", "dependents": ["other_plugin"]}
]}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` / `name` / `version` / `description` | str | manifest 信息（坏目录用目录名） |
| `enabled` | bool | false = 已停用 |
| `status` | str | `loaded` / `disabled` / `failed` |
| `reason` | str | 空串 = 正常；否则为停用/失败原因 |
| `dependents` | list[str] | **直接或间接**依赖它的插件 id（拓扑关系算出，供停用前提示） |

失败时 `{"ok": false, "plugins": [], "error_code": ..., "error_message": ...}`。

### 3.4.3 禁用列表真源与旧设置迁移

- `disabled.json` 是唯一真源；C# **不得**再维护自己的禁用列表判断。
- 旧 `AppSettings.DisabledPlugins` 由 C# 在首次进入插件管理时迁移一次：
  作为显式 `disabled_json` 传给本次 `bootstrap`（保证停用立刻影响这次装配），
  随后逐项调用 `set_plugin_enabled` 落盘，成功后清空旧字段；Python 调用
  失败则保留旧字段，下次启动重试。

### 3.5 `set_event_sink(callback) -> str`

注册事件汇聚出口。`callback` 是 C# 委托，签名固定为
**`void callback(string eventJson)`**（一个字符串参数）。

`eventJson` 形如：

```json
{"type": "download.log", "payload": {"type": "download.log", "level": "info", "message": "开始下载 JM123", "batch_id": "..."}}
```

| 成功 | `{"ok": true}` |
| --- | --- |
| 失败 | `{"ok": false, "error_code": "INVALID_ARGUMENT", "error_message": "事件回调必须是可调用对象"}` |

纪律：sink 在全部 Python 订阅者投递完之后调用；sink 抛异常只记入
`last_dispatch_errors`，不影响订阅者。C# 回调内**禁止再调 Python**，
只能入队后由 UI 线程取出（技术方案第十节）。

### 3.6 `clear_event_sink() -> str`

移除事件出口。成功 `{"ok": true}`，失败同上。

### 3.7 `parse_book_ids(text: str) -> str`

成功：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |
| `book_ids` | list[str] | 去重保序的纯数字编号；前导零原样保留 |
| `count` | int | 列表长度 |

规则：分隔符 `-` `,` `，` `、` `;` `；` 与任意空白；空串/无有效数字 →
`book_ids: []`（仍算成功）；非纯数字 token（`JM123`、`12a`）丢弃。

### 3.8 `start_download(book_ids_json: str, target_dir: str, work_dir: str = "") -> str`

参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `book_ids_json` | str | 推荐 JSON 数组字符串 `"[123, 456]"`；也接受纯文本编号串；**非纯数字 token 整批拒绝** |
| `target_dir` | str | 下载目录（由 C# 传入；不存在会自动创建） |
| `work_dir` | str | 可选临时工作目录父目录（缺省 = `target_dir`；不硬编码） |

成功（**立即返回**，不等待下载）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |
| `batch_id` | str | 批次 id（后续取消/查询用） |
| `total` | int | 去重后的本子数 |
| `status` | str | 固定 `"running"` |

失败：`INVALID_ARGUMENT`（编号列表为空 / 含非纯数字 / 目录不可用）。

临时目录降级：`work_dir` 不可用（`PermissionError` / `OSError`）时，单本自动降级到
`<target_dir>\.jml-tmp-<book>-<rand>`，并记一条 `download.log`（`level=warn`，已脱敏）；
降级后的临时目录同样在批次结束时清理；两处都不可用则该本失败（`PERMISSION_DENIED`，
消息带两处路径）。

线程语义：登记批次后起后台线程；所有批次合计最多 3 本并发；C# 不得同步等待，
结果通过事件回推。打包先写 `*.zip.part`，校验通过后原子替换；失败/取消会
清理 `.part` 与 0 字节占位文件。

### 3.9 `cancel_download(batch_id: str) -> str`

成功：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |
| `batch_id` | str | 原批次 id |
| `cancelled` | bool | 固定 `true`（已置取消标志） |

失败：`BATCH_NOT_FOUND` / `INVALID_ARGUMENT`。

线程语义：只 set 取消事件后**立即返回**，不等待下载线程；正在跑的每本在
"每本开始/每章/每图"检查点退出，剩余未开始的本子直接计入 `cancelled`。

### 3.10 `search(keyword: str, page: int, session_key: str = "main") -> str`

成功：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |
| `keyword` | str | 实际使用的关键词（可能来自快照） |
| `page` | int | 实际页码（≥1） |
| `total_pages` | int | 总页数（≥0） |
| `results` | list[SearchResultItem] | 当前页结果 |

`SearchResultItem`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `book_id` | str | JM 号 |
| `title` | str | 标题 |
| `author` | str | 作者（可能为空串） |
| `page_count` | int | 页数。**优先用数据源页数**；列表接口没给时由 Python 有界并发补全（见下方"页数补全"），仍取不到才为 0 |
| `tags` | list[str] | 标签 |
| `cover_url` | str | 封面 URL（C# 显示封面请调 `fetch_cover`，不要自己下载） |

翻页语义（旧缺陷 #8）：`page <= 1` = 发起新搜索并**快照关键词**；
`page > 1` = 使用会话里的快照关键词，忽略本次传入的 `keyword`。
换关键词必须重新以 `page=1` 发起搜索。

共享语义（单一所有者 + 按 key 隔离）：后端入口 `search()` 与插件服务
`jm.search` 都通过 `jml.core.searcher.get_session(key)` 取会话。
`session_key` 默认 `"main"`（主界面）；插件经 `ctx.call_service` 调用时
host 自动注入 `plugin:<plugin_id>`。不同 key 各有自己的关键词快照，一方
`page=1` 不会改另一方；禁止各自再 new 会话。

页数补全（DATA-1）：jmcomic 2.7.1 的搜索列表接口每条只返回 `name` / `tags`
等字段，**不含页数**，所以列表原始 `page_count` 恒为 0。Python 在返回一页
结果前，对当前页里 `page_count <= 0` 的条目做**有界并发详情补全**：

- 并发上限 **3**（与下载并发纪律一致）；
- 当前页整体最多等 **3 秒**，超时后未完成的条目保持 `0`（不伪造，也不阻塞返回）；
- 单条补全失败只让该条为 `0`，不影响其它条目与搜索结果本身；
- 补到的正数进**进程内缓存**，来回翻页不会反复请求同一本；失败不缓存，下次还能重试；
- 因此 `page_count` 的语义是"优先真实值，取不到才是 0"，**不是**"数据源未提供就恒为 0"。
  C# 只管显示，不需要也不允许自己补 0 之外的值。
  （jmcomic 一页实际返回 80 行，3 秒预算下通常只能补上首屏若干行；
  其余行随重复搜索/翻页通过缓存逐步补齐。）

失败：`INVALID_ARGUMENT`（关键词为空）。同步网络调用 → C# 用 `Task.Run`。

### 3.11 `get_detail(book_id: str) -> str`

成功：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |
| `book_id` | str | JM 号 |
| `title` | str | 标题 |
| `author` | str | 作者 |
| `page_count` | int | 页数。**优先用数据源页数，取不到才为 0** |
| `tags` | list[str] | 标签 |
| `description` | str | 简介；超过 200 字已截断并追加 `…` |
| `description_truncated` | bool | 是否发生过截断 |
| `cover_url` | str | 封面 URL |

失败：`INVALID_ARGUMENT`（空编号）或其它错误码。**截断只在 Python 做**，
C# 直接显示 `description`。

页数来源（DATA-1）：jmcomic 2.7.1 的 API 适配层把 `JmAlbumDetail.page_count`
硬编码为 `0`（`post_adapt_album`），真实页数只在专辑原始响应的 `total_photos`
字段里。Python 侧取一次原始响应并用 jmcomic 自己的解析器构造专辑实体
（请求数与原来相同），因此 **`get_detail` 返回的就是真实页数**：实测
`651712 → 42`、`565384 → 34`，与下载 ZIP 内图片数一致。只有数据源确实
取不到时才为 `0`。

成功：`{"ok": true, "delivered": int, "errors": list[str]}`；

仅测试/诊断用，正常业务不依赖。

可选诊断落盘（默认只在内存）。成功：
`{"ok": true, "log_dir": "<绝对目录或空串>"}`；传空串关闭落盘。

| `count` | int | `len(records)` |

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | true |

## 五、事件契约

### 5.1 信封

C# sink 收到的每个事件都是：

```json
{"type": "<event_type>", "payload": { ... }}
```

`payload` 自身也带 `type` 字段（与信封一致），并含
`Python/jml/core/protocol.py` 的 `EVENT_PAYLOAD_SCHEMAS` 所列必填字段。
下载类事件额外带 `batch_id`（协议表只校验必填字段，额外字段允许）。

### 5.2 事件表

| `type` | 必填 payload 字段（类型） | 额外字段 | 触发时机 |
| --- | --- | --- | --- |
| `download.item_started` | `book_id`(str), `title`(str) | `batch_id`(str) | 已取到本子标题、开始下载该本 |
| `download.item_finished` | `book_id`(str), `title`(str), `ok`(bool), `zip_path`(str), `error_code`(str), `error_message`(str) | `batch_id`(str) | 每本结束（成功/失败/取消） |
| `download.batch_finished` | `total`(int), `success`(int), `failed`(int), `cancelled`(int) | `batch_id`(str) | 批次全部结束，必发一次 |
| `download.log` | `level`(str), `message`(str) | `batch_id`(str) | 批次开始/单本开始/保存/失败/批次结束 |
| `search.page_loaded` | `keyword`(str), `page`(int), `total_pages`(int), `results`(list) | 无 | 搜索成功后 |
| `plugin.notification` | `level`(str), `title`(str), `message`(str) | 无 | 阶段 2 未使用（协议保留） |

补充：

- `download.item_finished.ok == true` 表示 ZIP 已生成且五项校验通过；
  `zip_path` 是最终文件名（同名副本已由 Python 处理）。
- 取消发生时，**已开始**的本子会发 `item_finished`（`ok=false`,
  `error_code="CANCELLED"`）；取消前从未启动的本子**不发** `item_started` /
  `item_finished`，但会计入 `batch_finished.cancelled`。
- 日志已脱敏（password/passwd/token/cookie/authorization/username 等打码）；
  jmcomic 自带 logger 也被接管：**WARNING 及以上**才转 `download.log` 事件，
  INFO/DEBUG 只进诊断环表（避免 300 页下载时每页一次同步回调）。
- `download.log.payload.batch_id`：下载线程内产生（含 jmcomic 日志转发）为
  当前批次 id；非下载线程（如宿主初始化）为空串 `""`，C# 归入全局日志窗。
- 事件在**触发它的 Python 线程**上回调（下载事件在下载工作线程），
  C# 必须 `Dispatcher.Invoke` 编组到 UI 线程。
- `download.log` 只走全局事件总线；C# 从 sink 收全部日志并按
  `payload.batch_id` 分窗，不再争抢同一个处理器（旧缺陷 #6）。错误日志行
  统一为 `[{error_code}] 消息`，成功路径省略前缀。
- 订阅者或 C# sink 抛异常会同时写入诊断环表（`EVENT_HANDLER_FAILED`），
  后台线程的错误可通过 `get_diagnostics()` 读取，不再只留在线程局部。
- `last_dispatch_errors()` 是**线程局部**的：并发 dispatch 时各线程只读取自己
  那次派发的错误，不会串到别的事件。
- 批次状态先提交再发 `batch_finished`：处理器内调用
  `jm.download.get_progress` 已是 `finished` 且 `result` 非空；所有状态/结果
  查询返回副本，插件改写返回值不影响内部记录。

## 六、宿主服务契约（插件调用）

**插件唯一调用路径**：`ctx.call_service(name, version, method, payload) -> dict`。
它等价于 `ctx.get_service(name, version).call(method, payload)`，但"取服务 +
校验 `call` 方法"由宿主收口；插件不得 import `jml.host.registry`、不得直接摸
注册表/事件总线本体（旧缺陷 #9）。取不到服务或服务对象无 `call` 方法 →
抛 `ServiceError`。

会话隔离：host 在转发时给 payload 追加 `_caller="plugin:<plugin_id>"`，
`jm.search` 据此使用 `plugin:<plugin_id>` 会话；插件不能改写该标识，
也不会污染主界面 `main` 的翻页快照。

统一签名：`call_service(name, version, method, payload) -> dict`。
服务名与版本：

| name | version | methods | payload | 成功返回 |
| --- | --- | --- | --- | --- |
| `jm.search` | 1 | `search`, `get_page` | `{"keyword": str, "page": int}`（`get_page` 可省略 keyword） | 同 `search()` 成功 JSON |
| `jm.detail` | 1 | `get_detail` | `{"book_id": str}` | 同 `get_detail()` 成功 JSON |
| `jm.download` | 1 | `start_batch` | `{"book_ids": list[str], "target_dir": str, "work_dir"?: str}` | `{"ok": true, "batch_id": str, "total": int, "status": "running"}` |
| `jm.download` | 1 | `cancel_batch` | `{"batch_id": str}` | `{"ok": true, "batch_id": str, "cancelled": true}` |
| `jm.download` | 1 | `get_progress` | `{"batch_id": str}` | `BatchStatus` |
| `jm.account` | 1 | `login_status`, `ensure_login`, `login`, `logout` | 任意 dict（账号密码字段**不读取**） | 账号状态结构（见 §十） |
| `jm.session` | 1 | `get_client`（**对象服务**，不走 `call_service`） | 无（`ctx.get_service("jm.session", 1).get_client()`） | 宿主 `jm_source` 里**已登录**的 jmcomic 客户端对象 |

`jm.account` 与顶层 `account_*` 入口共用 `jml.core.account` 的同一份内存状态，
不各自维护副本；服务层不抛业务失败，未知方法名仍抛 `ServiceError`。
**插件不能通过服务 payload 传账号密码**：`login` 只使用主程序经
`account_set_credentials` / `account_login_with` 写入的凭据；payload 里的
`username` / `password` 一律忽略。

**`jm.session/1`（宿主提供，阶段 4-4：收藏夹等需要登录态的只读功能）**

客户端对象无法塞进 `call_service` 的 JSON 信封，因此它是**强类型对象服务**
（与 `archive_reader/1` 同类）：插件在 `setup` 里
`service = ctx.get_service("jm.session", 1)`，读收藏夹时调用
`service.get_client()`。服务对象**没有** `call` 方法，用
`ctx.call_service("jm.session", 1, "get_client", ...)` 会抛 `ServiceError`。

| 方法 | 参数 | 返回 / 失败 |
| --- | --- | --- |
| `get_client()` | 无 | 宿主 `jm_source` 里**已登录**的 jmcomic 客户端对象（含内存登录 cookies，同一实例）；未登录 → 抛 `NotLoggedInError`（错误码 `NOT_LOGGED_IN`） |

语义锁定：

- **不自动登录**：插件必须先调 `jm.account.ensure_login`（`jm.account` 用主进程
  内存凭据登录）；`get_client()` 只负责把已登录会话交出去；
- **不交凭据**：服务只返回客户端对象，不返回账号、密码或 cookie 字典；插件没有
  任何读取凭据的通道；
- **不产生新会话**：返回宿主缓存的同一个客户端实例，插件只读使用；
- 宿主 bootstrap 时与 `jm.search/jm.detail/jm.download/jm.account` 一起注册；
  插件在 manifest 里声明 `services.requires: [{"name": "jm.session", "version": 1}]`，
  缺该服务时宿主拒绝加载并报「插件 xxx 缺少服务 jm.session/版本 1」；
- 数据源协议新增可选方法 `logged_in_client()`（真实实现见
  `jml.core.jm_source.JmcomicSource.logged_in_client`）；测试用假数据源同样实现它。

失败：`{"ok": false, "error_code": ..., "error_message": ...}`。
未知方法名 → 抛 `ServiceError`（插件拼错方法名属开发错误，不是业务失败）；
未知服务名/版本、或提供者没有 `call` 方法 → `ctx.call_service(...)` 抛 `ServiceError`。

入口与服务的关系：C# 侧查进度走顶层入口 `get_progress(batch_id)`（§3.16），
插件侧仍走 `jm.download.get_progress` 服务（§六表格）；两者返回同一份
`BatchStatus`，共享同一个批次登记表，不各自维护状态副本。

**`archive_reader/1`（ZIP 浏览插件提供，阶段 4-2）**

图片是原始 `bytes`，无法塞进 `call_service` 的 JSON 信封，因此它是**强类型对象
服务**：插件用 `ctx.get_service("archive_reader", 1)` 取得服务对象后直接调用方法
（该服务对象没有 `call` 方法，不走 `ctx.call_service`）。

| 方法 | 参数 | 返回 / 失败 |
| --- | --- | --- |
| `list_images(zip_path)` | `str` | `list[str]`：包内图片条目名（**自然排序**）；未打开则先打开。路径不存在 → `压缩包不存在`（`FILE_NOT_FOUND`）；非 ZIP → `不是有效的 ZIP 压缩包`（`ARCHIVE_INVALID`）；没有图片 → `压缩包中没有可浏览的图片`（`ARCHIVE_INVALID`） |
| `read_image(zip_path, index)` | `str`、`int`（0 起） | `bytes` 原始图片；未打开/已 `close` → `压缩包已关闭`（`ARCHIVE_CLOSED`）；下标越界或非法 → `页码超出范围`（`PAGE_OUT_OF_RANGE`） |
| `close(zip_path)` | `str` | `None`；幂等，未打开时不报错 |
| `is_open(zip_path)` | `str` | `bool`：当前是否保持打开（`read_image` 的前置条件） |

服务对象**不持有任何宿主对象**（没有 ctx / 注册表 / 事件总线），四个方法共用
一把显式 `threading.RLock`；`read_image` 只返回包内字节，**不解压到磁盘**。
失败抛 `AppError` 子类，`error_message` 与计划书 11.6 的五条文案逐字一致。

## 七、线程与阻塞语义

| 调用 | 是否阻塞 | 说明 |
| --- | --- | --- |
| `bootstrap` / `list_plugins` | 同步 | 读盘 + 可能 import 插件；C# 启动期在后台线程调用 |
| `set_plugin_enabled` / `get_plugin_management_state` | 同步 | 读写 disabled.json / 扫描 manifest，不 import 插件；C# 用 `Task.Run` 包装 |
| `search` / `get_detail` / `fetch_cover` | 同步网络 | C# 必须 `Task.Run` 包装，禁止占用 UI 线程 |
| `account_login` / `account_login_with` | 同步网络 | 登录请求可能耗时，C# 必须 `Task.Run` 包装 |
| `account_set_credentials` / `account_status` / `account_logout` / `account_clear` | 同步、不联网 | 只读写进程内存，可以在 UI 线程直接调用 |
| `start_download` | **立即返回** | 后台线程下载；C# 不得等待完成 |
| `cancel_download` | **立即返回** | 只 set 取消事件，不等下载线程退出 |
| 事件回调 | 异步 | 在 Python 工作线程触发；C# 入队 → UI 线程 |
| `set_event_sink` | 同步 | 建议在 UI 启动时注册一次 |

Python 侧共享状态：`jml_backend._STATE` + `threading.RLock`；
服务注册表、事件总线、下载批次表均显式加锁（旧缺陷 #10）。

## 八、行为等价锚点（C# 不得重复实现）

| 项 | Python 侧已锁定 |
| --- | --- |
| 并发 | 进程内**所有批次合计**同时最多 3 本（批次内线程池 3 + 模块级全局信号量） |
| 批量编号分隔符 | `-` `,` `，` `、` `;` `；` 空白；去重保序。**`parse_book_ids` 丢弃非法 token；`start_download` / `jm.download.start_batch` 整批拒绝非纯数字** |
| 产物命名 | `{标题}-JM{编号}.zip`；标题取不到 → `未知标题-{编号}.zip` |
| 文件名剥字符 | `\ / * ? : " < > |`；首尾空白与点去掉；编号同样清洗（防路径穿越） |
| 同名副本 | `xxx.zip` → `xxx - 副本.zip` → `xxx - 副本 (2).zip` → `(3)`…（不覆盖） |
| ZIP 内条目 | `001.ext`、`002.ext`…（三位零填充，后缀取首图扩展名） |
| 打包校验 | ZIP 可打开、条目数 == 图片数、图片可解码、像素 > 0、无零字节条目 |
| 取消 | 真取消：每本/每章/每图检查点，set 后下一检查点退出；未开始本不发 item 事件但计入 cancelled |
| 详情简介 | 超 200 字截断并追加 `…`，`description_truncated` 标记 |
| 搜索翻页 | 绑定发起搜索时的关键词快照 |
| 单本失败 | 不影响其它本；`batch_finished` 统计成功/失败/取消 |

## 九、C# 接入必做清单

1. `PluginBridge.CallJson` 直接 `JsonSerializer.Deserialize<T>((string)backend.xxx(...))`
   —— 阶段 2 起 `bootstrap` / `list_plugins` 已是合法 JSON 字符串。
2. 启动时 `set_event_sink(new Action<string>(OnPythonEvent))`；回调内只入队，
   由 UI 线程解析 JSON 并 `Dispatcher.Invoke` 更新界面。
3. 启动时调 `set_log_dir(<LOCALAPPDATA 下由 C# 计算>\JML\logs)`；
   需要展示诊断时调 `get_diagnostics(limit)` 读取已脱敏环表。
4. `start_download` 必须显式传 `work_dir = <LOCALAPPDATA>\JML\tmp`
   （不传时 Python 默认用下载目录；崩溃残留会落在用户下载夹）。
5. `start_download` 返回后立即用 `batch_id` 更新界面，**不要等待**；
   所有进度以事件为准；`download.log` 按 `payload.batch_id` 分窗。
6. 取消按钮调 `cancel_download(batch_id)`，按钮状态等 `batch_finished`
   或后续 `item_finished` 事件再恢复。
7. 搜索结果行封面的字节来自 `fetch_cover(book_id)`；失败显示暗红底 `X`，
   这属于 UI 表现，不要写进 Python。
8. 完成弹框文案由 C# 用 `batch_finished` 的 `success/total/failed` 拼装：
   `完成，成功 {success} / 共 {total}，失败 {failed}`。
9. 禁止在 C# 侧做：文件名清洗、200 字截断、翻页关键词记忆、同名覆盖判断、
   错误文案分类——这些全部以 Python 返回值/事件为准。
10. **禁止**在 C# 侧直接取 `jml.services.host_services.HOST_SERVICES` 模块全局，
   也**禁止**调用后端私有函数（如 `_dumps`）；所有 C# 调用只走 `jml_backend`
   的公开顶层入口（查进度用 `get_progress(batch_id)`，不绕宿主服务）。
11. **账号凭据的持久化只在 C# 侧**：Windows 凭据管理器（首选）/ DPAPI 加密
    文件；不得写进 `settings.json`、插件配置、日志或提交记录。Python 的
    `account_*` 入口只把凭据放在进程内存，不落盘。
12. 账号录入 / 修改窗口：先 `account_clear()`，再 `account_set_credentials`
    + `account_login`（需要保留“可重试凭据”时），或直接
    `account_login_with(username, password)`（一次性）。成功后用
    `account_status()` 的 `username_masked` 显示账号；未登录显示“未登录”。
13. `account_login` / `account_login_with` 是**同步网络**调用，必须
    `Task.Run`；`account_set_credentials` / `account_status` /
    `account_logout` / `account_clear` 不联网，可直接在 UI 线程调用。
14. 未登录时收藏夹必须明确提示；插件调 `jm.account.ensure_login` 得到
    `NOT_LOGGED_IN` 时显示「未登录，无法浏览收藏夹」，不要自己尝试登录。
    登录成功后的客户端由宿主服务 `jm.session/1` 的 `get_client()` 交给插件
    （客户端对象，不含凭据）；C# 与插件都不得读写密码。
15. `username_masked` 只用于显示，不得当作真实账号回写配置或用于任何
    认证判断。

## 十、账号与登录态（阶段 3 新增）

### 10.1 状态结构（所有 `account_*` 入口共用）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ok` | bool | 本次调用是否成功；`account_status` 是纯查询，恒为 `true` |
| `logged_in` | bool | 当前是否已登录 |
| `username_masked` | str | 用户名打码；未配置账号为 `""`，未登录但已配置时仍给打码 |
| `error_code` | str | 成功 / 纯查询为 `""`；失败见 §10.3 |
| `error_message` | str | 成功 / 纯查询为 `""`；失败为已脱敏中文 |

额外字段：

| 字段 | 出现入口 | 说明 |
| --- | --- | --- |
| `credentials_kept` | `account_logout` | 是否仍保留内存凭据（默认 `true`） |
| `credentials_cleared` | `account_clear` | 固定 `true` |

`username_masked` 打码规则（`jml.core.account.mask_username`）：

- 空账号 → `""`；
- 1~2 字符 → `***`；
- 3~5 字符 → 首尾各留 1 个字符，如 `a***c`；
- 6 字符及以上 → 首尾各留 2 个字符，如 `ab***cd`。

明文用户名与明文密码**都不进入任何返回值**。

### 10.2 入口语义

| 入口 | 语义 | 失败 |
| --- | --- | --- |
| `account_set_credentials(username, password)` | 校验后写入/覆盖进程内存；账号或密码变了就让旧登录态失效；不会自动登录 | 空账号/空密码/非字符串 → `INVALID_ARGUMENT` |
| `account_login()` | 用内存凭据登录；成功后 `logged_in=true`、写打码用户名 | 无凭据 `NOT_LOGGED_IN`；登录失败见 §10.3 |
| `account_login_with(username, password)` | 一次性登录：**本次凭据不写入长期内存**；成功后会话留在数据源客户端，但之后 `ensure_login` 不会用这次凭据重登 | 同上 |
| `account_logout()` | 默认**保留内存凭据**，只清登录态与数据源会话 cookie | `credentials_kept` 告知是否还能自动重登 |
| `account_status()` | 查询登录态；纯查询，不联网 | 恒 `ok=true`，错误字段为空串 |
| `account_clear()` | 清空内存凭据 + 登录态 + 数据源会话（“修改账号”前调用） | 恒 `ok=true` |

`ensure_login()`（后端入口不直接暴露，但 `jm.account` 服务提供）三态：

| 情况 | 行为 | `error_code` |
| --- | --- | --- |
| 已登录 | 直接返回，不调用数据源 | `""` |
| 未登录且内存有凭据 | 调 `source.login`；成功后 `logged_in=true` | `""` 或 §10.3 的分类错误 |
| 未登录且内存无凭据 | 不联网，立即失败 | `NOT_LOGGED_IN` |

失败时统一返回 `ok=false` + `error_code` + `error_message`，账号结构额外带
`logged_in=false` / `username_masked`，方便界面直接显示，不需要二次查询。

### 10.3 登录失败分类（按异常类型，不读文案）

| 错误码 | 触发条件 |
| --- | --- |
| `INVALID_CREDENTIALS` | jmcomic 登录 API 返回 HTTP 200 但 JSON `code != 200`（转换为 `InvalidCredentialsError`），或数据源以 `False` 表示凭据错误 |
| `NETWORK_ERROR` | `RequestRetryAllFailException`、`ConnectionError` |
| `TIMEOUT` | `TimeoutError`；以及等待其它线程登录结果超时（120 秒） |
| `JM_ERROR` | 其它 `JmcomicException`；登录 API HTTP 5xx |
| `NOT_LOGGED_IN` | 未登录且内存没有凭据 |
| `NOT_AVAILABLE` | 当前数据源没有实现 `login` |
| `CANCELLED` | 登录过程中凭据被修改 / `account_clear` / `account_logout`，在途结果被丢弃 |

### 10.4 jmcomic 2.7.1 登录 API 查证

- 默认客户端是 API 实现：`JmModuleConfig.DEFAULT_CLIENT_IMPL = 'api'`
  （`jmcomic/jm_config.py:471`），`JmOption.default().new_jm_client()` 得到
  `jmcomic.jm_client_impl.JmApiClient`。
- 登录调用 `client.login(username, password)`
  （`jmcomic/jm_client_impl.py:802-838`），内部 `req_api('/login', False,
  data={...})`；`req_api` 默认 `require_success=True`（同文件 `:884-897`）。
- `JmApiResp.is_success` 要求 HTTP 成功且 JSON `code == 200`
  （`jmcomic/jm_client_interface.py:113-114`）；失败由
  `require_success` 抛 `ResponseUnexpectedException`（`:40-45`，
  `jmcomic/jm_exception.py:137-147`）。`jm_source` 只按这个**类型**把它转成
  `INVALID_CREDENTIALS`；HTTP 5xx 按结构化状态码转 `JM_ERROR`。
- 登录成功后 `JmApiClient.login` 只把 cookies 写进**内存**里的 postman
  元数据（`jm_client_impl.py:834-836`），不写任何文件，也不会调用
  `JmOption.to_file()`；Python 侧从不把账号密码放进 option 配置。
- `JmApiClient.login` **不设置** `client._username`；只有网页端
  `JmHtmlClient.login` 会设置（同文件 `:414-415`）。匿名会话同样带
  `AVS` cookie，所以 **`AVS` 不能作为登录态判据**。Python 在
  `JmcomicSource` 里用 `_logged_in` 显式记录“本次进程成功登录过”，
  `is_logged_in()` 以它为准（网页端 `_username` 作为辅助信号）。
- 全项目只有 `Python/jml/core/jm_source.py` import jmcomic；账号模块与
  入口都不直接引用第三方库。

### 10.5 线程与锁纪律

- 账号状态放 `jml.core.account._STATE`，用显式 `threading.RLock` 保护。
- **网络请求绝不在持锁期间执行**：先快照凭据 → 释放 `_STATE_LOCK` →
  调 `source.login` → 回锁提交状态；提交前用 `generation` 校验凭据没被改过。
- 单飞（single-flight）：同一时刻只允许一个登录在途，其余线程等待同一个
  结果，不会重复调用数据源；等待上限 `LOGIN_WAIT_SECONDS=120` 秒。
- `JmcomicSource` 自己的客户端/登录态用独立 `RLock` 保护；登录与下载共用
  同一个客户端会话，不新建第二份客户端。
- `account_login_with` 也占用同一个“在途登录”槽位，避免与
  `ensure_login` 并发登录。

### 10.6 凭据安全自证

- **不落盘**：`jml.core.account` 不 import `os` / 不使用任何文件写 API；
  不调用 `JmOption.to_file()`；凭据只存在 `_STATE["username"]` /
  `_STATE["password"]` 两个内存键里。
- **不进日志**：登录成功只记打码用户名；登录失败只记错误码、异常类型名
  与经 `_scrub` 处理后的文案；诊断记录**不挂原始登录异常对象**（其
  traceback 可能夹带响应原文）。所有对外文本再过 `sanitize_text`
  （覆盖 password/passwd/token/cookie/authorization/username 等）。
- **不进异常消息**：`jm_source.login` 抛出的凭据错误使用固定文案
  “账号或密码不正确”，并用 `from None` 切断原始响应异常链；HTTP 5xx 也只
  给固定文案。
- **回传打码**：任何返回值只含 `username_masked`，不含明文用户名/密码。
- **来源纪律**：真实凭据由 C# 的 Windows 凭据管理器 / DPAPI 读出后经
  `account_set_credentials` / `account_login_with` 传入；测试凭据只允许
  由测试辅助读取 `JML_TEST_CREDENTIALS_FILE` 指向的本地不入库 JSON，
  **该文件读取逻辑不进入产品代码路径**；代码中零硬编码账号。
- **测试**：账号用例全部离线（假数据源）；真实登录只作为人工验证，
  不进入 pytest。

## 十一、插件设置项（阶段 3 任务 3-B 新增）

对应技术方案 2.5「配置契约」与功能计划书 4.8 / 决策 #11：插件在 manifest 的
`config.schema` 里声明设置项，主设置窗口据此生成动态表单；**schema 既是默认值
来源，也是写入校验的唯一依据**（对应旧缺陷 #5：schema 真正参与校验）。

### 11.1 `list_plugin_settings() -> str`

无参数，返回已加载插件的设置定义（只读，不写盘、不联网）：

```json
{
  "ok": true,
  "plugins": [
    {
      "plugin_id": "history",
      "plugin_name": "下载历史",
      "fields": [
        {"key": "limit", "label": "保留条数", "type": "number",
         "default": 200, "value": 200, "options": [], "min": 10, "max": 5000},
        {"key": "mode", "label": "排序", "type": "select",
         "default": "recent", "value": "recent",
         "options": ["recent", "clicks", "images"]},
        {"key": "dir", "label": "ZIP 目录", "type": "path",
         "default": "", "value": "", "options": []},
        {"key": "token", "label": "访问令牌", "type": "password",
         "default": "", "value": "", "options": [], "has_value": true}
      ]
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `plugins[]` | 数组 | 只含**已加载且 schema 非空**的插件；加载失败/无设置项的插件不出现 |
| `plugin_id` | str | manifest 的 id（写回设置时原样使用，C# 不得推导） |
| `plugin_name` | str | manifest 的 name（分组标题） |
| `fields[]` | 数组 | 顺序与 schema 声明一致 |
| `key` | str | schema 里的键 |
| `label` | str | 显示标签；schema 未给 `label`/`title` 时回填为 key |
| `type` | str | 见 §11.3，**只允许六种** |
| `default` | 标量 | schema 生成的默认值（password 恒为空串） |
| `value` | 标量 | 当前生效值（已合并默认值与落盘值）；password 恒为空串 |
| `options` | 数组 | `select` 的可选值（元素可为字符串/数字/布尔），其余类型为空数组 |
| `min` / `max` | 数字 | 仅 schema 声明时出现，供界面提示；C# 不据此自行判合法性 |
| `has_value` | bool | **仅 password 出现**：是否已设置过值（明文不回传） |

顺序：插件按 `plugin_id` 升序，保证界面稳定。入口不向 C# 抛异常；宿主内部异常
按 §一收口为 `{"ok": false, "error_code", "error_message"}`。

### 11.2 `set_plugin_setting(plugin_id, key, value_json) -> str`

| 参数 | 说明 |
| --- | --- |
| `plugin_id` | 必须已加载；未知/已卸载 → `NOT_FOUND` |
| `key` | schema 里存在的配置项；不存在 → `INVALID_ARGUMENT` |
| `value_json` | **JSON 文本**：文本值必须带引号（`"\"abc\""`），数字 `16`、布尔 `true`；不是合法 JSON → `INVALID_ARGUMENT` |

成功：

```json
{"ok": true, "key": "limit", "value": 200}
```

password 项成功时额外带 `has_value`，且 **`value` 恒为空串**：

```json
{"ok": true, "key": "token", "value": "", "has_value": true}
```

失败：`{"ok": false, "error_code", "error_message"}`，错误码只用到三个：

| 情况 | `error_code` |
| --- | --- |
| 空 plugin_id / key、value_json 非法 JSON、类型不符、枚举外、越界、未知 key | `INVALID_ARGUMENT` |
| 插件不存在或未加载 | `NOT_FOUND` |
| 校验通过但写 `config.json` 失败（权限/磁盘等） | `IO_ERROR` |

**拒绝写入语义**：校验失败时既不修改进程内存里的当前值，也不触碰
`config.json`；界面必须保留用户输入（不得静默改回旧值），在字段下方显示
`[error_code] error_message` 供修正后重试。

### 11.3 schema 声明与字段类型枚举

```json
{
  "limit": {"type": "integer", "default": 200, "min": 10, "max": 5000, "label": "保留条数"},
  "mode":  {"type": "string", "default": "recent", "enum": ["recent", "clicks", "images"]},
  "dir":   {"type": "string", "default": "", "ui": "path"},
  "token": {"type": "string", "ui": "password"}
}
```

- `type`（校验类型）只能是 `string` / `integer` / `number` / `boolean`，决定写入校验；
- `ui`（界面提示，可选）只能是下表六种；未声明时：有 `enum` → `select`，
  否则 `string→text`、`integer|number→number`、`boolean→bool`；
  未知 `ui` 在插件加载时即报 `ConfigError`（schema 写错尽早暴露）。

| `type`（返回） | 渲染控件 | 取值来源 |
| --- | --- | --- |
| `text` | `TextBox` | schema type 为 string 且无 ui/enum |
| `path` | `TextBox` + 「浏览…」 | `"ui": "path"` |
| `number` | 数字框 | schema type 为 integer/number |
| `bool` | `CheckBox` | schema type 为 boolean |
| `select` | `ComboBox` | 有 `enum`（或显式 `"ui": "select"`） |
| `password` | `PasswordBox` | `"ui": "password"` |

校验规则（写入与默认值生成共用同一套，见 `Python/jml/host/config.py`）：

- 类型：`integer` 拒绝 `true/false` 与浮点；`number` 拒绝布尔；按 Python 类型严格判断；
- `enum`：值必须命中数组元素（元素可为字符串/数字/布尔）；
- `min` / `max`：仅对可比较类型生效，越界拒绝；
- `required: true` 且缺 `default`：插件加载时即报 `ConfigError`；
- 默认值本身也过一遍校验，schema 写错尽早失败。

### 11.4 password 与凭据安全

- `list_plugin_settings` 对 password 项**永不返回值**（`value` 空串），只给 `has_value`；
- `set_plugin_setting` 成功后同样不回值；
- password 项**不写入 `config.json`**、schema 里**不允许声明非空 default**；
  值只保存在 Python 进程内存（本次运行有效，`PluginContext.config_get` 仍可读）；
  存量 `config.json` 里若被人工写入同名项也一律忽略；
- 需要跨重启的凭据必须走 C# 侧 Windows 凭据管理器 / DPAPI（§九.11、§10.6），
  不属于插件配置；
- C# 界面侧：PasswordBox 不回填；留空表示不修改；写入成功后立即清空输入框，
  不缓存任何明文密码字符串。

### 11.5 落盘位置

`%APPDATA%\JML\plugins\{plugin_id}\config.json`（路径由 Python 用
`os.environ["APPDATA"]` 推导，C# 不硬编码）。原子写：先写 `.tmp` 再
`os.replace`；内容为全部非 password 项的当前值（UTF-8、`ensure_ascii=False`、
2 空格缩进），**不含任何凭据**。目录不存在时自动创建。

### 11.6 C# 接入纪律

1. 只调 `list_plugin_settings` / `set_plugin_setting` 两个入口，不绕宿主私有函数；
2. `list_plugin_settings` 与 `set_plugin_setting` 在后台线程执行（同步读盘/写盘），
   设置页加载与保存不得阻塞 UI 线程；
3. 字段类型、选项、范围提示全部来自 Python；C# 不复制校验逻辑，
   只按 `type` 选控件、按 `error_code` 展示；
4. 失败一律显示在字段下方（`[error_code] error_message`），不弹全局框；
5. password 控件不回填、成功后清空，不写进日志/配置/`settings.json`。

## 十二、插件结构化页面协议（阶段 4 新增，技术方案第三节方案 A）

> 目标：插件不返回任意 XAML / 界面描述，只返回“模板 + 数据”；C# 侧只有
> `list` / `browser` / `action` 三个通用渲染器（`form` 保留给设置与账号界面）。
> 模板类型与标题**只来自 manifest**，插件返回值不能改变它们。

### 12.1 入口与返回信封

| 入口 | 参数 | 返回 |
| --- | --- | --- |
| `plugin_page_load(plugin_id, page_id, params_json)` | `str` / `str` / **JSON 文本**（空串 = `{}`） | JSON 字符串（见下） |
| `plugin_page_action(plugin_id, page_id, action_id, payload_json)` | `str` / `str` / `str` / **JSON 文本**（空串 = `{}`） | JSON 字符串（见下） |
| `plugin_page_image(plugin_id, page_id, index)` | `str` / `str` / `int` | `bytes` 原图；失败 `None`（唯一非 JSON 入口之一） |

`plugin_page_load` 成功：

```json
{"ok": true,
 "template": "list|browser|action|form",
 "title": "<manifest 页面标题>",
 "data": {"<模板 payload>": "字段见 12.2"}}
```

`plugin_page_action` 成功（插件 handler 返回的 `refresh` / `data` / `message`
由宿主归一化，其余键忽略；**阶段 4-4 起额外透传可选 `intent`**）：

```json
{"ok": true, "refresh": false, "data": null, "message": "状态文案"}
```

- `refresh=true`：C# 应重新调用 `plugin_page_load`（带着当前页码）；
- `data`：该模板的新 payload（可为 `null`）；非 `null` 时 C# 就地重渲染，
  不再发一次 load；
- `message`：状态文案，原样展示；
- `intent`（可选，阶段 4-4）：插件返回 `{"intent": {...}}` 时宿主原样透传、
  不解释含义：

  ```json
  {"ok": true, "refresh": false, "data": null, "message": "",
   "intent": {"kind": "detail", "book_id": "123"}}
  ```

  收藏夹约定 `kind=detail`（`book_id`）与 `kind=download`
  （`book_ids`）；C# 收到后**只转发**给主窗口的既有路径
  （`DetailWindow` / 切下载页 + `StartWithIds`），不做业务判断。没有 intent
  时信封里不出现该键（与旧插件兼容）。

失败一律 `{"ok": false, "error_code": "...", "error_message": "..."}`。

### 12.2 三套模板 payload

`list`：

```json
{
  "columns": [{"key": "time", "title": "时间", "width": 120}],
  "rows": [{"time": "2026-10-18", "book_id": "123"}],
  "page": 1, "page_size": 50, "total": 123, "total_pages": 3,
  "row_actions": [{"id": "open", "title": "打开", "primary": true}],
  "filters": [
    {"key": "folder_id", "label": "收藏夹",
     "options": [{"value": "0", "label": "全部"}, {"value": "7", "label": "子夹"}],
     "value": "0"},
    {"key": "sort", "label": "排序",
     "options": [{"value": "mr", "label": "最近收藏"}, {"value": "mv", "label": "最多点击"}],
     "value": "mr"}
  ],
  "empty_text": "暂无记录"
}
```

- `rows` 的每个元素是任意 JSON 对象，C# 用 `JsonElement` 原样保留全部字段
  （不裁剪、不改名、不排序）；`columns[].key` 是行对象里的取值键；
- `width`（像素）可缺省 → 自动宽度；`row_actions[].primary` 决定主/次按钮样式；
- `page` 1 起；`page_size`、`total_pages` 可缺省（缺省 `50` / 由
  `total` 与 `page_size` 推算）；
- **阶段 4-4 扩展：`filters`（可选）**——筛选项列表，C# 在列表上方为每项渲染
  一个下拉框（文本用 `label`，选项 = `options`，选中项 = `value`）。用户切换后
  C# 以 `{"page": 1, "<key>": "<新 value>", ...其它当前筛选值}` 重新
  `plugin_page_load`；选项内容、排序规则、空态全部由 Python 决定。缺省 / 空数组
  = 不显示筛选栏（旧插件行为不变）。收藏夹插件用它实现「收藏夹目录」「排序」两个
  下拉。

`browser`：

```json
{
  "items": [{"name": "001.zip", "path": "C:/zip/001.zip"}],
  "page": 1, "page_size": 20, "total": 42, "total_pages": 1,
  "item_index": 0, "image_index": 0, "image_count": 7,
  "folder": "C:/zip", "allow_folder_choice": true,
  "empty_text": "目录为空"
}
```

- `items` 是文件列表（ZIP 等）；元素顺序即显示顺序（**自然排序/文件名清洗在 Python**）；
- `item_index`：当前打开的文件下标（`-1` = 未打开，只看列表）；
- `image_index`：当前图片下标（0 起）；`image_count`：当前文件图片总数；
- `plugin_page_image` 的 `index` 即这里的 `image_index`；**图片原图 bytes 不 base64 进 JSON**，
  当前选中条目由插件自身在 load 时记录。
- **阶段 4-2 扩展**：`folder` 为当前目录绝对路径（空串 = 尚未选择目录）；
  `allow_folder_choice=true` 时 C# 在文件列表上方显示「选择文件夹…」按钮，选定目录后以
  `{"page": 1, "folder": "<目录>", "item_index": -1}` 重新 `plugin_page_load`。
  按钮显隐、列出哪些 ZIP、空态文案全部由 Python 决定，C# 不判断业务状态。

`action`：

```json
{
  "items": [{"name": "001.zip", "path": "C:/zip/001.zip"}],
  "state": "idle|running",
  "status_text": "服务运行中：http://127.0.0.1:8080",
  "actions": [{"id": "start", "title": "开始浏览"}, {"id": "stop", "title": "停止浏览"}],
  "port": 8080,
  "url": "http://127.0.0.1:8080/",
  "folder": "C:/zip",
  "allow_folder_choice": true,
  "empty_text": "选择文件夹…"
}
```

- `state` / `status_text` / `port` 只做展示（`port=0` 表示未启动）；
- `actions[].id` 原样回传给 `plugin_page_action`；
- **阶段 4-3 扩展**：`url` 为空串表示当前没有可打开的服务地址；非空时 C# 显示
  「在浏览器中打开」按钮，点击只把该地址转发给 `Process.Start(... UseShellExecute=true)`
  （C# 不拼地址、不判断服务状态）。`folder` / `allow_folder_choice` / `empty_text`
  与 `browser` 模板同义：`allow_folder_choice=true` 时 action 模板文件列表上方也显示
  「选择文件夹…」，选定后以 `{"page": 1, "folder": "<目录>", "item_index": -1}`
  重新 `plugin_page_load`。动作按钮点击时按 §12.3 回传 `item` / `item_index`。
- ZIP 网页浏览插件用 `port=0` + `127.0.0.1` 自动分配端口，停止后必须释放端口。

`form`：本阶段**不**由功能页渲染（设置项与账号录入仍走各自界面）；
功能页收到 `form` 时显示固定提示 `[NOT_IMPLEMENTED]`，不做通用表单渲染。

### 12.3 参数传递约定（C# → Python）

`params_json` / `payload_json` 必须是 **JSON 对象文本**（空串等价 `{}`；
非法 JSON 或非对象 → `INVALID_ARGUMENT`）。约定的键：

| 模板 / 场景 | 键 | 含义 |
| --- | --- | --- |
| `list` / `browser` 翻页 | `page` | 列表页码（1 起） |
| `browser` 选中文件 | `item_index` | 文件下标；`-1` = 回文件列表 |
| `browser` 选择文件夹（阶段 4-2） | `folder` | 目录绝对路径；换目录后 Python 重新列 ZIP 并记住 `last_folder` |
| `action` 选择文件夹（阶段 4-3） | `page` / `folder` / `item_index` | 与 browser 相同的目录选择参数（`item_index=-1` 回文件列表） |
| `browser` 打开图片 | `image_index` | 图片下标（0 起），选中文件时通常传 `0` |
| `list` 行操作 | `row` / `row_index` / `page` | 整行原始 JSON 对象 / 行下标 / 当前页码 |
| `list` 筛选下拉（阶段 4-4） | `<filters[].key>` | 用户选中的选项 `value`；同时带 `page=1` 与其它当前筛选值（收藏夹：`folder_id` / `sort`） |
| `action` 动作按钮 | `item` / `item_index` | 当前选中文件 `{name,path}` 或 `null` / 下标 |

插件可以忽略不认识的键；C# 不解释参数含义，只按上表透传。

### 12.4 插件侧 API（`PluginContext`，仍不暴露宿主对象）

```python
ctx.register_page(page_id, loader)                     # loader(params: dict) -> dict（模板 payload）
ctx.register_page_action(page_id, action_id, handler)  # handler(payload: dict) -> dict
ctx.register_page_image(page_id, resolver)             # resolver(index: int) -> bytes | None
```

除上面三个注册方法与既有的服务/事件/配置方法外，插件还能读两个只读属性：

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `ctx.plugin_id` | str | manifest 声明的插件 id |
| `ctx.data_dir` | str | 本插件专属可写数据目录的**绝对路径**：`%APPDATA%/JML/plugins/{plugin_id}/data` |

`data_dir` 的路径推导与目录创建只发生在宿主：`loader._build_context` 通过
`loader.plugin_data_dir(plugin_id)` 推导路径，再由 `_create_data_dir` 执行
`os.makedirs(..., exist_ok=True)` 创建后传入 context（与 `config.json` 同根，
位于其上一级目录）。插件只拿绝对路径，**不得**自己拼 `%APPDATA%`、不得读写别的插件目录；目录创建失败 → 该
插件本次装配失败并记录原因（不影响其它插件）。插件的数据文件都放在该目录下
（如下载历史的 `history.json`），业务数据同样不得包含凭据。

**阶段 4-2 小扩展：`ctx.config_set(key, value)`**。它写的是本插件 manifest
`config.schema` 里声明过的配置项，与主设置窗口的 `set_plugin_setting` 共用同一个
`PluginConfig` 实例和同一份 `config.json`（schema 校验与原子落盘只有一处实现），
非法值抛 `ConfigError` 且当前值与磁盘都不变。`plugin_id` 仍由宿主闭包绑定，
插件只能写自己的配置项。ZIP 浏览插件用它把所选目录记进 `last_folder`。

纪律（宿主强制，`Python/jml/host/pages.py` + `loader.py`）：

1. **plugin_id 由宿主绑定**：三个方法签名里没有 `plugin_id`，插件无法注册/覆盖别人的页面；
2. 注册的 `page_id` 必须在该插件 manifest 的 `pages[]` 里，否则本次装配失败
   （`NOT_FOUND` 语义，错误消息含插件 id 与页面 id）；
3. 所有注册在显式 `threading.RLock` 内完成，读路径也加锁；同一键重复注册覆盖旧值；
4. 插件重新装配（`load_all` / `reset`）会清空页面注册表，插件 setup 失败时撤销其部分注册；
5. 插件返回值必须是 JSON 可序列化 `dict`（图片钩子返回 `bytes`）；**禁止**返回
   XAML / 控件描述 / 可执行界面。

### 12.5 路由与错误码

校验顺序：插件已加载 → 页面已在 manifest 声明 → 钩子已注册。

| 情况 | `error_code` | 说明 |
| --- | --- | --- |
| `plugin_id` 未加载 / `page_id` 未声明 | `NOT_FOUND` | `plugin_page_image` 对应返回 `None` |
| 钩子未注册（没调 `ctx.register_page*`） | `NOT_IMPLEMENTED` | 文案明确写“未实现…钩子（请在 setup 中调用 ctx.register_page*）” |
| `params_json` / `payload_json` 非法 JSON 或非对象 | `INVALID_ARGUMENT` | 入口不抛异常 |
| 钩子返回值不是 `dict` / 模板值非法 | `INVALID_DATA` | 协议违约 |
| 插件钩子内抛其它异常 | 按 §1.1 异常类型分类 | 网络/文件等沿用原表 |

`plugin_page_image` 任何失败都返回 `None` 并写诊断 `PAGE_IMAGE_FAILED`，
C# 显示图片占位“图片加载失败”，不弹错误框。

### 12.6 C# 渲染纪律

| 模板 | 渲染 |
| --- | --- |
| `list` | `DataGrid`：列 = `columns`（`DataGridTextColumn`，绑定行对象索引器）；行 = `rows`；行操作按钮 = `row_actions`（每行一组，点击回传整行 JSON）；上一页/下一页用 `page` 重新 `plugin_page_load`；空态显示 `empty_text`；**阶段 4-4**：`filters` 非空时在列表上方渲染下拉框，切换后以 `{page:1, <key>: <value>}`（带上其它当前筛选值）重新 `plugin_page_load`，筛选栏不自己判断业务 |
| `browser` | 左侧文件列表 = `items`（双击打开）；右侧图片区；图片走 `plugin_page_image(index)`，`BitmapImage` **只在 UI 线程**创建；上一页/下一页/「第 n 页 / 共 N 页」用 `image_index`/`image_count`；「返回列表」与 **Esc** 都发 `item_index=-1` 回到列表（`MainWindow` 在窗口级 `PreviewKeyDown` 调 `PluginPageHost.TryHandleEscape()`，焦点不在页面时也生效）；`allow_folder_choice=true` 时文件列表上方显示「选择文件夹…」按钮，用 `Microsoft.Win32.OpenFolderDialog` 选目录后以 `{page:1, folder, item_index:-1}` 重新 `plugin_page_load` |
| `action` | 左侧文件列表 + `actions` 动作按钮 + `status_text` 状态文案 + 刷新按钮；动作结果 `refresh=true` 时整页重载，`data` 非空时就地重渲染；**阶段 4-3**：`data.url` 为 http/https 绝对地址时显示「在浏览器中打开」按钮（生产用 `Process.Start(new ProcessStartInfo(url){UseShellExecute=true})` 只做转发，STA 测试可注入假打开器），`allow_folder_choice=true` 时文件列表上方显示「选择文件夹…」并复用 browser 的目录选择逻辑 |

- **不写业务逻辑**：排序、文件名、分页边界、成功失败全部来自 Python；C# 只按
  `page` / `total_pages` 决定按钮可用态，不做数据二次判断；
- **阶段 4-4：intent 只转发**。动作结果含 `intent` 时，`PluginPageHost` 交给
  可注入的 `IUiIntentHandler`（生产实现是 `MainWindow`，STA 测试注入假实现）：
  `detail` → 打开现有 `DetailWindow`；`download` → 切下载页 + `StartWithIds`。
  C# 不校验 `book_id`、不判断登录态、不拼状态文案；
- 失败只显示 `[error_code] error_message`，不弹全局框、不清空当前可重试界面；
- 内页标题栏仍走 `NavigationStack.PushInner / PopInner`；`PluginPageHost`
  只渲染内容区，不复制顶部返回栏；
- 插件功能列表（`PluginFeaturesView`）按**插件**列出；只声明 1 个页面直接进入，
  多个页面先在视图内显示页面选择列表，再 `PushInner`。

### 12.7 线程与阻塞语义

- `plugin_page_load` / `plugin_page_action` 是同步 Python 调用（可能读盘），
  C# 必须 `Task.Run` 包装，禁止占用 UI 线程；
- `plugin_page_image` 只产出 `bytes`；`BitmapImage` 的创建与赋值必须回 UI 线程；
- Python 侧注册表显式加锁，事件仍走既有 `plugin.notification`（状态变化）。

### 12.8 与任务书的差异（已按本节实现）

| 项 | 任务书原文 | 本契约实际 |
| --- | --- | --- |
| 分页字段 | `list` 只有 `page/page_size/total`；`browser` 只有 `page/total` | 两者都**可选**接受 `total_pages`；缺省时由 `total/page_size` 推算（纯展示） |
| browser 选中目标 | 未定义 | 增加可选 `item_index`（`-1` = 只看列表）与 `image_count`（图片总页数） |
| browser 目录选择 | 未定义 | 增加可选 `folder` / `allow_folder_choice`（payload）与 `params.folder`（阶段 4-2，ZIP 浏览插件用） |
| action 目录选择与外部浏览器 | 未定义（action 只有文件+动作+状态） | 阶段 4-3 增加可选 `url` / `folder` / `allow_folder_choice` / `empty_text`：`url` 只驱动「在浏览器中打开」按钮，文件夹选择复用 browser 逻辑；C# 仍只转发，不判断业务状态 |
| `ctx` 配置写入 | 只有 `config_get` | 阶段 4-2 增加 `config_set`（与 `set_plugin_setting` 共用同一 `PluginConfig`，仅限本插件 schema 内 key） |
| `list` 筛选下拉 | 未定义 | 阶段 4-4 增加可选 `filters`（`[{key,label,options,value}]`）：C# 渲染成下拉框，切换后以 `{page:1, <key>: <value>}` 重新 load |
| 行动作跨页面跳转 | `refresh` / `data` / `message` | 阶段 4-4 增加可选 `intent`（收藏夹 `detail` / `download`）：C# 只转发给主窗口既有路径，不做业务 |
| 登录态传给插件 | 只有 `jm.account`（登录状态） | 阶段 4-4 增加宿主服务 `jm.session/1`：插件用 `get_service(...).get_client()` 拿**已登录客户端对象**，不拿凭据；未登录抛 `NOT_LOGGED_IN` |
| 返回按钮语义 | “返回按钮”未说明目标 | 发布 `plugin_page_load` 且 `params.item_index = -1`，由插件决定回列表状态 |
| 标题 | 顶层 `title` | 优先 manifest `pages[].title`；插件不能覆盖为任意值 |
| `form` | 模板集包含 | 本阶段功能页不渲染，返回 `NOT_IMPLEMENTED` 提示 |
