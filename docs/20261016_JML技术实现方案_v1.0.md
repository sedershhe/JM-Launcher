## 一、总体分层架构（四层）

```
┌─────────────────────────────────────────────────────┐
│ 1. 表现层（C#/WPF，PCL2 风格）                        │
│    MainWindow 三层骨架 + 各功能页 + 控件              │
│    纪律：不做任何业务逻辑，只做展示与转发             │
├─────────────────────────────────────────────────────┤
│ 2. 桥接层（C#）                                      │
│    PythonRuntime / DTO / EventRelay / PluginBridge   │
│    纪律：唯一的跨语言边界，GIL 调度 + 线程编组        │
├─────────────────────────────────────────────────────┤
│ 3. 业务层（Python，jml_backend 包）                  │
│    下载 / 搜索 / 详情 / 账号 / 插件宿主 / 服务注册表  │
│    纪律：保留原 Python 业务逻辑，不感知 WPF          │
├─────────────────────────────────────────────────────┤
│ 4. 插件层（Python 包，每插件一个目录）                │
│    manifest + 业务实现 + 服务声明                    │
│    纪律：只走协议，不碰宿主私有实现，零路径探测       │
└─────────────────────────────────────────────────────┘
```

各层职责边界：

| 层 | 允许 | 禁止 |
| --- | --- | --- |
| 表现层 | 数据绑定、事件转发、界面状态 | 直接拼 Python 调用、拼业务规则 |
| 桥接层 | GIL 管理、DTO 转换、回调编组到 UI 线程 | 业务判断（如"失败算不算成功"） |
| 业务层 | 全部业务规则、网络、文件、加密 | import WPF 相关、操作 UI 对象 |
| 插件层 | 通过协议调服务/发事件/声明页面 | 摸宿主私有属性、按文件路径加载兄弟插件 |

**一条铁律**：跨语言只允许经过桥接层定义的 DTO 字典（键名锁定），禁止把 Python 对象直接漏到 UI 层。

## 二、插件协议规范（api_version = 1）

### 2.1 插件形态与 manifest

每个插件是 `plugins/` 下一个目录，含 `plugin.json`：

```json
{
  "id": "zip_browser",
  "name": "ZIP 浏览",
  "version": "1.0.0",
  "api_version": 1,
  "description": "不解压直接翻页浏览压缩包内图片",
  "entry": "main.py",
  "dependencies": { "plugins": ["download_history"] },
  "services": {
    "provides": [ { "name": "archive_reader", "version": 1 } ],
    "requires": [ { "name": "archive_reader", "version": 1 } ]
  },
  "pages": [
    { "id": "zip_browser.main", "title": "ZIP 浏览", "template": "browser" }
  ],
  "config": { "schema": "config.schema.json" }
}
```

加载规则（对应计划书 8.2 / 11.3）：

| 检查 | 不通过时 |
| --- | --- |
| `api_version` ≠ 宿主支持 | **拒绝加载**，插件管理界面明确提示"协议版本不兼容" |
| 依赖插件缺失或被停用 | 拒绝加载，提示"缺少依赖插件 xxx" |
| 所需服务无人提供 | 拒绝加载，提示"缺少服务 xxx" |
| 依赖环 | 拒绝整环加载并报出环成员 |

加载顺序：拓扑排序（真实生效，对应旧缺陷 #3/#4）。

### 2.2 服务注册表（核心机制）

```
宿主启动流程：
  扫描 plugins/ → 读 manifest → 校验协议版本 → 拓扑排序
  → 依序 import 插件 → 插件调 host.register_service(name, version, obj)
  → 全部装完后核对 requires 列表，缺谁报谁
```

- 主程序也注册服务：`jm.search`、`jm.detail`、`jm.download`、`jm.account`（供插件调用，如收藏夹的「下载」按钮）
- 服务调用统一签名：`call_service(name, version, method, payload) -> dict`
- `zip_web` 依赖 `zip_browser` 就写成 `requires: archive_reader/1`，**不再有任何路径探测**

### 2.3 事件系统（禁止裸 dict）

所有事件 = `event_type`（字符串常量）+ `payload`（按类型固定的字段表）：

| 事件类型 | payload 字段 |
| --- | --- |
| `download.item_started` | book_id, title |
| `download.item_finished` | book_id, title, ok, zip_path, error_code, error_message |
| `download.batch_finished` | total, success, failed, cancelled |
| `download.log` | level, message（已脱敏） |
| `search.page_loaded` | keyword, page, total_pages, results[] |
| `plugin.notification` | level, title, message |

事件经桥接层 `EventRelay` 转发到 C#，`Dispatcher.Invoke` 编组到 UI 线程。**锁：注册表与分发均加显式锁**（对应旧缺陷 #10）。

### 2.4 UI 扩展点

| 扩展点 | 说明 |
| --- | --- |
| 功能页 | manifest 的 `pages[]`，出现在「插件功能」列表 |
| 设置项 | manifest 声明 → 注册进主设置窗口（对应决策 #11） |
| 通知 | `plugin.notification` 事件 → 界面提示区 |

### 2.5 配置契约

- 插件自带 `config.schema.json`（类型 + 默认值 + 范围）
- 宿主读 schema **生成默认值并校验**写入的值，非法值拒绝并回退默认（对应旧缺陷 #5）
- 配置落 `%APPDATA%\JML\plugins\{id}\config.json`，不含任何凭据

## 三、插件页面的呈现方式（关键设计决策）

**问题**：UI 在 C#（WPF），插件在 Python，插件页面怎么画？

**两个候选**：

- **方案 A（推荐）：结构化页面协议**——插件声明页面模板类型，C# 侧提供少量通用页面模板渲染器，插件通过协议提供"列定义 + 行数据 + 动作回调"。
- 方案 B：每个插件自带一个 C# UI 工程页面——插件变成双语言包，开发/分发成本翻倍，与"轻量简单"冲突。

**方案 A 的模板集（覆盖全部四个旧插件，够用即止）**：

| 模板 | 数据接口 | 覆盖 |
| --- | --- | --- |
| `list` | 列定义 + 行数据 + 行按钮 + 翻页 | 下载历史、收藏夹（复用搜索列表样式） |
| `browser` | 文件夹选择 → 文件列表 + 翻页图片 + 返回 | ZIP 浏览（页码自然排序在 Python 侧保证） |
| `action` | 文件列表 + 启动/停止动作 + 状态文案 | ZIP 网页浏览 |
| `form` | 字段定义（文本/密码/下拉/路径选择） | 插件设置项、账号录入 |

**约束**：模板不够用时先评估加模板，**不允许**插件返回任意 XAML（安全与稳定红线）。

## 四、并发与线程模型

```
UI 线程（WPF Dispatcher）
  │  发起调用（只传参数 DTO）
  ▼
桥接层 PythonRuntime.Invoke（Py.GIL）
  │  Python 业务执行
  ▼
Python 侧：
  下载：单工作线程驱动，内部 ThreadPoolExecutor(max_workers=3) 并发 3 本
        真取消：batch 级 threading.Event，下载协程在章节/图片检查点轮询，
        set 后立即中断（不等当前本子跑完）——对应决策 #2
  搜索/详情/收藏夹：jmcomic 同步 API，在后台线程执行
  回调：Python → C# delegate（持 GIL 时触发）→ EventRelay → Dispatcher 编组到 UI 线程
```

| 纪律 | 对应旧缺陷 |
| --- | --- |
| 工作线程只产出数据（bytes/dict/path），**UI 对象全部主线程创建** | #7 跨线程图片对象 |
| 下载日志走独立日志通道（按 batch_id 区分），主窗口/详情窗各自订阅 | #6 日志争抢 |
| 翻页关键词绑定**发起搜索时**的快照，不读输入框当前值 | #8 |
| 桥接层所有 Python 调用持 GIL；Python 侧共享容器显式加锁 | #10 |

**GIL 串行化说明**：所有 Python 调用经同一 GIL 串行执行，长任务（批量下载）在 Python 侧内部并发，C# 侧绝不因等待 Python 阻塞 UI 线程（调用一律 `Task.Run` 包装）。

## 五、目录结构

```
JML/
├─ JML.csproj / Directory.Packages.props / requirements.txt
├─ App.xaml / MainWindow.xaml        # 三层骨架（阶段 1 重写）
├─ Controls/                          # 按需自绘：ListItemButton、NavRadioButton、IconButton
├─ Pages/
│   ├─ DownloadPage.xaml              # 下载（全页，无左栏）
│   ├─ SearchPage.xaml                # 搜索（全页）
│   ├─ SettingsPage.xaml              # 设置（含插件注册项 + 账号录入）
│   ├─ PluginHubPage.xaml             # 插件页（左二级目录 + 右内容）
│   └─ PluginPageHost.xaml            # 结构化模板渲染器（list/browser/action/form）
├─ Infrastructure/                    # 已有：PythonRuntime / LogSanitizer / AppPaths / PythonEnvironmentReport
├─ Bridge/                            # DTO 定义 / EventRelay / PluginBridge / DownloadBridge / SearchBridge
├─ Navigation/                        # PageStack、内页进入/返回机制
├─ Assets/                            # icon.ico（沿用 PCL2，13 帧）+ 矢量 Path 图标
├─ Python/
│   ├─ jml_backend.py                 # 入口（扩展为模块路由）
│   └─ jml/
│       ├─ core/                      # downloader / searcher / detail / account / naming / validation
│       ├─ host/                      # 插件宿主：扫描/校验/拓扑排序/服务注册表/事件总线/配置契约
│       └─ services/                  # 主程序注册的服务（jm.search / jm.download / jm.account…）
├─ plugins/                           # 插件目录（每插件一个子目录 + plugin.json）
│   ├─ download_history/
│   ├─ zip_browser/
│   ├─ zip_web/
│   └─ favorites/
├─ JML.Tests/                         # xUnit（桥接层/命名/脱敏/导航）
└─ docs/ + docs/devlog/
```

运行期数据（全部自有目录，零数据耦合）：`%APPDATA%\JML`（配置）、`%LOCALAPPDATA%\JML`（日志/缓存）。

## 六、账号与安全

| 项 | 方案 |
| --- | --- |
| 账号录入 | 设置页 `form` 模板界面录入，必须提供**修改窗口**（硬性要求） |
| 存储 | Windows 凭据管理器（首选，`cmdkey`/Win32 API），失败回退 DPAPI 加密文件；**绝不明文** |
| 测试账号 | 经安全测试配置注入（如 `JML_TEST_CREDENTIALS_FILE` 指向本地不入库文件），构建产物零凭据 |
| 脱敏 | `LogSanitizer` 全链路生效：password/passwd/token/cookie/authorization/username |
| 下载路径 | 记住上次目录，存 `%APPDATA%\JML\settings.json` |

## 七、关键行为等价清单（实现时的验收锚点）

实现时逐条对照（摘自计划书 11.6，代码中用常量/测试锁定）：

- 分隔符 `- , ， 、 ; ； 空白`；并发 3；默认桌面；产物 `{标题}-JM{编号}.zip`
- 同名副本命名 `xxx.zip → xxx - 副本.zip → xxx - 副本 (2).zip`
- 文件名剥除 `\ / * ? : " < > |`；ZIP 内 `001.ext` 三位零填充
- 搜索行封面 80×110、失败暗红底 X、空结果灰色"未找到相关结果"
- 简介超 200 字截断；完成弹框"完成，成功 x / 共 y，失败 z"
- ZIP 浏览五条错误文案逐字锁定；页码自然排序
- 错误按异常类型判定，不做关键词匹配（旧缺陷 #2）

## 八、阶段开发计划与子代理分工

> 主代理把控流程：每阶段 = 分派 → 实现 → 分段验收（测试真跑）→ devlog + Git checkpoint 标签 → 合并进入下一阶段。

| 阶段 | 内容 | 分工 |
| --- | --- | --- |
| **1 外壳 + 插件协议** | 三层骨架 + 内页返回机制；Python 环境引导页；插件宿主（manifest/校验/拓扑/服务注册表/事件/配置契约）；插件管理界面 | frontend-agent：骨架与页面；backend-agent：Python 宿主与协议；utility-agent：测试与配置样板；verifier-agent：阶段验收 |
| **2 主程序核心** | 下载（真取消/同名副本/校验打包）、搜索（列表/封面/翻页）、详情 | backend-agent：`jml/core` 全部；frontend-agent：三个页面 + Bridge 绑定；verifier-agent：对照等价清单验收（下载类必须查 ZIP 实际产物） |
| **3 账号与设置** | 账号录入 + 凭据管理器/DPAPI + 设置页 + 插件设置项机制 | backend-agent：account 模块与安全存储；frontend-agent：设置页与 form 模板；verifier-agent：脱敏与零凭据审查 |
| **4 四插件** | 顺序：下载历史 → ZIP 浏览（注册 archive_reader 服务）→ ZIP 网页浏览（消费该服务）→ 收藏夹 | backend-agent：插件 Python 实现；frontend-agent：模板渲染器补齐；verifier-agent：服务依赖真实生效验收（停用 zip_browser 时 zip_web 必须明确报错） |
| **5 收尾** | 整体回归、无界面自检命令、zip 便携版发布配置 | utility-agent：发布配置；verifier-agent：全量回归 |

每阶段产物纪律（对应 11.4）：
1. 阶段完成 → `docs/devlog/2026MMDD-NN-主题.md`
2. 测试真跑（xUnit + pytest，失败不得声称完成）
3. Git 提交 + `checkpoint-YYYYMMDD-NN` 标签

## 十、风险与预留

| 风险 | 对策 |
| --- | --- |
| `form/list` 模板表达力不足 | 先覆盖已知 4 插件需求；新需求先评估加模板，不允许任意 XAML |
| pythonnet 回调在 GIL 下的死锁 | 桥接层统一入口 + 回调队列化（先入队，UI 线程取出），禁止在回调里再调 Python |
| 凭据管理器不可用（策略限制） | 回退 DPAPI；两者都失败则禁用收藏夹并明确提示，不落明文 |
| jmcomic API 行为差异 | 阶段 2 验收以可观察行为对照旧版基线，不逐版复刻中间缺陷 |
