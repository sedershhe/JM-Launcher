## 一、产品定位一句话

把旧项目的功能原样搬到新外壳上：界面换成 PCL2 风格，功能一个不少，用户已有的使用习惯尽量不变。

## 二、功能总览（7 大块）

```
JML
├── 1. 下载（主功能）
├── 2. 搜索
├── 3. 详情
├── 4. 下载历史          ← 旧插件移植
├── 5. 收藏夹浏览        ← 旧插件移植
├── 6. ZIP 浏览          ← 旧插件移植
├── 7. ZIP 网页浏览      ← 旧插件移植
└── （附）设置与账号
```

界面组织：**标签页**形式，顶部切换，底部一条状态栏（与旧项目一致）。

## 三、逐块功能说明

### 1. 下载（主功能）

**用户能做什么**
- 在输入框里填 JM 本子编号，**支持一次填多个**（用 `-`、`,`、`，`、`、`、`;`、`；`、空格 分隔都行）
- 选择下载到哪个文件夹（默认是桌面）
- 点「开始下载」，程序开始批量下载
- 下载过程中可以点「取消」

**规则与表现**
| 行为 | 说明 |
| --- | --- |
| 并发 | 同时最多下 **3** 本 |
| 取消方式 | **软取消**：只跳过还没开始的本子，正在下的那一本会跑完 |
| 单本失败 | 某一本失败不影响其它本子，继续下 |
| 完成后 | 弹框提示"成功 x / 共 y，失败 z" |
| 日志 | 只读文本框，自动滚到底，显示下载过程 |
| 产物 | 每本打包成一个 ZIP，文件名 `{标题}-JM{编号}.zip` |
| 质量保证 | 打包后校验 ZIP 条目、图片能否解码、像素是否有效，不过关就判这本失败 |

**已知的旧项目缺陷，本次要改进**
- 同名 ZIP 旧项目是**静默覆盖**（会丢数据）→ 本次改为**自动改名**或**询问**（待确认，见第五节）

### 2. 搜索

**用户能做什么**
- 输入关键词搜索，结果以列表展示
- 每条显示：封面缩略图、标题、作者、页数、JM 号
- 每条右侧有「详情」「下载」两个按钮
- 翻页（上一页 / 下一页，显示"第 N 页 / 共 M 页"）

**规则与表现**
- 搜索参数、总页数算法、页数补全规则与旧项目保持一致（用户已习惯）
- 封面异步加载，不卡界面；加载失败显示红色 `X`
- 无结果时显示灰色"未找到相关结果"
- 搜索失败时状态栏提示并弹错误框

### 3. 详情

**用户能做什么**
- 从搜索列表点「详情」打开，查看单本完整信息
- 看到：封面、标题、作者、页数、标签、简介
- 点「下载本子」直接下载这一本

**规则与表现**
- 简介超过 **200 字**截断加省略号
- 有独立的下载日志区域
- 加载失败时提示

### 4. 下载历史（旧插件移植）

**用户能做什么**
- 在一个独立标签页里看到以前下载过什么
- 每条显示：时间、本子号、成功/失败、输出文件路径
- 可设置最多保留多少条（默认 200 条）

### 5. 收藏夹浏览（旧插件移植）

**用户能做什么**
- 查看**当前登录账号的收藏夹**
- 列表样式与搜索结果一致（封面 + 标题 + 作者 + JM 号）
- 支持切换收藏夹目录、改变排序（最近收藏 / 最多点击 / 最多图片）
- 每条可「详情」「下载」

**前提**
- 需要账号处于登录状态，未登录时给出明确提示

### 6. ZIP 浏览（旧插件移植）

**用户能做什么**
- 选择一个文件夹，列出里面所有 ZIP
- 双击打开某个 ZIP，**直接在包里翻页看图**（不解压到磁盘）
- 上一页 / 下一页，显示"第 n 页 / 共 N 页"
- 窗口缩放时图片重新适配
- 返回列表（点返回按钮或按 Esc）

**规则**
- 页码排序必须是**自然排序**（`999` 排在 `1000` 前面，不能按字符串排）

### 7. ZIP 网页浏览（旧插件移植）

**用户能做什么**
- 选文件夹、列出 ZIP
- 点「用浏览器阅读」→ 自动打开系统浏览器，进入**无缝纵向连续阅读**（图片一张接一张，无间隙）
- 可以点「停止浏览服务」关闭

**表现**
- 只在本机回环地址启动服务，不对外
- 端口由系统自动分配，每次打开自动释放
- 浏览器页面显示"第 n 页 / 共 N 页"进度

## 四、设置与账号（新增，旧项目没有）

因为安全红线要求**不得沿用旧项目的明文配置**，账号部分需要新增界面：

| 功能 | 说明 |
| --- | --- |
| 账号录入窗口 | 用户在界面里填账号密码，不写入明文配置文件 |
| 凭据安全存储 | 用 Windows 凭据管理器或 DPAPI 加密，**不存明文** |
| 下载路径设置 | 记住用户上次选择的下载目录 |
| 各插件的设置项 | 收藏夹排序、ZIP 浏览文件夹、历史保留条数等 |

> 硬性要求：**测试时的账号通过安全的测试配置注入，禁止硬编码账号密码。**

## 五、需要你拍板的问题（影响功能范围）

这些问题不定，功能细节就无法最终确定：

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | **同名 ZIP 怎么办？** 覆盖 / 跳过 / 自动改名 / 询问 | 旧项目是静默覆盖（会丢数据），建议至少改成改名或询问 |
| 2 | **取消语义**：沿用"软取消"还是升级为"真取消"（立即中断）？ | 影响用户等待体验 |
| 3 | **是否保留插件体系**（可动态装卸插件）？ | 旧体系实际用得很少；若不需要，四个功能可直接做成固定标签页，省大量工作 |
| 4 | **ZIP 网页浏览**保持"外部浏览器"还是改成"应用内嵌阅读器"？ | 影响是否需要内置浏览器控件 |
| 5 | **是否沿用旧图标 / 品牌名**？ | 涉及资源与外观 |
| 6 | 要不要**进度条**？（旧项目只有文字日志，没有进度） | 可增强，但属行为变更 |
| 7 | **交付形态**：安装包 / 单文件 / 是否签名？ | 影响发布方式 |
| 8 | 是否需要**迁移旧数据**（下载历史、收藏夹设置、浏览过的文件夹）？ | 若需要，要写一个迁移工具 |

## 六、建议的开发顺序（按依赖关系排）

```
阶段 0  环境（已完成）
        └─ Git / 依赖清单 / pythonnet 桥接 / 主题 / 目录与脱敏

阶段 1  基础骨架
        └─ 主窗口标签页框架 + 状态栏 + Python 环境检测与引导界面

阶段 2  下载链路（核心，最先做）
        └─ 编号解析 / 目录选择 / 批量下载 / 日志 / 取消 / 打包与校验

阶段 3  搜索与详情
        └─ 搜索列表 / 封面 / 翻页 / 详情窗 / 快速下载

阶段 4  账号与设置
        └─ 账号录入 + 安全存储（收藏夹功能依赖登录态，须先于它做）

阶段 5  四个旧插件功能
        ├─ 下载历史（最简单，先做）
        ├─ ZIP 浏览
        ├─ 收藏夹浏览（依赖阶段 4 的登录态）
        └─ ZIP 网页浏览（依赖 ZIP 浏览的读包能力）

阶段 6  收尾
        └─ 整体回归 / 无界面自检命令 / 发布配置
```

**排序理由**：下载是主功能且被其它功能复用；收藏夹依赖登录态，所以账号要先做；
ZIP 网页浏览依赖 ZIP 浏览的读包能力，所以排在它后面。

## 七、验收口径（功能层面）

每完成一个阶段，按下面三条验收：

1. **功能可用**：按本计划书描述，人工实际操作一遍走通
2. **结果与旧项目一致**：可观察行为（文案、文件名、排序、错误提示）与旧项目对照无差异
3. **下载类功能不看状态文字，看实际产物**：必须检查 ZIP 是否生成、条目数量对不对、图片能否打开、像素是否正常

---

## 八、明确不做的事

- 不做旧项目的历史缺陷复刻（如静默覆盖同名文件、错误分类误判等）
- 不引用、不复制旧项目的任何代码与文件
- 不在代码或配置里写入任何真实账号密码
