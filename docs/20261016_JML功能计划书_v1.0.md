## 一、项目定位与边界

**一句话**：把旧项目的功能原样搬到新外壳上——界面换成 PCL2 风格，功能一个不少，用户已有习惯尽量不变。

**三条边界（已确定）**

| 边界 | 内容 |
| --- | --- |
| **主程序只保留三项** | 下载、搜索、详情（及其唤起下载） |
| **其余一律插件化** | 下载历史、收藏夹浏览、ZIP 浏览、ZIP 网页浏览，以及**后续所有新功能** |
| **技术栈** | C#/.NET（WPF，PCL2 风格）+ Python（保留原业务逻辑）+ pythonnet 桥接；C# 层不做业务功能逻辑 |

## 四、逐块功能说明

### 4.1 下载（主程序）

**用户能做什么**
- 输入 JM 本子编号，**支持一次填多个**（分隔符：`-`、`,`、`，`、`、`、`;`、`；`、空格）
- 选择下载目录（默认桌面）
- 点「开始下载」批量下载；过程中可「取消」

**规则与表现**

| 行为 | 说明 |
| --- | --- |
| 并发 | 同时最多 **3** 本 |
| 取消 | **真取消**：立即中断（旧项目为软取消，已改） |
| 单本失败 | 不影响其它本子，继续下载 |
| 完成后 | 弹框"成功 x / 共 y，失败 z" |
| 日志 | 只读文本框，自动滚到底 |
| 产物 | 每本一个 ZIP，命名 `{标题}-JM{编号}.zip` |
| 同名处理 | **Windows 同名副本命名法**（旧项目为静默覆盖，已改） |
| 质量保证 | 校验 ZIP 条目、图片可解码、像素有效；不过关判该本失败 |

### 4.2 搜索（主程序）

- 关键词搜索，列表展示：封面缩略图、标题、作者、页数、JM 号
- 每条右侧「详情」「下载」按钮
- 翻页：上一页 / 下一页，"第 N 页 / 共 M 页"
- 搜索参数、总页数算法、页数补全规则与旧项目保持一致
- 封面异步加载不卡界面；失败显示红色 `X`
- 无结果显示灰色"未找到相关结果"；失败时状态栏提示 + 弹框

### 4.3 详情（主程序）

- 展示：封面、标题、作者、页数、标签、简介
- 点「下载本子」直接下载
- 简介超过 **200 字**截断加省略号
- 有独立下载日志区；加载失败时提示

### 4.4 下载历史（插件）

- 独立标签页，显示：时间、本子号、成功/失败、输出路径
- 可配置最多保留条数（默认 200）

### 4.5 收藏夹浏览（插件）

- 查看当前登录账号的收藏夹，列表样式与搜索结果一致
- 支持切换收藏夹目录、切换排序（最近收藏 / 最多点击 / 最多图片）
- 每条可「详情」「下载」
- **前提**：需登录态，未登录时给出明确提示

### 4.6 ZIP 浏览（插件）

- 选文件夹列出所有 ZIP；双击**直接在包内翻页看图**（不解压到磁盘）
- 上一页 / 下一页，"第 n 页 / 共 N 页"；窗口缩放时图片重新适配
- 返回列表（返回按钮或 Esc）
- **页码必须自然排序**（`999` 在 `1000` 之前，不能按字符串排）

### 4.7 ZIP 网页浏览（插件）

- 选文件夹列 ZIP → 点「用浏览器阅读」→ 唤起系统浏览器，无缝纵向连续阅读
- 可点「停止浏览服务」关闭
- 只绑本机回环地址；端口自动分配并自动释放；浏览器端显示"第 n 页 / 共 N 页"

### 4.8 设置与账号（主程序，新增）

| 功能 | 说明 |
| --- | --- |
| 账号录入窗口 | 界面填写，**不写入明文配置文件**（旧项目为明文，必须改） |
| 凭据安全存储 | Windows 凭据管理器或 DPAPI 加密 |
| 下载路径设置 | 记住上次选择的目录 |
| 插件设置项 | 收藏夹排序、ZIP 浏览文件夹、历史保留条数等，由插件自行注册 |

> 硬性要求：**测试用账号通过安全的测试配置注入，禁止硬编码账号密码；必须提供账号修改窗口。**

## 五、品牌与图标方案（已确定）

### 5.1 素材来源

完整 PCL2 仓库（`D:\vscode\Project\PCLUI\PCL-main`）中确有图标资源。
> 注：此前只查了 `PlainToolkit.UI` 仓库（只有样式、无任何图片），故先前结论为"不存在"。

| 文件 | 尺寸 | 用途（代码引用实测确认） |
| --- | --- | --- |
| `Images/icon.ico` | **13 帧，16~256** | 应用图标、启动闪屏 |
| `Images/Heads/Logo.png` | 64×64 | 关于页、模组启动画面 |
| `Images/Heads/PCL2.png` | 64×64 | 仅关于页展示 |

用户已确认：**图标同样开源，可沿用**。

### 5.2 一个必须知道的事实修正

原计划"采用图标背景、把文字改成 JML"。实测发现：
**PCL2 标题栏的 Logo 不是图片，而是矢量 `Path`**（`FormMain.xaml:117` 的 `ShapeTitleLogo`，
`Data="M26,29 v-25 h6 ..."` 描边画出 "PCL" 字样）——它是路径数据，**无法直接改文字**。

但 PCL2 **本身内置文字 Logo 模式**（`FormMain.xaml.vb:725` 的 `UiLogoType`，共 4 种）：

| 值 | 模式 | 控件 |
| --- | --- | --- |
| 0 | 无 | 不显示 |
| 1 | 默认 | `ShapeTitleLogo`（矢量 "PCL" 路径） |
| **2** | **文本** | `LabTitleLogo`，文字取自设置项 `UiLogoText` |
| 3 | 图片 | `ImageTitleLogo` |

### 5.3 最终方案

| 位置 | 方案 |
| --- | --- |
| 程序名 | **JM Launcher** |
| 标题栏 | PCL2 同款渐变背景 + `UiLogoType=2` 文本模式，文字 = **JML** |
| 应用图标 | 沿用 PCL2 `icon.ico`，图标文字 = **JML** |

走 PCL2 原生支持的路径，无需改矢量路径、无需重新画图。

### 5.4 矢量图标可行性（重要结论）

**结论：界面内可以用矢量；`.ico` 文件本身不行，必须导出位图。**

实测证据——对 `icon.ico` 做字节级解析，**13 帧全部是位图**：

```
count=13
  帧0:  48x48   BMP/DIB 位图      帧7:  48x48   BMP/DIB 位图
  帧1:  32x32   BMP/DIB 位图      帧8:  40x40   BMP/DIB 位图
  帧2:  16x16   BMP/DIB 位图      帧9:  32x32   BMP/DIB 位图
  帧3:  256x256 PNG  位图         帧10: 24x24   BMP/DIB 位图
  帧4:  128x128 BMP/DIB 位图      帧11: 20x20   BMP/DIB 位图
  帧5:  96x96   BMP/DIB 位图      帧12: 16x16   BMP/DIB 位图
  帧6:  64x64   BMP/DIB 位图
```

ICO 是**多尺寸位图容器**（微软官方：帧只能是 `BITMAPCOREHEADER` / `BITMAPINFOHEADER`
位图或内嵌 PNG 三种形态），**不支持 SVG 等矢量格式**。

**做法**

| 用途 | 矢量？ | 做法 |
| --- | --- | --- |
| 标题栏、界面内图标 | ✅ 可以 | 直接用 WPF `Path` / `DrawingImage`，任意缩放不失真 |
| 任务栏 / exe / 资源管理器 | ❌ 不行 | 必须 `.ico`；由矢量源**导出**多尺寸位图后打包 |

**推荐工作流（矢量源单一真源 + 按需导出）**

```
矢量源（XAML Path 或 SVG）
   ├─→ 界面内：直接引用矢量，任意 DPI 清晰
   └─→ .ico  ：导出 16/20/24/32/40/48/64/96/128/256 各一张，打包为多帧 .ico
```

**必须含多尺寸帧**：Windows 在任务栏、资源管理器、大图标视图、高 DPI（150%/200%）
各取不同帧；单帧 ico 在其它场景会被拉伸模糊。
—— 这也是可直接沿用 PCL2 `icon.ico` 的重要原因：它已含 13 帧（16~256）。

## 七、插件体系：问题根因与协议优化方向

用户确定"后续功能**全部通过插件添加**"，因此先把旧项目的地基问题讲清。

### 7.1 旧项目缺陷：依赖声明全是空数组

**现象**：4 个插件的 `dependencies.plugins` 均为 `[]`，
但 `zip_web` 实际强依赖 `zip_browser` 的 `zip_archive.py`。

**根因链（关键）**

```
宿主隔离导入（只把插件自身目录放进虚拟包路径）
  → 插件之间无法互相 import
      → 开发者改用"按文件路径手工加载"绕过
          → 依赖不走清单、改走路径
              → 清单填了也没用 → 干脆全填空数组
```

**根因在第一步**：不是"忘了填"，而是隔离导入导致跨插件 import 失败，
才逼出路径探测 + 硬编码路径这一串权宜之计。

**三重后果**
1. 宿主的拓扑排序与依赖检测**从未真正生效**（只在单元测试跑过）
2. 代码里硬编码了绝对路径 → **项目搬家即挂**
3. 删掉 `zip_browser` 会让 `zip_web` 不可用

**对新项目的致命性**：全部插件化必然产生大量跨插件复用。若沿用旧机制，
每做一次复用就要重写路径探测，且依赖顺序无保证、删插件无明确报错。
**因此必须先解决"插件之间如何复用"，再动手做插件体系。**

### 7.2 数据交换协议的优化方向

核心一条：**让插件既能"需要什么"，也能"提供什么"，全部走协议。**

| # | 优化项 | 解决什么 |
| --- | --- | --- |
| 1 | **服务注册表（最关键）** | 主程序与插件均可注册服务；插件声明所需服务；宿主统一装配，缺失时明确报错 |
| 2 | 事件完整化 | 所有事件都有类型，**禁止裸 dict**（旧项目 `download.batch_finished` 即为裸 dict） |
| 3 | UI 扩展点扩充 | 除标签页/命令外，补充"设置项"与"通知提示" |
| 4 | 配置契约生效 | schema 真正用于默认值与校验，不再只是文档 |
| 5 | 协议版本化 | 明确兼容策略，不匹配直接拒绝（已确定） |
| 6 | 依赖声明生效 | 拓扑排序 + 环检测 + 缺失明确报错（宿主本就有此能力，只是未被用起来） |

### 7.3 服务注册表如何解决跨插件复用

以 `zip_web` 依赖 `zip_browser` 为例：

```
zip_browser 声明：我提供 IArchiveReader 服务（版本 1）
zip_web     声明：我需要 IArchiveReader 服务（版本 1）

宿主启动：按依赖顺序先加载 zip_browser → 装配服务给 zip_web
         若前者缺失/被禁用 → zip_web 明确报"缺少服务"，而非崩溃
```

**结果**：消除路径探测、硬编码路径与空数组依赖声明。

### 7.4 克制边界（与"轻量简单"定位一致）

不做插件沙箱隔离（同进程，与 Python 桥接方案一致）、
不做热插拔（重启生效即可）、不做跨版本自动适配（不匹配直接拒绝）。

```
        └─ 插件管理界面（启用 / 停用 / 重新扫描 / 查看状态）

阶段 2  主程序核心功能（只保留三项）
        ├─ 下载：编号解析 / 目录选择 / 批量下载 / 真取消 / 同名副本命名 / 打包与校验
        ├─ 搜索：列表 / 封面 / 翻页
        └─ 详情：详情窗 + 唤起下载

阶段 3  账号与设置
        └─ 账号录入 + 安全存储（收藏夹插件依赖登录态，须先于它做）

阶段 4  四个旧插件（全部以插件形式移植）
        ├─ 下载历史（最简单，先做）
        ├─ ZIP 浏览（并对外注册"压缩包读取"服务）
        ├─ ZIP 网页浏览（依赖上一项提供的服务）
        └─ 收藏夹浏览（依赖阶段 3 的登录态）

阶段 5  收尾
        └─ 整体回归 / 无界面自检命令 / zip 便携版发布配置
```

**排序理由**
1. 插件协议必须最先做——后续所有功能都是插件，协议不定则无法挂载；
2. 主程序三项核心紧随其后，它们是插件要调用的服务来源；
3. 账号先于收藏夹，因为收藏夹需要登录态；
4. ZIP 网页浏览依赖 ZIP 浏览注册的服务，故排在其后——这是**服务依赖**，不是路径探测。

## 九、验收口径

每完成一个阶段，按以下验收：

1. **功能可用**：按本计划书描述，人工实际操作一遍走通
2. **结果与旧项目一致**：可观察行为（文案、文件名、排序、错误提示）对照无差异
3. **下载类功能不看状态文字，看实际产物**：必须检查 ZIP 是否生成、条目数量、图片能否打开、像素是否正常
4. **插件依赖真实生效**：停用某插件时，依赖它的插件必须明确提示，而不是崩溃
5. **零路径探测**：插件之间不得靠文件路径互相加载

## 十、注意事项大全

### 10.1 与旧项目的"三零"纪律（硬性）

| 零 | 含义 |
| --- | --- |
| **零代码耦合** | 不引用、不 import、不复制旧项目任何源代码 |
| **零运行时耦合** | 运行时不启动、不连接任何属于旧项目的进程/解释器/端口/文件句柄 |
| **零数据耦合** | 不读写旧项目任何文件；配置、数据、日志、缓存全部落在自己的目录 |

**具体禁止**：引用旧项目模块 / 子进程调用其脚本 / 通过端口或临时文件通信 /
引用其虚拟环境与构建残留 / 复用其 `runtime_data` / 加载其插件清单 /
复用其含明文账号的配置文件 / 在代码中写入指向旧目录的路径常量或注释。

> 已做零耦合自检：检索旧项目路径共 7 处命中，**全部位于注释与文档**，代码逻辑中零引用。

### 10.2 安全红线

- 旧项目的明文账号密码**绝不迁移、绝不复制、绝不写入代码/配置/提交记录**
- **必须提供账号修改窗口**（界面或命令行均可），不能只有写死配置一种方式
- 测试用账号通过**安全的测试配置注入**；正式构建不硬编码任何凭据
- 凭据优先用 Windows 凭据管理器 / DPAPI 加密，**至少不能是明文**
- 日志与报错必须**脱敏**，覆盖 `password`/`passwd`/`token`/`cookie`/`authorization`/`username`
- 敏感信息不入库：账号、密码、Cookie、Token、Keystore、签名密码

### 10.3 旧项目缺陷——本次不得复刻

| # | 缺陷 | 本次做法 |
| --- | --- | --- |
| 1 | 同名 ZIP **静默覆盖**（会丢数据） | 改为 Windows 同名副本命名法 |
| 2 | 错误分类靠消息关键词匹配，含 "name" 就误判为 DNS 失败 | 按异常类型判定 |
| 3 | 插件跨复用靠**路径探测 + 硬编码路径** | 改为服务注册表 |
| 4 | 依赖清单与实际依赖不一致（全空数组） | 依赖声明必须真实生效 |
| 5 | 配置 schema 只声明不校验 | 默认值与校验真正生效 |
| 6 | 主窗口与详情窗争抢日志处理器，并发时日志被抢 | 独立日志通道 |
| 7 | 图片对象在工作线程创建（跨线程脆弱） | 工作线程只产出数据，主线程创建 UI 对象 |
| 8 | 翻页用输入框当前关键词，改词后翻页语义错乱 | 翻页绑定发起搜索时的关键词 |
| 9 | 插件摸宿主私有属性（如 `backend.option`） | 插件只走协议，不碰私有实现 |
| 10 | 事件总线无锁（Python 靠 GIL 侥幸） | 显式加锁 / 并发容器 |

### 10.4 工程纪律

- **Git**：从第一天起进仓库；每个里程碑打 `checkpoint-YYYYMMDD-NN` 标签
- **开发日志**：写在 `docs/devlog/`；**没有日志的提交不算有效里程碑**
- **依赖清单必须入库**（旧项目最大教训：无 requirements.txt，版本只能反推）
- **文件命名**：时间 + 主题 + 版本
- **不硬编码路径**：任何绝对路径都不写进代码
- **分段验收再合并**：每阶段测试必须真跑，失败不得声称完成
- **最小修改**：严格按预案执行，遇与预案不符的情况先停下输出检查点，由人工审批

### 10.5 环境搭建阶段已踩过的坑（后续避免重犯）

| # | 问题 | 原因 | 处理 |
| --- | --- | --- | --- |
| 1 | 主项目编译报 Xunit 类型找不到、AssemblyInfo 特性重复 | SDK 默认 glob 把测试项目的 `.cs` 也卷进主项目编译 | 主项目排除测试目录 |
| 2 | `Path` / `File` 未解析 | 缺 `using System.IO` | 补 using |
| 3 | CS1626：无法在带 catch 的 try 块中 yield return | C# 语法限制 | 改为先收集到 List 再返回 |
| 4 | Python 报 `SyntaxWarning: invalid escape sequence` | 文档字符串里的 Windows 路径反斜杠 | 注释中不写裸路径 |

### 10.6 必须保持等价的可观察行为（用户已习惯）

| 项 | 行为 |
| --- | --- |
| 批量编号分隔符 | `-`、`,`、`，`、`、`、`;`、`；`、空白 |
| 默认下载路径 | 桌面 |
| 并发数 | 3 |
| 产物命名 | `{标题}-JM{编号}.zip`；标题取不到时为 `未知标题-{编号}` |
| 文件名非法字符 | 剥除 `\ / * ? : " < > \|` |
| ZIP 内文件名 | `001.ext`、`002.ext`…（三位零填充，后缀取首图） |
| 搜索结果行 | 封面 80×110、标题加粗、作者、`页数: N \| JM号: id`、详情/下载按钮 |
| 封面失败 | 暗红底 `X` |
| 详情简介 | 超 200 字截断加省略号 |
| 空结果文案 | 灰色"未找到相关结果" |
| 完成弹框 | "完成，成功 x / 共 y，失败 z" |
| ZIP 浏览错误文案 | 逐字锁定：`压缩包不存在` / `不是有效的 ZIP 压缩包` / `压缩包中没有可浏览的图片` / `压缩包已关闭` / `页码超出范围` |
| 页码排序 | 自然排序（`999` 在 `1000` 之前） |

### 10.7 明确不做的事

- 不复刻旧项目历史缺陷（见 10.3）
- 不引用、不复制旧项目任何代码与文件
- 不写入任何真实账号密码
- 不做插件沙箱隔离 / 热插拔 / 协议降级兼容层
- 不做旧数据迁移工具
- 暂不做进度条
