## 一、产品定位一句话

把旧项目的功能原样搬到新外壳上：界面换成 PCL2 风格，功能一个不少，用户已有的使用习惯尽量不变。

---

## 二、功能总览（7 大块）

```
JML
├── 1. 下载（主功能）
├── 2. 搜索
├── 3. 详情
├── 4. 下载历史          ← 旧插件移植
├── 5. 收藏夹浏览        ← 旧插件移植
├── 6. ZIP 浏览          ← 旧插件移植
├── 7. ZIP 网页浏览      ← 旧插件移植
└── （附）设置与账号
```

界面组织：**标签页**形式，顶部切换，底部一条状态栏（与旧项目一致）。

## 三、逐块功能说明

### 1. 下载（主功能）

**用户能做什么**
- 在输入框里填 JM 本子编号，**支持一次填多个**（用 `-`、`,`、`，`、`、`、`;`、`；`、空格 分隔都行）
- 选择下载到哪个文件夹（默认是桌面）
- 点「开始下载」，程序开始批量下载
- 下载过程中可以点「取消」

**规则与表现**
| 行为 | 说明 |
| --- | --- |
| 并发 | 同时最多下 **3** 本 |
| 取消方式 | **软取消**：只跳过还没开始的本子，正在下的那一本会跑完 |
| 单本失败 | 某一本失败不影响其它本子，继续下 |
| 完成后 | 弹框提示"成功 x / 共 y，失败 z" |
| 日志 | 只读文本框，自动滚到底，显示下载过程 |
| 产物 | 每本打包成一个 ZIP，文件名 `{标题}-JM{编号}.zip` |
| 质量保证 | 打包后校验 ZIP 条目、图片能否解码、像素是否有效，不过关就判这本失败 |

**已知的旧项目缺陷，本次要改进**
- 同名 ZIP 旧项目是**静默覆盖**（会丢数据）→ 本次改为**自动改名**或**询问**（待确认，见第五节）

### 2. 搜索

**用户能做什么**
- 输入关键词搜索，结果以列表展示
- 每条显示：封面缩略图、标题、作者、页数、JM 号
- 每条右侧有「详情」「下载」两个按钮
- 翻页（上一页 / 下一页，显示"第 N 页 / 共 M 页"）

**规则与表现**
- 搜索参数、总页数算法、页数补全规则与旧项目保持一致（用户已习惯）
- 封面异步加载，不卡界面；加载失败显示红色 `X`
- 无结果时显示灰色"未找到相关结果"
- 搜索失败时状态栏提示并弹错误框

### 3. 详情

**用户能做什么**
- 从搜索列表点「详情」打开，查看单本完整信息
- 看到：封面、标题、作者、页数、标签、简介
- 点「下载本子」直接下载这一本

**规则与表现**
- 简介超过 **200 字**截断加省略号
- 有独立的下载日志区域
- 加载失败时提示

### 4. 下载历史（旧插件移植）

**用户能做什么**
- 在一个独立标签页里看到以前下载过什么
- 每条显示：时间、本子号、成功/失败、输出文件路径
- 可设置最多保留多少条（默认 200 条）

### 5. 收藏夹浏览（旧插件移植）

**用户能做什么**
- 查看**当前登录账号的收藏夹**
- 列表样式与搜索结果一致（封面 + 标题 + 作者 + JM 号）
- 支持切换收藏夹目录、改变排序（最近收藏 / 最多点击 / 最多图片）
- 每条可「详情」「下载」

**前提**
- 需要账号处于登录状态，未登录时给出明确提示

### 6. ZIP 浏览（旧插件移植）

**用户能做什么**
- 选择一个文件夹，列出里面所有 ZIP
- 双击打开某个 ZIP，**直接在包里翻页看图**（不解压到磁盘）
- 上一页 / 下一页，显示"第 n 页 / 共 N 页"
- 窗口缩放时图片重新适配
- 返回列表（点返回按钮或按 Esc）

**规则**
- 页码排序必须是**自然排序**（`999` 排在 `1000` 前面，不能按字符串排）

### 7. ZIP 网页浏览（旧插件移植）

**用户能做什么**
- 选文件夹、列出 ZIP
- 点「用浏览器阅读」→ 自动打开系统浏览器，进入**无缝纵向连续阅读**（图片一张接一张，无间隙）
- 可以点「停止浏览服务」关闭

**表现**
- 只在本机回环地址启动服务，不对外
- 端口由系统自动分配，每次打开自动释放
- 浏览器页面显示"第 n 页 / 共 N 页"进度

## 四、设置与账号（新增，旧项目没有）

因为安全红线要求**不得沿用旧项目的明文配置**，账号部分需要新增界面：

| 功能 | 说明 |
| --- | --- |
| 账号录入窗口 | 用户在界面里填账号密码，不写入明文配置文件 |
| 凭据安全存储 | 用 Windows 凭据管理器或 DPAPI 加密，**不存明文** |
| 下载路径设置 | 记住用户上次选择的下载目录 |
| 各插件的设置项 | 收藏夹排序、ZIP 浏览文件夹、历史保留条数等 |

> 硬性要求：**测试时的账号通过安全的测试配置注入，禁止硬编码账号密码。**

## 五、已确定的决策（2026-10-16 用户拍板）

| # | 事项 | 决策 |
| --- | --- | --- |
| 1 | 同名 ZIP | 采用 **Windows「同名副本」命名法**：`xxx.zip` → `xxx - 副本.zip` → `xxx - 副本 (2).zip`…；不再静默覆盖 |
| 2 | 取消语义 | **真取消**：立即中断正在进行的下载，不再等当前本子跑完 |
| 3 | ZIP 网页浏览 | **外部浏览器**（唤起系统默认浏览器），不做应用内嵌阅读器 |
| 4 | 进度条 | **暂时搁置**，保持只有文字日志 |
| 5 | 交付形态 | **zip 便携版**（解压即用，无需安装程序） |
| 6 | 旧数据 | **不迁移**，新项目从零开始（旧历史、旧插件配置一律不带过来） |
| 7 | 插件体系 | **保留并完善**；后续功能更新**全部通过插件添加** |
| 8 | 主程序边界 | 主程序只保留**下载、搜索、详情（及其唤起下载）**；其余功能一律做成插件 |
| 9 | 插件间服务 | **允许**插件之间互相提供服务（主程序 + 插件都可注册服务） |
| 10 | 协议版本不兼容 | **拒绝加载**并明确提示，不做降级兼容层 |
| 11 | 插件扩展设置界面 | **允许**（插件自己的设置项可进入主设置窗口） |
| 12 | 品牌 | 程序名称定为 **JM Launcher**；图标方案已确定（见第六节） |

## 六、品牌与图标方案（已确定）

### 6.1 素材来源

用户补充克隆了完整 PCL2 仓库 `D:\vscode\Project\PCLUI\PCL-main`，其中**确有图标资源**
（此前 `PlainToolkit.UI` 仓库只有样式、无任何图片，故先前查不到）：

| 文件 | 尺寸 | 用途（代码实测确认） |
| --- | --- | --- |
| `Images/icon.ico` | 13 帧，16~256 | 应用图标（`vbproj` 的 `ApplicationIcon` + 启动闪屏） |
| `Images/Heads/Logo.png` | 64×64 | 关于页、模组启动画面 |
| `Images/Heads/PCL2.png` | 64×64 | 仅在关于页展示 |

用户已确认：**图标同样开源，可沿用**。

### 6.2 一个重要事实修正

原计划"采用图标背景、把文字改成 JML"。实测发现：
**PCL2 标题栏的 Logo 不是图片，而是矢量 `Path`**
（`FormMain.xaml:117` 的 `ShapeTitleLogo`，`Data="M26,29 v-25 h6 ..."` 画出 "PCL" 字样）。
它是路径描边，无法"改文字"。

但 PCL2 **本身就内置了文字 Logo 模式**（`FormMain.xaml.vb:725` 的 `UiLogoType`）：

| 值 | 模式 | 控件 |
| --- | --- | --- |
| 0 | 无 | 不显示 |
| 1 | 默认 | `ShapeTitleLogo`（矢量 "PCL" 路径） |
| **2** | **文本** | **`LabTitleLogo`，文字取自设置项 `UiLogoText`** |
| 3 | 图片 | `ImageTitleLogo`（读 `PCL\Logo.png`） |

### 6.3 最终方案

| 位置 | 方案 |
| --- | --- |
| **程序名** | JM Launcher |
| **标题栏** | PCL2 同款渐变背景 + `UiLogoType=2` 文本模式，文字 = **JML** |
| **应用图标** | 沿用 PCL2 `icon.ico`，图标文字 = **JML** |

走 PCL2 原生支持的路径，无需改矢量路径、无需画图。

### 6.4 关于"能否用矢量图写图标"（用户提问）

**结论：界面内可以用矢量；但 .ico 文件本身不行，必须导出位图。**

**实测证据**：对 `icon.ico` 做字节级解析，13 帧全部是位图——

```
count=13
  帧0:  48x48   BMP/DIB 位图     帧7:  48x48   BMP/DIB 位图
  帧1:  32x32   BMP/DIB 位图     帧8:  40x40   BMP/DIB 位图
  帧2:  16x16   BMP/DIB 位图     帧9:  32x32   BMP/DIB 位图
  帧3:  256x256 PNG  位图        帧10: 24x24   BMP/DIB 位图
  帧4:  128x128 BMP/DIB 位图     帧11: 20x20   BMP/DIB 位图
  帧5:  96x96   BMP/DIB 位图     帧12: 16x16   BMP/DIB 位图
  帧6:  64x64   BMP/DIB 位图
```

ICO 是**多尺寸位图容器**（微软官方说明其帧为 `BITMAPCOREHEADER` / `BITMAPINFOHEADER`
或内嵌 PNG 三种位图形态），**不支持 SVG 等矢量格式**。

**因此做法如下（已写入计划书）**：

| 用途 | 是否可用矢量 | 做法 |
| --- | --- | --- |
| 窗口标题栏、界面内图标 | ✅ **可以** | 直接用 WPF `Path` / `DrawingImage` 写矢量，任意缩放不失真 |
| 任务栏 / exe / 资源管理器图标 | ❌ **不行** | 必须以 `.ico` 提供；由矢量源**导出**多尺寸位图后打包 |

**推荐的图标工作流**（矢量源 + 按需导出）：

```
矢量源（XAML Path 或 SVG，单一真源）
   ├─→ 界面内：直接引用矢量，任意 DPI 清晰
   └─→ .ico  ：按 16/20/24/32/40/48/64/96/128/256 各导出一张位图，
                打包成单个多帧 .ico
```

**必须包含多尺寸帧的理由**：Windows 在任务栏、资源管理器列表、
大图标视图、高 DPI 屏（150%/200%）会各取不同帧。
单帧 ico（如只用 32×32）在其它场景会被拉伸而模糊。
—— 这也是"沿用 PCL2 `icon.ico`"可行的重要原因：它已含 13 帧（16~256）。

## 七、建议的开发顺序（按依赖关系排）

> 已按第五节决策调整：插件体系**提前**到主功能之前，
> 因为后续所有功能都要以插件形式挂载。

```
阶段 0  环境（已完成）
        └─ Git / 依赖清单 / pythonnet 桥接 / 主题 / 目录与脱敏

阶段 1  主程序外壳 + 插件协议（地基，最先做）
        ├─ 主窗口标签页框架 + 状态栏
        ├─ Python 环境检测与引导界面
        ├─ 插件协议：数据模型 / 服务注册表 / 事件 / UI 扩展点 / 配置契约
        └─ 插件管理界面（启用 / 停用 / 重新扫描 / 查看状态）

阶段 2  主程序核心功能（按决策只保留三项）
        ├─ 下载：编号解析 / 目录选择 / 批量下载 / 真取消 / 同名副本命名 / 打包与校验
        ├─ 搜索：列表 / 封面 / 翻页
        └─ 详情：详情窗 + 唤起下载

阶段 3  账号与设置
        └─ 账号录入 + 安全存储（收藏夹插件依赖登录态，须先于它做）

阶段 4  四个旧插件（全部以插件形式移植）
        ├─ 下载历史（最简单，先做）
        ├─ ZIP 浏览（并对外注册"压缩包读取"服务）
        ├─ ZIP 网页浏览（依赖上一项提供的服务）
        └─ 收藏夹浏览（依赖阶段 3 的登录态）

阶段 5  收尾
        └─ 整体回归 / 无界面自检命令 / zip 便携版发布配置
```

**排序理由**：

1. 插件协议必须最先做——后续所有功能都是插件，协议不定则无法挂载；
2. 主程序三项核心紧随其后，它们是插件要调用的服务来源；
3. 账号先于收藏夹，因为收藏夹需要登录态；
4. ZIP 网页浏览依赖 ZIP 浏览注册的服务，所以排在其后；
   按新协议这是**服务依赖**，不再是旧项目那种路径探测。

## 八、验收口径（功能层面）

每完成一个阶段，按下面三条验收：

1. **功能可用**：按本计划书描述，人工实际操作一遍走通
2. **结果与旧项目一致**：可观察行为（文案、文件名、排序、错误提示）与旧项目对照无差异
3. **下载类功能不看状态文字，看实际产物**：必须检查 ZIP 是否生成、条目数量对不对、图片能否打开、像素是否正常

补充两条针对插件体系的验收：

4. **插件依赖真实生效**：停用一个插件时，依赖它的插件必须给出明确提示，而不是崩溃
5. **零路径探测**：插件之间不得靠文件路径互相加载（这是旧项目的根因缺陷）

## 九、明确不做的事

- 不做旧项目的历史缺陷复刻（静默覆盖同名文件、错误分类误判、路径探测加载等）
- 不引用、不复制旧项目的任何代码与文件
- 不在代码或配置里写入任何真实账号密码
- 不做插件沙箱隔离（保持同进程，与 Python 桥接方案一致）
- 不做插件热插拔（重启生效即可）
- 不做协议降级兼容层（版本不匹配直接拒绝）
