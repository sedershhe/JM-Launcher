## 一、目标与边界

### 1.1 要做什么

做一个 `list` 模板插件，进入页面自动跑一轮测试，回答一个问题：

> 当前这台机器、这条网络，现在能访问哪个禁漫网页域名？

测试分三类：

1. **重定向探测**：复刻 jmcomic 的 `JmModuleConfig.get_html_domain()`——访问永久网域，跟随 301、在 302 处取 `Location`，解析出当前可用的网页域名。
2. **发布页入口探测**：访问 `JM_PUB_URL`（`https://jmcomicgo.org`），跟随 301 到最终发布页，判定发布页是否可达。只判连通性，不解析页面里的域名列表。
3. **候选域测活**：对已知的网页候选域逐个发 HTTPS 请求，记录 HTTP 状态、耗时、最终地址，给出"可用 / 受限 / 不可用"判定。

### 1.2 不做的事（已与用户确认）

| 不做 | 原因 |
| --- | --- |
| 测移动端 API 域名、图片 CDN、域名下发服务器 | 用户确认只测网页域名 |
| 解析发布页页面内容、抓全量域名列表 | 用户 2026-11-13 拍板：只把发布页**入口**纳入候选，不做页面解析 |
| 改主程序配置、覆盖 jmcomic 的域名缓存 | 只读诊断，不得干预搜索/下载的选域 |
| 写 `ctx.config_set`、写 `ctx.data_dir`、存历史 | 只读诊断，不落盘 |
| 新增宿主服务 | 纯插件实现，零宿主改动 |

### 1.3 验收口径

- 进入页面后能拿到一张表：每行一个域名，含判定、HTTP 状态、耗时、最终地址。
- 表里至少有：永久网域入口行、发布页入口行；静态候选行按去重后的结果展示（目标域与某个静态候选相同时，只保留 `redirect_target` 一行）。
- 探测走系统代理（与 jmcomic 的 `get_html_domain()` 同口径）：插件读取 `JmModuleConfig.DEFAULT_PROXIES` 并传给 `curl_cffi`；系统没有代理时直连。
- 28 秒内出结果（含总预算截断）。
- 页面上"重测"只重测该行，不重跑全部。
- 插件不写任何宿主状态；关掉插件后主程序行为无变化。

## 二、依据：jmcomic 2.7.1 的实现拆解

### 2.1 调用链

```
JmModuleConfig.get_html_domain()            jm_config.py:326-335
  └─ JmcomicText.parse_to_jm_domain(...)    jm_toolkit.py:68-72
       └─ JmModuleConfig.get_html_url()     jm_config.py:337-347
            └─ postman.with_redirect_catching().get(JM_REDIRECT_URL)
                 └─ RedirectPostman          common/postman/postman_proxy.py:138-163
```

永久网域常量（`jm_config.py:113`）：

```python
JM_REDIRECT_URL = 'https://jm365.work/3YeBdF'
```

### 2.2 重定向规则（RedirectPostman）

源码 `common/postman/postman_proxy.py:138-163`，行为是：

1. 每次请求默认置 `allow_redirects=False`（`kwargs.setdefault`，调用方显式传 `True` 可覆盖）；
2. 状态码 **301** → 读 `Location`，继续请求下一跳（永久移除）；
3. 状态码 **302** → 停止循环；
4. 其它状态码 → 抛 `NotImplementedError("status_code = ...")`；
5. 最终返回最后一次响应的 `Location` 头。

第 2 步的循环是 `while True`，**没有跳数上限**；插件自己限 4 跳（见 §5.2）。

也就是说，jmcomic 认为"真正的可用域名"是 302 跳转的目标地址，301 只是路径上的中转。

### 2.3 域名解析（parse_to_jm_domain）

源码 `jm_toolkit.py:7`、`68-72`：

```python
pattern_jm_domain = compile(r'https://([\w.-]+)')

@classmethod
def parse_to_jm_domain(cls, text: str):
    if text.startswith(JmModuleConfig.PROT):
        return cls.pattern_jm_domain.search(text)[1]
    return text
```

所以 `Location` 是 `https://18comic.vip/...` 时取 `18comic.vip`；不是 https 开头时原样返回。

### 2.4 缓存副作用（为什么不能直接调用）

`get_html_domain()` 带 `@field_cache("DOMAIN_HTML")`（`jm_config.py:326-327`）。`field_cache` 的实现是：第一次调用把返回值写进 `JmModuleConfig.DOMAIN_HTML`，之后直接返回缓存，不再测（`common/util/decorator_util.py:40-69`）。

`DOMAIN_HTML` 与 `DOMAIN_HTML_LIST` 的优先级写在 `jm_config.py:207-213`：

```
# 使用优先级:
# 1. DOMAIN_HTML_LIST
# 2. [DOMAIN_HTML]
```

结论：**直接调用 `get_html_domain()` 会写主程序的模块级域名缓存**。用户要的是"只读诊断"，所以插件不复用这个函数，只复刻它的规则（301 继续、302 取 Location、正则取域名）。同理，`get_html_domain_all()` 会写 `DOMAIN_HTML_LIST`，也不调用。

### 2.5 运行时自动换域（仅作背景，不进插件）

- `request_with_retry`（`jm_client_impl.py:53-124`）：先试 `domain_list[0]`，失败逐个换域，全失败抛 `RequestRetryAllFailException`。
- `AdvancedRetryPlugin`（`jm_plugin.py:1261-1349`）：按历史失败次数排序域名，单域失败到上限就跳过。
- `JmApiClient.after_init`（`jm_client_impl.py:984-992`）：从 3 个 bytepluses 地址拉最新移动端 API 域名（拉取细节在 `fetch_latest_api_domain_for_module`，`1017-1050`）。

这些是"请求时容错"，不是"主动测试"，本插件不涉及。

### 2.6 候选域名从哪来

只读地取四个来源，按优先级拼接：

| 优先级 | 来源 | 代码位置 | 角色 | 默认 |
| --- | --- | --- | --- | --- |
| 1 | 永久网域 `https://jm365.work/3YeBdF` | `jm_config.py:113` | `redirect_entry` | 开 |
| 2 | 发布页入口 `https://jmcomicgo.org/` | `jm_config.py:114` | `publish_entry` | 开（2026-11-13 拍板） |
| 3 | 插件内置静态兜底 3 个 | 与 `jm_source.py:245-249` 同步 | `static_fallback` | 开 |
| 4 | `JmModuleConfig.DOMAIN_HTML`（若已有值） | `jm_config.py:212` | `jmcomic_cache` | 关（通常为 `None`） |
| 5 | `JmModuleConfig.DOMAIN_HTML_LIST`（若已有值） | `jm_config.py:213` | `jmcomic_list` | 关（可选） |

静态兜底取项目现有常量（`jm_source.py:245-249`）：

```
comic18j-moco.work
comic18j-nico.site
comic18j-ada.work
```

说明：

- **默认候选 = 第 1、2、3 行**，运行期再追加 `redirect_target`。
- 插件允许 `import jmcomic` **只读**读取 `JmModuleConfig.DEFAULT_PROXIES`（代理需求，§4.1）与 `JM_REDIRECT_URL` / `JM_PUB_URL` 常量；**不读** `DOMAIN_HTML` / `DOMAIN_HTML_LIST`（第 4、5 行默认关闭），不调用任何方法、不写字段。理由：项目约定 jmcomic 只在 `jm_source` 里 import，代理这一项是 2026-11-13 用户拍板后必须破例的最小范围。
- 发布页入口 URL：优先 `getattr(JmModuleConfig, "JM_PUB_URL", "https://jmcomicgo.org")`；`import jmcomic` 失败时用内置常量 `https://jmcomicgo.org`。
- 插件内复制静态常量，注释标明"与 `Python/jml/core/jm_source.py:245-249` 同步"；**不 import `jm_source` 的私有常量**。
- 去重后最多 8 个（含两个入口），超出按上表优先级截断。截断是为了把最坏耗时压在预算内。`redirect_target` 是运行期追加行，不计入这 8 项。
- 域名规范化（只对第 4、5 行，若以后开启）：先 `str(item).strip().lower()`；**含 `/`、`:` 的项直接跳过**（发布页列表里夹带 `jm365.xyz/ZNPJam` 这类 APP 下载地址，去掉路径会变成假域名）；再去 `http://` / `https://` 前缀、去首尾空白；`.` 不在其中的跳过。`DOMAIN_HTML` 可能是裸域或带协议的 URL；`DOMAIN_HTML_LIST` 可能是 `list` / `set` / `tuple` / `str`（多行）/ `None`——`str` 当单个整体处理，`set`/`tuple` 转 `list`，`None` 跳过，不能直接把字符串丢进 `for`（会按字符迭代）。
- 发布页**页面内容**不解析：只跟随 301、判定最终页是否 200；不调用 `get_html_domain_all()`（它会写 `DOMAIN_HTML_LIST` 缓存）。
- **2026-11-12 实测背景**：第 1 行与第 3 行在直连环境下 DNS 全部失败，只有发布页入口可访问；这就是把第 2 行纳入候选的原因。

## 三、总体设计

### 3.1 文件与职责

```
plugins/connectivity_test/
├── plugin.json     清单：id / 页面 / 空服务
├── main.py         页面对象：组装候选、调度探测、拼 list JSON、重测动作
└── probe.py        探测内核：单域 HTTP 探测 + 重定向链，纯函数，可注入假实现做单测
```

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| `probe.redirect_probe(entry_url, fetch, *, stop_on_302=True)` | 入口 URL、可注入的 fetch；`stop_on_302=True` 用于永久网域，`False` 用于发布页（301 跟到底、200 收口） | `{verdict, http_status, latency_ms, final_url, hop_chain, error}` |
| `probe.probe_domain(domain, fetch)` | 裸域名、可注入的 fetch | 同上（单跳，`allow_redirects=False`） |
| `probe.proxies_from_jmcomic()` | 无（内部只读 `jmcomic.JmModuleConfig.DEFAULT_PROXIES`） | `dict` 或 `None`；供 `fetch` 传给 curl_cffi |
| `main.ConnectivityPage.load(params)` | 宿主参数 `{"page": 1}` | list 模板 JSON |
| `main.ConnectivityPage.action_retest(payload)` | `{"row": {...}, "row_index": n, "page": 1}` | `{"ok", "data", "message"}` |

### 3.2 数据流

```
进入页面
  └─ load({"page": 1})
       ├─ 组装候选（最多 8 项，见 §2.6）
       ├─ 并发调度（4 路）
       │    ├─ 永久网域 → redirect_probe(stop_on_302=True)：逐跳 301，302 收口
       │    │       └─ 得到最终域名 → 追加 redirect_target 任务
       │    ├─ 发布页 → redirect_probe(stop_on_302=False)：逐跳 301，200 收口
       │    └─ 其余候选 → probe_domain()：请求 https://{domain}/
       ├─ 等全部完成或到总预算（28 秒）
       └─ 排序 + 拼 list JSON 返回
```

`redirect_target` 是**依赖任务**：入口链跑完才知道测哪个域。它不计入 8 项候选上限，追加后与最后一轮候选并发；最坏耗时见 §5.1。

### 3.3 页面对象状态

```python
class ConnectivityPage:
    def __init__(self, ctx):
        self._ctx = ctx
        self._lock = threading.Lock()
        self._rows = []          # 本轮结果（只存 JSON 基本类型）
        self._checked_at = ""    # 本轮开始时间
```

- `_rows` 只存在内存，不落盘、不写 config。
- `load` 每次重新跑一轮并覆盖 `_rows`；写 `_rows` 时持 `self._lock`。
- `action_retest` 读 `_rows`、只更新一行、返回整页 `data`。
- `_page_payload()` 负责把 `_rows` + `_checked_at` 拼成 §6.2 的 list JSON（含 `columns`、分页字段、`row_actions`）；`load` 与 `action_retest` 共用它，保证两种返回结构一致。

## 四、候选与判定规则

### 4.1 每项怎么测

| 角色 | 请求 | 跟随重定向 | 说明 |
| --- | --- | --- | --- |
| `redirect_entry` | `https://jm365.work/3YeBdF` | 手动，最多 4 跳 | 301 继续，302 停并取 `Location`；其它状态码记为异常 |
| `publish_entry` | `https://jmcomicgo.org/` | 手动，最多 4 跳 | 301 继续，200 收口；只判发布页可达，不解析页面里的域名列表 |
| `redirect_target` | `https://{最终域}/` | 不跟 | 由入口链解析出来，单独测一次，证明目标域本身可访问 |
| `jmcomic_cache` / `jmcomic_list` / `static_fallback` | `https://{domain}/` | 不跟 | 只判可达性 |

说明：

- 普通域只请求根路径 `https://{domain}/`，作为"连通性采样点"。它不代表搜索页或详情页一定成功（项目搜索通道请求的是 `/search/photos?...`，判定更严）。这样选是为了少传参数、降低触发风控的概率；如果以后发现根路径被 Cloudflare 拦而搜索页正常，再把采样点改成搜索页。
- `publish_entry` 的 200 页面是"发布页"，不是漫画站；它只能证明"发布页入口这条链路可达"，不能证明漫画站可用。界面角色文案要写"发布页入口"，不要写成"可用域名"。
- `redirect_entry` 和 `publish_entry` 共用一个重定向函数，用 `stop_on_302` 区分：入口 `True`（302 取 Location 作为漫画站域名），发布页 `False`（301 跟到底，200 收口）。
- `Referer` 的 host 按角色取：`redirect_entry` 用 `jm365.work`，`publish_entry` 用 `jmcomicgo.org`，普通域用域本身。

请求参数（timeout / impersonate / Accept-Language 的取值参照 `jm_source._fetch_html`；`allow_redirects=False` 是本插件有意不同，为了手动跟 301）：

```python
creq.get(
    url,
    timeout=8.0,
    impersonate="chrome",
    allow_redirects=False,
    proxies=proxies_from_jmcomic(),   # 见下；None 表示直连
    headers={
        "Accept-Language": "zh-CN,zh;q=0.9",
        "Referer": f"https://{domain}/",
    },
)
```

`impersonate="chrome"` 沿用 jmcomic 的做法（`jm_config.py:455-465` 的 `new_postman` 默认 chrome），避免被 TLS 指纹拦截；`Referer` 参照 `jm_source._fetch_html`，少一个被 403 的理由。

**代理口径（2026-11-13 用户拍板：跟随系统代理）：**

- jmcomic 的 `get_html_url()` 走 `new_postman()`，默认带 `proxies=DEFAULT_PROXIES`，而 `DEFAULT_PROXIES = ProxyBuilder.system_proxy()`（`jm_config.py:455-465`、`473`）——即**跟随系统代理**。
- 插件读取同一个字段，保证与 `get_html_domain()` 同口径：

```python
def _normalize_proxy(value):
    text = str(value or "").strip()
    if not text:
        return None
    # ProxyBuilder 返回的是 "host:port"，curl_cffi 需要带协议的 URL
    return text if "://" in text else f"http://{text}"

def proxies_from_jmcomic():
    try:
        import jmcomic
        raw = getattr(jmcomic.JmModuleConfig, "DEFAULT_PROXIES", None)
    except Exception:
        return None                    # jmcomic 不可用：直连
    if not raw:
        return None                    # 系统没配代理：直连
    if isinstance(raw, dict):
        pairs = {k: _normalize_proxy(v) for k, v in raw.items()}
        pairs = {k: v for k, v in pairs.items() if v}
        return pairs or None
    if isinstance(raw, str):
        value = _normalize_proxy(raw)
        return {"http": value, "https": value} if value else None
    return None
```

- `DEFAULT_PROXIES` 是 `ProxyBuilder.system_proxy()` 的结果：没配代理时是 `{}`，配了是 `{"http": "...", "https": "..."}`（`common/util/requests_util.py:27-42`）。
- `ProxyBuilder` 返回值去掉了协议前缀（形如 `127.0.0.1:7890`），传给 curl_cffi 前要补 `http://`，否则可能被当成协议名。
- 代理地址可能含账号密码，**绝对不要**写进 `ctx.log`、行数据或错误消息。
- `import jmcomic` 失败（或字段缺失）时退回直连；这是兜底，不是默认路径。
- 项目 `jm_source._fetch_html` 是直连（`jm_source.py:429-438`），与本插件口径不同；这是 2026-11-13 拍板的已知差异，不视为 bug。

### 4.2 判定表

| 情况 | verdict | `result`（界面标签，只 4 值） | `description` 里的细分文案 |
| --- | --- | --- | --- |
| HTTP 200，且响应前 8KB 不含异常特征 | `ok` | 可用 | HTTP 200 · 耗时 |
| HTTP 200，含 `Restricted Access!` | `restricted` | 受限 | 地区受限 |
| HTTP 200，含 `Could not connect to mysql!` | `restricted` | 受限 | 服务端异常 |
| HTTP 200，含 Cloudflare 挑战特征（`Just a moment` / `cf-challenge`） | `restricted` | 受限 | 人机验证 |
| HTTP 301 / 302，且 `Location` 是 https 网页域 | `ok` | 可用 | 跳转 · 最终地址 |
| HTTP 403 | `restricted` | 受限 | 访问被拒 |
| HTTP 429 | `restricted` | 受限 | 请求过多 |
| 其它 4xx（400 / 404 / 451 等） | `restricted` | 受限 | 访问被拒 |
| HTTP 5xx | `restricted` | 受限 | 服务端异常 |
| 超时 / DNS 失败 / SSL 失败 / 连接失败 | `fail` | 不可用 | 异常类型 |
| 到总预算仍未完成 | `pending` | 未完成 | 超过预算 |

异常特征取自 jmcomic 自带文案（`jm_config.py:119-122`）：

```python
JM_ERROR_RESPONSE_TEXT = {
    "Could not connect to mysql! Please check your database settings!": "禁漫服务器内部报错",
    "Restricted Access!": "禁漫拒绝你所在ip地区的访问，你可以选择: 换域名/换代理",
}
```

注意：`restricted` **不算可用**，可用域名只从 `ok` 里取。界面上不单独标"推荐"——排序天然把 `ok` 放前面，无需新增字段（`list` 模板也没有合适的位置）。这与项目搜索通道"非 200 即失败"的口径不同——连通性测试要区分"网络通但被拒"和"网络不通"，所以单列一类。

### 4.3 排序与去重

1. `redirect_entry` 固定第一行；
2. `publish_entry` 固定第二行；
3. `redirect_target` 紧随其后（如果有）；
4. 其余按 `verdict` 权重：`ok` > `restricted` > `fail` > `pending`；
5. 同权重按 `latency_ms` 升序；
6. 同域名去重，保留优先级高的角色：`redirect_target` > `publish_entry` > `jmcomic_list` > `jmcomic_cache` > `static_fallback`；
7. §2.6 的"最多 8 项"只作用于组装阶段，`redirect_target` 是入口完成后追加的，不计入这 8 项，也不与静态项抢名额。

## 五、探测实现细节

### 5.1 并发与预算

- 线程池：`ThreadPoolExecutor(max_workers=4, thread_name_prefix="jml-conn")`。
- 单域超时：8 秒（与 `jm_source.HTML_CHANNEL_TIMEOUT = 8.0` 一致）。
- 两个入口（`redirect_entry`、`publish_entry`）：最多 4 跳，单跳 **5 秒**，每条链最长 20 秒（2026-11-13 用户拍板，由 3 秒改为 5 秒：实测发布页耗时 0.6–3.0 秒波动，出现过 3006ms 被 3 秒超时误判的案例）。
- 默认候选 5 项（两个入口 + 3 个静态）；上限 8 项（含两个入口）。两个入口并行跑、各最长 20 秒；其余候选在空位上跑，8 秒一轮即可完成；`redirect_target` 在入口完成后追加，与最后一轮重叠。**最坏约 28 秒**（入口链 20 秒 + `redirect_target` 8 秒）。
- 总预算：28 秒（恰好覆盖 28 秒理论最坏值，无剩余余量；实测典型 2–9 秒）。到点后未完成的任务标记 `pending`，不阻塞页面返回。
- 收尾：

```python
pool = ThreadPoolExecutor(max_workers=4, thread_name_prefix="jml-conn")
try:
    ...
finally:
    pool.shutdown(wait=False, cancel_futures=True)
```

为什么不用 `with ThreadPoolExecutor(...)`：`with` 退出时会 `wait=True`，总预算到点后仍要等最慢的任务（最多 8 秒），与"预算到点立即返回"冲突。

补充两条收尾事实：

- `shutdown(wait=False)` 不会杀已运行的任务，它们最多再跑 8 秒（受 curl 超时约束）。`load` 是宿主串行调用，不会同时叠很多轮；页面返回后这些线程只是收尾，不写任何共享状态。
- 线程池 worker 不是 daemon，但它们由 `load` 创建并随请求结束而退出；协议 §5.7 约束的是"`setup` 里起非 daemon 线程"，本插件不违反。

### 5.2 重定向链

```python
from urllib.parse import urljoin

def redirect_probe(entry_url, fetch, max_hops=4, hop_timeout=3.0, stop_on_302=True):
    hops = []
    url = entry_url
    for _ in range(max_hops):
        resp = fetch(url, timeout=hop_timeout)
        hop_url = getattr(resp, "url", url) or url
        hops.append({"url": hop_url, "status": resp.status_code})
        location = resp.headers.get("Location", "") or ""
        location = urljoin(hop_url, location)   # Location 可能是相对路径
        if resp.status_code in (301, 302):
            if not location:
                break
            if stop_on_302 and resp.status_code == 302:
                return {... "final_url": location, "hop_chain": hops ...}
            url = location
            continue
        # 200 或其它：就地收口
        return {... "final_url": hop_url, "hop_chain": hops ...}
    return {... "verdict": "fail", "error": "重定向超过 4 跳或链中断" ...}
```

`stop_on_302` 的两种用法：

- `redirect_entry`：`True`，302 的 `Location` 就是当前漫画站域名；
- `publish_entry`：`False`，301/302 都继续跟，直到 200 收口（发布页入口 `jmcomicgo.org` 当前是 301 → `jmcomictt.site` → 200）。

与 jmcomic 的差异（有意为之）：

- jmcomic 遇到 301/302 之外的状态码直接抛 `NotImplementedError`；插件把它记成 `fail`/`restricted`，不抛异常，保证页面能出结果。
- jmcomic 不保留中间跳转；插件保留 `hop_chain`，放进 `description` 供排查。
- jmcomic 的跳转循环没有上限；插件限 4 跳，防止死循环或恶意重定向。
- `Location` 可能是相对路径，插件用 `urljoin` 补全；jmcomic 直接把它当 URL 用，遇到相对路径会失败。

### 5.3 结果数据模型

每行只存 JSON 基本类型（字符串 / 整数 / 列表 / 字典）：

```python
{
    "domain": "comic18j-moco.work",
    "role": "static_fallback",
    "endpoint": "https://comic18j-moco.work/",
    "verdict": "ok",
    "http_status": 200,
    "latency_ms": 420,
    "final_url": "https://comic18j-moco.work/",
    "hop_chain": [{"url": "...", "status": 301}],
    "error": "",
    "checked_at": "2026-11-12 23:12:00",
}
```

约束：

- 不放 `datetime`、`Path`、`bytes`、`set`、`tuple`、`nan`/`inf`（协议 §6.8）。
- `latency_ms` 用 `int(round(...))`。
- `latency_ms` 对 `redirect_entry` 是**整条链的 wall time**（从第一跳到最后一跳），其它角色是单次请求耗时。
- `checked_at` 是内部字段，**不直接塞进行里**：`list` 模板的 `time` 字段会渲染成"下载 <时间>"（协议 §6.3），语义不对。拼行时把时间写进 `description`，例如 `HTTP 200 · 420ms · 23:12:00`。
- `hop_chain` 是 `list[dict]`，键全为字符串。

### 5.4 线程安全

- `load` 在宿主调用线程里完成全部等待，返回前 `_rows` 已是最终值；写 `_rows` 时持 `self._lock`。
- `action_retest` 同样用 `self._lock` 保护 `_rows` 的读改写。
- 探测任务本身不碰 `_rows`，只返回结果字典，由主线程汇总。

### 6.4 动作：retest

payload（协议 §6.3）：

```json
{
  "row": {
    "title": "comic18j-moco.work",
    "author": "静态兜底",
    "result": "可用",
    "domain": "comic18j-moco.work",
    "role": "static_fallback",
    "endpoint": "https://comic18j-moco.work/",
    "verdict": "ok",
    "http_status": 200,
    "latency_ms": 420,
    "final_url": "https://comic18j-moco.work/",
    "hop_chain": [],
    "error": ""
  },
  "row_index": 1,
  "page": 1
}
```

处理：

1. 取 `row.domain`、`row.role`、`row.endpoint`；
2. 以 `(row.domain, row.role)` 为主键在 `_rows` 里查找；`row_index` 只作提示，先校验 `0 <= row_index < len(_rows)`，越界或缺失时回退按 domain 查找；仍找不到就追加到末尾（不抛错，避免一次过期点击让整页报错）；
3. 只重测这一项（`redirect_entry` 走 `redirect_probe`，其余走 `probe_domain`）；`endpoint` 缺失时按 `role` 重新构造：入口用 `JM_REDIRECT_URL`，其余用 `https://{domain}/`；
4. 更新 `_rows` 中对应项；
5. 返回：

```python
{"ok": True, "data": self._page_payload(), "message": f"已重测 {domain}"}
```

用 `data` 而不是 `refresh`：`refresh` 会再调一次 `load`，等于全量重测；`data` 直接替换当前页数据，只换一行。

### 6.5 没有"全部重测"按钮

`list` 模板没有页面级按钮（协议 §6.3 字段表里只有 `row_actions`）。全量重测靠两种方式：

- 重新进入页面（触发一次 `load`）；
- 以后若宿主给 `list` 加页面级按钮，再补一个 `retest_all` 动作。

本方案不为了一个按钮改用 `action` 模板——`action` 的 `items` 是文件列表，展示不了"HTTP 状态 / 耗时"这类明细。

## 七、错误处理与脱敏

### 7.1 单域失败不外抛

`probe.py` 里所有异常都收口成该行的 `verdict` + `error`。除下一节的两种导入/参数错误外，`load` 永远返回正常的 list JSON。原因：连通性测试的"失败"本身就是要展示的结果，把它变成整页错误反而看不到其它域。

每个探测任务在汇总时单独 `try/except`：`future.result()` 抛出的异常转成该行的 `verdict=fail`、`error="类型: 消息"`，不影响其它行。

### 7.2 插件级异常

只保留两种会抛出的情况：

| 情况 | 抛什么 | 界面 |
| --- | --- | --- |
| `retest` 的 payload 里没有 `row.domain` | `InvalidArgumentError("重测参数缺少 domain")` | `INVALID_ARGUMENT` |
| `curl_cffi` 未安装（导入失败） | `RuntimeError("缺少 curl_cffi，无法执行连通性测试")` | `UNKNOWN_ERROR` |

两条实现约束：

- `curl_cffi` 必须**惰性 import**（在 `load`/`retest` 首次用到时 import，不要放模块顶层）。放顶层的话，缺库会让插件在管理页直接"加载失败"，页面根本进不去，就不是表格里这个错误码了。项目 `jm_source.py:427` 也是函数内 import。
- 用 `RuntimeError` 而不是"功能不可用"错误码，是因为 `errors.py` 只有 `ERROR_NOT_AVAILABLE` 常量、没有对应的 `AppError` 子类；想显示 `NOT_AVAILABLE` 得新建异常类，超出本插件范围。`RuntimeError` 归 `UNKNOWN_ERROR` 是当前唯一可行解。

其余情况（域名列表为空、全部探测失败）都返回 `rows` + `empty_text`，不抛异常。

### 7.3 日志与脱敏

- `ctx.log` 只写"开始测试 / 完成 X 项 / 可用 Y 项"这类汇总，不逐域打印。
- 错误文本里不拼 headers、cookies、代理地址；`curl_cffi` 的异常消息先截断到 200 字符再放 `ctx.log`。插件本身只发无凭据的 GET，没有账号/Cookie 可泄漏；不依赖宿主内部的 `sanitize_text`，避免插件与宿主私有函数耦合。
- 行数据里的 `error` 字段只保留异常类型 + 简短消息，例如 `TimeoutError: Request timed out`。

| 301 → 302（永久网域） | 第一跳 301 `Location`，第二跳 302 `Location` | `stop_on_302=True`；`verdict=ok`，`hop_chain` 两跳，`final_url` 正确 |
| 301 → 200（发布页） | 第一跳 301 `Location`，第二跳 200 | `stop_on_302=False`；`verdict=ok`，`hop_chain` 两跳，`final_url` 是 200 的地址 |
| 302 且 `stop_on_302=False` | 302 `Location` | 继续跟随，不在这里收口 |
| 302 直接返回（永久网域） | 单跳 302 | `verdict=ok`，一跳 |
| 400 | 400 | `verdict=restricted`，`error` 非空 |
| 超时 | 抛 `TimeoutError` | `verdict=fail`，`http_status=0` |
| 200 + `Restricted Access!` | 200 文本 | `verdict=restricted` |
| 重定向超过 4 跳 | 连续 301 | `verdict=fail`，`error` 含"超过 4 跳" |
| 相对 `Location` | 302，`Location="/next"` | `final_url` 被 `urljoin` 补成绝对地址 |
| 空候选（注入空组装函数） | — | `rows=[]`，`empty_text` 生效 |
| 代理配置：jmcomic 不可用 | 让 `import jmcomic` 抛 `ImportError` | `proxies_from_jmcomic()` 返回 `None` |
| 代理配置：空 dict | `DEFAULT_PROXIES = {}` | 返回 `None`（直连） |
| 代理配置：dict | `{"http": "127.0.0.1:7890", "https": "..."}` | 原样返回 |
| 代理配置：字符串 | `"127.0.0.1:7890"` | 转成 `{"http": ..., "https": ...}` |

单测落点：**`Python/tests/test_connectivity_plugin.py`**，与现有插件测试（`test_advanced_search_plugin.py` 等）同一目录，用 `run_python_tests.bat` 跑。

设计评审时发现并已修正的问题：

1. **`columns` 一开始列了 5 个键**（domain/role/verdict/http_status/latency_ms）。协议规定"其它列 key 最多补 3 个标签"，且 `domain` 与主标题重复。已改为只放 `http_status`、`latency_ms`。
2. **403 一开始算"不可用"**。与项目搜索通道"非 200 即失败"一致，但连通性测试的语义要区分"网络通但被拒"。已单列 `restricted`。
3. **一开始用 `with ThreadPoolExecutor(...)`**。`with` 退出会 `wait=True`，预算到点后仍要等最慢任务，与"到点立即返回"冲突。已改为手动 `shutdown(wait=False, cancel_futures=True)`。
4. **未处理 `get_html_domain()` 的缓存副作用**。直接调用会写 `DOMAIN_HTML`，违反只读。已改为复刻规则、不调用原函数。
5. **没有内容特征校验**，Cloudflare 挑战页返回 200 会被误判可用。已补判定表（§4.2）。
6. **实测推翻了"候选够用"的假设**。`jm365.work` 与 3 个静态候选全部 DNS 失败，方案因此新增了发布页入口（§12 表第 1 行）这个必须拍板的问题。
7. **`retest` 原方案按 `row_index` 定位**，loader 默认 `--index -1` 会定位失败。已改为以 `row.domain` 为主键。
8. **`DOMAIN_HTML_LIST` 的类型没考虑**（可能是 `set` / `str` / `None`）。已在 §2.6 补规范化规则。
