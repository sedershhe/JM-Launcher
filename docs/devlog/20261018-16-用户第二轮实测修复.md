## 1. 正常权限仍不能下载 / 插件配置写盘失败 → 数据目录三级降级

**现象**：普通权限启动时下载报 `[WinError 5]`；插件设置写盘报 `config.json.tmp: Permission denied`。
**排查**：ACL 正常（普通权限 shell 能写 `%APPDATA%\JML\plugins\zip_browser`），说明是**进程侧被拦**（令牌/安全软件过滤），不再追根因，改为不依赖 AppData。

**实现**（按用户要求顺序）：

```
1. %APPDATA%\JML（配置） + %LOCALAPPDATA%\JML（数据/日志/缓存/临时）
2. Path.GetTempPath()\JML
3. <程序目录>\runtime_data
```

- 判定用**实测写探针**（建目录 → 写唯一临时文件 → 删除），不看 `Directory.Exists`；
- `AppPaths.RootKind` / `LastFailures` 暴露选择结果；程序目录写 `runtime-data-root.txt`（根/kind/时间/失败原因，无凭据，已 gitignore）；
- C# 在 Python 初始化后调用 `set_data_root(配置根, 插件数据根, 日志目录)`，Python 的 `host/paths.py` 统一供 `config.py` / `loader.py` / `plugin_state.py` 使用；
- 设置页新增「数据目录」卡片显示实际根，降级时提示"临时目录可能被清理"；
- 插件设置写盘失败文案改为可行动：`配置写入失败：数据目录不可写（当前数据目录：<path>）`。

> 这一条同时修掉了用户报的"两个浏览插件的文件夹保存不住"（写盘失败导致 `last_folder` 从未落盘）。

## 2. 「用浏览器阅读」不唤起浏览器

**真因**：`PluginPageHost.ApplyActionResultAsync` 在 `result.Refresh == true` 时直接重载并 `return`，**从未读取 `data.url`**；而 zip_web 的 start 恰好返回 `refresh=true + data.url`。

**修法**：动作成功后在重载/应用之后 `TryAutoOpenActionUrl`，只接受 http/https；`_autoOpenedUrl` 保证同 URL 不重复打开、失败可重试、停止服务后重新启动会再次打开；保留「在浏览器中打开」按钮；打开失败显示 `[OPEN_FAILED] 打开浏览器失败：<url>（异常类型）`。
