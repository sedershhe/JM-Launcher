## 一、为什么"差得远"（诊断结论）

`PlainToolkit.UI` 自述是从 **PCL2-CE 社区分支**抽取的纯 XAML 样式库（"Zero custom controls"），给的是"描边按钮 + 圆点单选 + 带边框卡片"；PCL2 主线是 VB 自定义控件"胶囊导航 + 白填充紧阴影卡片 + 52 高胶囊主按钮"。再叠加 JML 原先强制深色（PCL2 只有浅色），差距被放大成**两套设计语言 + 明暗反向**。

## 二、本轮完成的外壳改造

| 项 | 实现 |
|---|---|
| 窗口 | `WindowStyle=None` + `AllowsTransparency=True` + `Background={x:Null}`；`ResizeMode` 自管；900×550（最小 810×470）；不提供最大化（PCL2 同） |
| 透明外边 | 外 10 + 内 8 = 18px；窗体圆角 6 |

| 缩放 | 自绘 8 个命中矩形 + 鼠标捕获，`GetCursorPos → CompositionTarget.TransformFromDevice` 换算 DIP；150% DPI 下四边/四角实测生效 |
| 标题栏 | 高 48、纯色 `ColorBrush4 #4890F5`；三段式 `1*/Auto/1*` |

## 三、顺手修掉的两个隐蔽缺陷

1. **主题切换静默失效**：`PlainToolkit.UI` 的 `ThemeHelper.Initialize` 在 BAML 载入时读到的是相对 Source 字符串 `"Colors.xaml"`，识别不到调色板，`SetTheme` 不生效（实测停在 `ColorsDark`）。改用库自带的显式重载 `Initialize(generic, light, dark)`，并加 `ThemeHelper_SwitchesToPclLightPalette` 防回归。
2. **150% DPI 下的缩放换算**：缩放命中区用物理像素直接算会偏移，改为 `TransformFromDevice` 换算到 DIP 后实测四边正确。
