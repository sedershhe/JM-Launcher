# 20261018-14 阶段 4-5：插件管理真源迁移（C# → Python）

## 一、背景

计划书 8.2 / 10.4 要求：停用某插件时，依赖它的插件必须**明确提示**，
而不是等到 setup 才崩。阶段 1 在 `Pages/PluginListView` 里临时用
`AppSettings.DisabledPlugins` 做启用/停用判断，但 loader 没有 disabled
参数，禁用并没有真正阻止加载。本阶段把"启用/停用/依赖提示"的所有权
整体迁到 Python 宿主。

## 二、真源与迁移

- 唯一真源：`%APPDATA%/JML/plugins/disabled.json`（被停用插件 id 的
  JSON 数组，排序去重，原子写：临时文件 → flush + fsync → `os.replace`）。
- 新增 `Python/jml/host/plugin_state.py`：禁用列表读写、禁用列表参数解析、
  多级 dependents 计算、扫描状态/管理状态推导、bootstrap 状态重算。
- 旧 `AppSettings.DisabledPlugins` 降级为**仅首启迁移读取**：
  `RuntimeBootstrap.Start` 在 Python 初始化后调用
  `PluginManageBridge.MigrateLegacyDisabledPluginsAtStartup()`（旧值为空时
  零开销、不扫描目录）；有旧值时借一次 `list_plugins`（只扫描不 import）
  拿到合法 id，再逐项 `set_plugin_enabled` 落盘并清空旧字段。
  若启动期没能完成（如插件目录暂缺），首次进入插件管理时仍会把旧值作为
  本次 `bootstrap` 的显式 `disabled_json`（保证停用立刻影响这次装配）后重试；
  Python 调用失败则保留旧值、下次启动重试。

## 三、禁用真正生效

- `loader.load_all(plugins_dir, disabled_ids=None)`：被停用插件不 import、
  不 setup，进入 `failed`（`enabled=false`，原因"插件已停用"）。
- 依赖被停用插件的插件不加载，原因明确为
  `缺少依赖插件 xxx（该插件已停用）`；多级依赖（A←B←C）同样级联拒绝。
- `bootstrap` / `list_plugins` 的 loaded/failed 元素都带
  `enabled` 与 `blocked_reason`；`get_plugin_management_state` 额外给
  `status` / `reason` / `dependents`。
- 决策 #7（重启生效）：`set_plugin_enabled` 只改持久化状态与后续
  bootstrap/scan 结果，不热加载/不卸载已在进程内的插件。bootstrap 缓存
  命中时若 disabled 集合变化，只用上一次真实装配结果重算状态，绝不重复
  import/setup。

## 四、界面

- `PluginListView` 改为经 `IPluginManageGateway` 调用 Python：
  `Bootstrap` / `ListPlugins` → `get_plugin_management_state` → 渲染状态列
  （`已加载` / `已停用` / `加载失败（原因）`）。
- 选中行后才允许启用/停用；停用前若 `dependents` 非空，弹确认框列出会被
  影响的插件（确认器可注入，便于离线测试）；`set_plugin_enabled` 失败在
  状态栏显示 `[错误码] 原因`。
- 删除 C# 侧"从 AppSettings 读禁用列表再判断"的渲染逻辑。

## 六、遗留说明

- `Pages/PluginFeaturesView` 仍读取一次 `AppSettings.DisabledPlugins` 做
  过滤；该文件不在本阶段允许修改范围内。迁移后旧字段恒为空，且 Python
  bootstrap 已把停用插件移出 loaded，因此该过滤是**无副作用的历史代码**，
  不构成第二真源。
