# 20261029-01 插件协议规范与开发套件

## 起因

项目已有四个插件（`download_history`、`favorites`、`zip_browser`、`zip_web`），要继续加新插件。先要回答一个问题：本项目有没有插件协议规范？没有就按源码写一份，并在 `AGENTS.md` 里声明地址。

## 检查结论：原本没有

- 全项目 `.md` 里搜"插件协议 / 插件规范 / plugin protocol / 插件开发 / 页面模板 / manifest"，零命中。
- `docs/` 下只有功能计划书、技术实现方案、桥接契约、动效与视觉规格、发布说明、devlog。`README.md` 有"内置插件"一节，但只是介绍，不是契约。
- 协议事实全部散在源码里：`Python/jml/host/manifest.py`（清单校验）、`config.py`（配置 schema）、`loader.py`（装配）、`pages.py`（页面钩子）、`plugin_context.py`（ctx 接口）、`Python/jml/services/host_services.py`（宿主服务）、`Python/jml/core/protocol.py` 与 `events.py`（事件）、`Bridge/Dto/PluginPageDtos.cs`（四个页面模板的 payload 字段）。

### 2. 独立套件 `plugin_sdk/`

```
plugin_sdk/
├── README.md                        套件说明、三步上手、改协议同步表
├── 20261029_JML插件协议规范_v1.0.md  协议全文
├── loader.py                        独立加载器（check / run / page / action）
└── template/                        空白模板
    ├── README.md                    复制后改哪几处、五个新手坑
    ├── plugin.json                  清单（JSON 不支持注释，字段说明见 template/README.md）
    ├── main.py                      骨架：load / action_hello / setup
    └── config.schema.json           三个示例配置项
```

`loader.py` 不启动 WPF，直接调宿主的 Python 侧装配逻辑，所以行为和主程序一致：

- 数据目录默认落系统临时目录（`%TEMP%/jml_plugin_sdk`），不污染 `%APPDATA%/JML`
- 自动注册宿主服务（`jm.search` / `jm.detail` / `jm.download` / `jm.account` / `jm.session`），依赖它们的插件也能正常装配
- 错误统一打印成 `[失败] [错误码] 消息` 并返回退出码 1

## 验证

`loader.py` 实测：

| 命令 | 结果 |
| --- | --- |
| `check plugin_sdk/template` | 通过，退出码 0 |
| `run plugin_sdk/template` | `my_plugin` 装配成功 |
| `page plugin_sdk/template my_plugin.main --page 1` | 信封正常，`list` 模板两行数据 |
| `action ... hello --row title=第一条 --index 0` | payload 为 `{"row":...,"row_index":0,"page":1}`，返回 `{"ok":true,...,"message":"已处理：第一条"}` |
| `run plugins` | 四个真实插件全部装配，服务表 `archive_reader/1` + 五个 `jm.*/1` |
| `page plugins x.y` | 友好提示"要指到具体插件目录"，退出码 1 |

`pytest Python/tests`：**633 通过，1 失败**。失败项是 `test_layering.py::test_core_downloader_import_does_not_pull_host_modules`，原因是当前沙箱禁止子进程创建管道（`PermissionError: [WinError 5]`），与本次改动无关。
