## 起因

P4 的插件本体通过 loader 单点验收后，要按方案 §14 用真实网络跑 8 条手工用例，确认双通道、排除语法、五类范围、分类/子分类、时间筛选在真实站点上成立。

## 用例脚本

`Draw/20261108_搜索P5用例_v1.0.py`：用 `subprocess` 调 `loader.py page` 驱动插件，逐条判定并打印 PASS/FAIL，明细落系统临时目录 `_p5_cases_result.json`。

两个坑：

1. loader 把插件装配日志（`[plugin:...]`）和域名探测日志打进 stdout，整段 `json.loads` 会失败。脚本改为从第一个行首 `{` 开始截取、末尾 `}` 兜底。
2. 子进程默认按 GBK 输出中文，父进程按 UTF-8 解码会乱码且影响报错可读性。给子进程加 `PYTHONIOENCODING=utf-8`、`PYTHONUTF8=1`。

## 两处判据修正（原判据不成立，不是实现 bug）

1. **用例 7 原写「同人 + 汉化」**：实测 `doujin+chinese` 与 `doujin` 结果完全相同。延伸验证（`Draw/20261108_搜索子分类对比_v1.0.py`，JmPageTool 精确解析）：

   | 路径 | 条目 | 前 3 |
   | --- | --- | --- |
   | `/search/photos/doujin` | 80 | 1489271 / 1489264 / 1489265 |
   | `/search/photos/doujin/sub/chinese` | 80 | 同上 |
   | `/search/photos/doujin/sub/CG` | 80 | 1489158 / 1489142 / 1488686 |
   | `/search/photos/single` | 80 | 1445774 / 1044155 / 1485862 |
   | `/search/photos/single/sub/youth` | 6 | 1445774 / 1044155 / 1209822 |
   | `/search/photos/another/sub/cosplay` | 6 | 1212333 / 1212240 / 1208754 |

   同人分类下作品几乎全部是汉化，所以「汉化」子分类等于全集——站点行为正常。子分类本身有效（CG / youth / cosplay 都明显收敛）。用例 7 改用 CG 判定。
2. **用例 8 原写「本页条数 < 80」**：本周「全彩」有 83 条（> 一页 80），本页自然满 80。时间筛选其实生效（total 从 10000 封顶降到 83）。判据改为「channel=html 且 total < 500」。
