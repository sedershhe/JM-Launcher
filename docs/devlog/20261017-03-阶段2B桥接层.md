## 二、关键设计（后续阶段必须遵守）

| 点 | 设计 |
|---|---|
| 事件回调 | C# 委托签名 **`void(string eventJson)` 单参数**；回调体只做「已启动判断 → 入队 → 请求 UI 排空」 |
| 队列 | `ConcurrentQueue`，容量 10000，超限丢弃并计数（`DroppedCount`） |
| UI 编组 | 可注入 `Action<Action> uiDispatcher`：生产 `Dispatcher.BeginInvoke`，xUnit 注入同步实现（**不启动 WPF Application**） |
| 委托存活 | `_sinkDelegate` 字段强引用 + Python 侧 `_STATE["event_callback"]` 二次强引用（防 pythonnet 委托被 GC） |
| 日志分窗 | 按 `payload.batch_id` → `BatchId`/`IsGlobal`，主下载页与详情窗各收各的（旧缺陷 #6） |
| 参数传递 | 桥接层只用 JSON 字符串传参；**不得**把 `Dictionary<string,string>` 直接丢给 Python（见下节） |
| GIL | 生产代码只有 `PythonRuntime.Invoke` 内含 `Py.GIL()`；全仓无 `.Result`/`.Wait()` 阻塞 UI |

## 三、复核发现并修掉的严重缺陷（本阶段最大收获）

**现象**：`DownloadBridge.GetProgress` 对**任何** `batch_id` 都返回 `BATCH_NOT_FOUND`。

**根因链**：
1. 桥接层把 `Dictionary<string,string>{"batch_id": id}` 传给 Python；
2. pythonnet 3.2.1 不把它转成 Python `dict`，而是 **CLR 代理对象**（`GetPythonType()` = `System.Collections.Generic.Dictionary[String,String]`）；
3. Python 侧 `params = payload if isinstance(payload, dict) else {}` → 得到 `{}` → `batch_id=""`；
4. `get_batch_status("")` 抛 `BatchNotFound`，错误文案变成 `找不到下载批次: `（id 丢失）。

**为什么门禁没抓到**：原集成测试只断言 `ErrorCode == "BATCH_NOT_FOUND"`。空 id 与真实未知 id 走同一条分支，**测试假通过**。

**修法**（已落地）：
- Python 补顶层 `get_progress(batch_id)`，失败用 `error_payload` 收口；
- C# 改走 `backend.get_progress(batchId)`，删除 `CallHostServiceJson`（同时消除对 `HOST_SERVICES` 模块全局与后端私有 `_dumps` 的越层访问）；
- 两侧各补一条**能证明参数真到达**的断言：`ErrorMessage` 必须包含传入的 id；正向链路断言 `BatchId` 回显一致。

> 教训：失败路径的断言只锁错误码是不够的——错误码相同不代表参数到位。凡"带参数进、带参数出"的接口，断言里必须出现那个参数值。

## 五、可接受但需记录的取舍

| 项 | 说明 |
|---|---|
| `RuntimeBootstrap.Start` 在 UI 线程初始化 Python | 实测 `import jml_backend` 约 52ms，暂不挪后台；若后续启动变慢再改异步 + UI 编组 |
| `JML.Tests.csproj` 的 `_MSTestEnableParentProcessQuery=false` | 受限令牌环境（子代理沙箱）下 testhost 无法查询父进程会直接中止；该开关只影响测试宿主，不影响产品。副作用：runner 被杀时可能留孤儿 testhost |
| `Dispatcher` 已关闭时 `BeginInvoke` 只返回 aborted 不抛异常 | `_drainScheduled` 可能停在 1，仅影响退出期，队列有界 |
| `PluginBridge.Bootstrap/ListPlugins` 为同步方法 | 契约允许；调用方（插件页）自行 `Task.Run` |
| xUnit 真批次用例会在输出目录留空 `bridge-progress-*` 目录 | 位于 gitignore 的 bin 下，不影响仓库与产品 |
| `StartDownload` 用例的 1 秒断言 | 冷机可能偶发，本机全量 39 例 559ms；若后续 flaky 改 3 秒 |
