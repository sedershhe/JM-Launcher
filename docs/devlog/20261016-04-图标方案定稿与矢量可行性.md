## 二、一个重要事实修正

原计划"采用 PCL2 图标背景、把文字改成 JML"。

实测发现：**PCL2 标题栏 Logo 不是图片，而是矢量 Path**
（`FormMain.xaml:117` 的 `ShapeTitleLogo`，`Data="M26,29 v-25 h6 a7,7 180 0 1 0,14 ..."`
为描边路径，画出 "PCL" 三字母）。它是路径数据，**无法直接改文字**。

但 PCL2 本身内置文字 Logo 模式（`FormMain.xaml.vb:725` 的 `UiLogoType`，共 4 种）：

| 值 | 模式 | 控件 |

| **2** | **文本** | `LabTitleLogo`，文字取自 `Settings("UiLogoText")`（第 771 行赋值） |
| 3 | 图片 | `ImageTitleLogo`，读 `PCL\Logo.png` |

## 四、矢量图标可行性（用户提问）

### 结论
**界面内可以用矢量；`.ico` 文件本身不行，必须导出位图。**

### 实测证据
对 `icon.ico` 做字节级解析（小端序），13 帧全部为位图：

```
reserved=0 type=1 count=13
  帧0:  48x48   BMP/DIB 位图      帧7:  48x48   BMP/DIB 位图
  帧1:  32x32   BMP/DIB 位图      帧8:  40x40   BMP/DIB 位图
  帧2:  16x16   BMP/DIB 位图      帧9:  32x32   BMP/DIB 位图
  帧3:  256x256 PNG  位图         帧10: 24x24   BMP/DIB 位图
  帧4:  128x128 BMP/DIB 位图      帧11: 20x20   BMP/DIB 位图
  帧5:  96x96   BMP/DIB 位图      帧12: 16x16   BMP/DIB 位图
  帧6:  64x64   BMP/DIB 位图
```

依据微软官方（Raymond Chen, "The format of icon resources, revisited"，
devblogs.microsoft.com/oldnewthing/20231025-00）：icon 资源的图像数据只能是
`BITMAPCOREHEADER` / `BITMAPINFOHEADER` 位图，或内嵌 PNG——**均为位图，不支持 SVG**。

> 注：初次解析脚本有字节序 bug 导致输出大量垃圾帧，已用小端序重写并复核。

### 做法（已写入计划书第六节）

| 用途 | 是否可用矢量 | 做法 |
| --- | --- | --- |
| 窗口标题栏、界面内图标 | ✅ 可以 | 直接用 WPF `Path` / `DrawingImage`，任意缩放不失真 |
| 任务栏 / exe / 资源管理器图标 | ❌ 不行 | 必须 `.ico`；由矢量源导出多尺寸位图后打包 |

推荐工作流（矢量源单一真源 + 按需导出）：

```
矢量源（XAML Path 或 SVG）
   ├─→ 界面内：直接引用矢量
   └─→ .ico  ：导出 16/20/24/32/40/48/64/96/128/256 各一张，打包为多帧 .ico
```

**必须含多尺寸帧**：Windows 在任务栏、资源管理器、大图标视图、
高 DPI（150%/200%）下各取不同帧；单帧 ico 在其它场景会被拉伸模糊。
沿用 PCL2 `icon.ico` 可行的重要原因正是它已含 13 帧（16~256）。
