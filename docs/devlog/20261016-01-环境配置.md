# 20261016-01 · 项目环境初始化

## 背景

JML 是基于 C#/.NET + Python 混合栈，对旧项目（jm4.0 插件化版）的全新 UI 重写。
技术选型：C#/WPF 负责界面（PCL2 风格，使用 `PlainToolkit.UI`），Python 保留原有业务逻辑，
二者通过 **pythonnet** 桥接。C# 层不做任何功能业务逻辑。

本日志记录"从空项目到可开发状态"的环境配置过程。所有结论均来自本机实测，未依据猜测。

## 二、关键技术决策与实测结论

### 决策 1：UI 库框架版本冲突 —— 实测通过，不改外部仓库

- 冲突事实：`JML` 为 `net10.0-windows`，`PlainToolkit.UI` 为 `net8.0-windows`。
- 实测：net10.0-windows 项目直接 `ProjectReference` 引用 net8.0-windows 库，
  **构建成功，0 警告 0 错误**。
- 结论：不需要修改外部 UI 仓库，也不需要把 JML 降级到 net8。

### 决策 2：pythonnet 版本

- NuGet 最新稳定版 `pythonnet 3.2.1`（2026-10-08 发布，经 NuGet 官方页确认）。
- PyPI 元数据确认其支持 Python **3.11 / 3.12 / 3.13 / 3.14 / 3.15**，本机 3.13.7 在支持范围内。

### 决策 3：jmcomic 版本锁定

- 本机系统 Python 已装 **2.7.1**；旧项目用 2.7.2；PyPI 最新为 2.7.9。
- 处理：`requirements.txt` 固定为**当前已实测可用的 2.7.1**，避免凭记忆写版本号。
- 升级版本属于行为变更，需单独评估。

### 决策 4：Python 运行时不硬编码路径

- 旧项目的已知缺陷之一就是把路径硬编码进代码，导致搬家即挂，本项目不得重演。
- 处理：`PythonRuntime.LocatePythonDll()` 按优先级探测——
  环境变量 `JML_PYTHON_HOME` → PATH 中的 python → 常见安装位置 → 注册表，
  找不到时给出明确异常提示而非静默失败。
