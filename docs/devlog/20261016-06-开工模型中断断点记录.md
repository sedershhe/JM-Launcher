## 三、⚠️ 阻断项：C# 当前编译失败（必须优先修复）

```
JML\Navigation\NavigationStack.cs(70,72): error CS0037:
无法将 null 转换为“(string PageId, string Title)”，因为后者是不可为 null 的值类型
生成失败。0 个警告，1 个错误。
```

**位置**：`Navigation/NavigationStack.cs:70`

```csharp
popped = _innerStack.Count > 0 && _innerStack.Pop() is not null;   // ← 第 70 行
```

**原因**：`_innerStack` 的元素是值元组 `(string, string)`（值类型，不可为 null），
不能与 `null` 做模式匹配。

**修复建议**（二选一，待确认后执行）：

```csharp
// 方案 1（最小改动，推荐）：
popped = _innerStack.Count > 0;
if (popped) { _innerStack.Pop(); }

// 方案 2：改成先判断再弹
bool has;
lock (_gate) { has = _innerStack.Count > 0; if (has) _innerStack.Pop(); }
popped = has;
```

> 注意：`Pop()` 本身会移除栈顶，当前写法里 `_innerStack.Pop() is not null`
> 的语义本意是"弹成功了"，应直接以 `Count > 0` 判定。

**此错误不修复，项目无法构建，阶段 1 无法继续。**

## 五、一个接口约定需明确（非 bug，但易踩）

`emit_test_event(event_type, payload)` 要求 **payload 自带 `type` 字段且值等于 `event_type`**
（`events.py:109~114` 的"禁止裸 dict"校验）。

也就是说**正确调用方式**是：

```python
b.emit_test_event("download.log", {
    "type": "download.log",      # ← 必带，且必须与第一个参数一致
    "level": "INFO",
    "message": "m1",
})
```

而不是只传业务字段。第一次测试时我漏了 `type`，两次调用都报同一个错，
一度误判为 bug——**实际是接口约定**。
后续 C# 侧 `EventRelay` 封装时，建议由桥接层统一补 `type` 字段，避免每个调用点重复。
