## 筛选（5 个，协议 §6.9 上限就是 5）

| key | label | 选项 |
| --- | --- | --- |
| main_tag | 作品范围 | 0 站内 / 1 作品 / 2 作者 / 3 标签 / 4 登场角色 |
| order_by | 排序 | mr 最新 / mv 最多浏览 / mp 最多图 / tf 最多点赞 |
| time | 时间 | a 全部 / t 今日 / w 本周 / m 本月 |
| category | 分类 | 0 / doujin / single / short / another / hanman / meiman / doujin_cosplay / 3D / english_site |
| sub_category | 子分类 | "" -- / chinese / japanese / CG / other / cosplay / 3d / youth |

capabilities 只 gate `time` / `category` / `sub_category`；为 false 时 `enabled=false` + `hint="接口通道不支持此筛选"`。`main_tag` / `order_by` 双通道固定可用。

## 行为

- 参数回落：main_tag 0、order_by mr、time a、category 0、page ≥1、sub_category 空；非法值不抛异常。
- 无关键词：不调服务，返回空 rows、`total_pages:0`、`channel:""`、`empty_text="输入关键词后点「搜索」"`。
- 有结果：`rows` 映射 `book_id / thumb_book_id / title / author / page_count / tags`（tags 为字符串数组）。
- 动作：`open_detail` → `{"kind":"detail","book_id":...}`；`download` → `{"kind":"download","book_ids":[...]}`；未知 id → `{"ok":false,"refresh":false,"message":"未知操作"}`。intent 字段名按协议 §6.5 用 `kind`（方案骨架里的 `type` 是旧写法）。

## 验收（主代理独立复跑）

```
loader.py check plugins/advanced_search   → [通过] advanced_search v1.0.0；需要服务 jm.search/1；页面 advanced_search.main [search]
loader.py run plugins                     → 成功 5 个；服务表含 jm.search/1
loader.py page plugins/advanced_search advanced_search.main
                                          → ok:true / template:search / 5 filters 全 enabled / rows=[] / empty_text=输入关键词后点「搜索」
loader.py action plugins/advanced_search advanced_search.main open_detail --payload {"book_id":"1482019"}
                                          → intent {kind:"detail", book_id:"1482019"}
pytest Python/tests -q -p no:cacheprovider → 660 passed
```

注意：`loader.py page` 的第一个位置参数是**插件目录**，参数用 `--param KEY=VALUE`（可重复），不是 `--params`。方案 §14 里写的 `page advanced_search advanced_search.main --params ...` 是错的，实际命令是 `page plugins/advanced_search advanced_search.main --param keyword=...`。

## 与方案不一致（已确认可接受）

1. filters 按 5 个实现：协议 §6.9 硬上限 5，方案 §8.2 也只列 5 个。任务书里「6 个」是我写错。
2. 方案 §8.1 写 `services` 全空，实际声明了 `requires: jm.search/1`（协议 §7 要求用服务就声明），`loader run` 验证可装配。
3. `sub_category` 未按 category 联动（方案 §8.3）：与「改下拉只暂存、提交才重载」的协议语义冲突——联动只能靠重载，而重载会打断用户输入。保持全量 8 项，列入可选后续。
4. 方案骨架的 `intent.type` 改为协议要求的 `kind`；动作 id 用 `open_detail`（方案写 `detail`）。
5. 未加 `config.schema.json`（本插件无配置）。
