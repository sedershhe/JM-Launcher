# 20261108-06 强化搜索插件 P6：子分类联动与 PCL2 挥镐加载动画

## 起因

P5 的 8 条用例全通过后，用户手工验收前提出两处补强：

1. 子分类下拉总是给全部 8 项，和当前分类不匹配（例如「全部」分类下还能选「汉化」）。
2. 加载时只有一行「正在加载页面…」文字，想要 PCL2 的挥镐动画。

设计经用户确认：联动只改插件、C# 不动；挥镐动画放全部插件页（list / search / browser / action 四种模板通用）。

## 一、子分类联动（只改插件）

### 规则

依据 jmcomic 常量与 2026-11-08 站点实测（P5 对比脚本）：

| 当前分类 | 允许的子分类 |
| --- | --- |
| doujin 同人 | chinese 汉化 / japanese 日语 / CG |
| single 单本 | youth 青年 |
| another 其他 | other 其他 / cosplay / 3d |
| 其余分类 | 只有空值 `--` |

### 改动

- `plugins/advanced_search/main.py:85-90`：新增 `_SUB_CATEGORY_RULES`。
- `plugins/advanced_search/main.py:208-222`（`_filters_payload`）：仅对 `sub_category` 按 `state["category"]` 过滤选项（保留 `""` 与允许项，顺序、label 不变）；当前值不在允许集合时回落 `""`。

## 二、PCL2 挥镐加载动画（新增宿主控件）

### 控件

- 新建 `Controls/JmlLoadingPickaxe.xaml`（193 行）与 `.xaml.cs`（82 行）。
- 60×47 画布：镐子 Path（几何、Height 35、Margin 10,6、StrokeThickness 2 照抄 PCL2 `MyLoading.xaml`）、左右碎屑（3×5，初始透明）、底部 25×2 进度条；颜色继承 Foreground（默认 `ColorBrush1`）。
- 动画：XAML 关键帧 Storyboard，1.6s 循环——0~250ms 保持 -20° → 600ms 用 BackEase（EaseIn，Amplitude 0.3）转到 50° → 1500ms 用 ElasticEase（EaseOut）转到 25° → 1600ms 瞬时回 -20°；碎屑 600ms 显示、650~750ms 淡出、600~780ms 位移。
- `IsRunning` 依赖属性：true 启播，false 停止并复位。

### 接入

- `Pages/PluginPageHost.xaml:596-605`：放在 Row=1 内容区所有面板之后，居中覆盖、`IsHitTestVisible=False`、初始 `Collapsed`。不放进 Row=0 的状态行，避免 60×47 把状态行撑高、加载时内容下跳。
- `Pages/PluginPageHost.xaml.cs:266-318`：`LoadAsync` 入口显示并启播，外层 `try/finally` 保证成功、失败、异常、早退都会停止并隐藏。

### 主代理修正

子代理按任务书写了右碎屑 Y 位移 +6（向下），与 PCL2 原实现（左右都是 -6、向上飞）不符；已改为 `Controls/JmlLoadingPickaxe.xaml:113` 的 `-6`，并同步注释。

### 测试

`JML.Tests/PluginPageTests.cs`：

- `:2232-2275`：`FakePluginPageGateway` 增加 `LoadGate`，把原队列逻辑抽成 `NextLoad`。
- `:2511-2565`：新增两条——卡住载入时断言挥镐 `Visible` 且 `IsRunning=true`；放行完成后断言 `Collapsed` 且 `IsRunning=false`。

## 未覆盖 / 风险

1. 挥镐动画只在 STA 测试里验证了启停（Visible/IsRunning），**没有在真机窗口里目视确认**旋转、碎屑方向与节奏——留待人工验收。
2. Storyboard 直接以命名 `RotateTransform`/`TranslateTransform` 为目标；`Begin` 在测试中未抛异常，但真机若报名称作用域错误，需改成 `(UIElement.RenderTransform).(RotateTransform.Angle)` 属性路径写法。
3. `LoadAsync` 被快速连点时，先结束的那次可能在 finally 里提前隐藏动画；属既有并发问题，本次未动。
4. 方案 §14 的 8 条验收用例与验收记录未改动，等用户确认后再更新。
