发现的缺陷：

| 编号 | 缺陷 | 根因 | 处理 |
|---|---|---|---|
| UI-1 | 搜索框初始 16×54 px | `PlainCard` 模板的 `ContentPresenter` 用 `TemplateBinding HorizontalContentAlignment`，WPF 默认 `Left`，三页都未设 `Stretch` | **已修**：三页卡片设 `HorizontalContentAlignment/VerticalContentAlignment=Stretch`；STA 实测 `KeywordBox` 11×36 → **918×36** |
| UI-2 | 日志区 175×240 窄条 | 同 UI-1 | **已修**：下载页日志 117×160 → **1014×257.4**；详情窗 130×100 → **1014×119.5** |
| UI-3 | 空结果文字贴左上角 | 同 UI-1 | **已修**：文字中心 (66, 25.9) → **(524, 206.7)** = 卡片中心 |
| DATA-1 | 页数恒 0（搜索 5/5、详情 2/2） | jmcomic 2.7.1 把 `page_count` 硬编码为 `'0'`，真实值只在专辑原始 JSON 的 `total_photos`；搜索列表接口根本不返回页数 | **已修**：详情取 `total_photos`（651712→42、565384→34，与 ZIP 条目数一致）；搜索按需有界补全（并发 3、3 秒封顶、带缓存） |
| SEC-1 | C# 脱敏对 `Bearer` 令牌不完整（`*** abc.def` 残留） | 规则顺序错误：键值规则先吃掉 "Bearer"，令牌无法再识别 | **已修**：按 Python 的三段规则重排（先认证方案、再整行头、最后键值），并加**跨语言一致性测试**（同一输入两侧都不许残留令牌） |

用户决策（2026-10-17）：

1. 页数补全**保持 3 秒封顶**、能填多少算多少（不要求首屏 5/5）；
2. 空输入框**加淡色背景**让输入区域可见（不动外部主题）；
3. 搜索失败**先恢复按钮状态再弹框**；
4. 页数未知时显示 `页数: -`，不把"未知"显示成"0 页"。
