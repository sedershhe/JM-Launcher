## 二、界面与数据的边界（本阶段重点）

| 事项 | 归属 | 实现 |

## 三、关键交互

| 交互 | 链路 |
|---|---|
| 下载页开始 | `ParseBookIds` → `StartDownload(ids, dir, AppPaths.TempDirectory)` → 事件回推日志/进度 |
| 取消 | `await CancelDownload(batchId)`，按钮等 `batch_finished` 恢复；取消与完成的竞态不覆盖完成文案 |
| 完成 | `batch_finished` → 弹框 `完成，成功 {success} / 共 {total}，失败 {failed}`（有取消时追加 `，取消 {n}`） |
| 搜索 | `Search(keyword, 1, "main")`；翻页 `Search(…, page, "main")` |
| 封面 | `FetchCover(bookId)` → `byte[]` → **UI 线程**建 `BitmapImage(CacheOption=OnLoad)`；失败暗红底 X |
| 行内下载 / 详情下载 | `DownloadRequested` → `MainWindow` → 切下载页 + `StartWithIds` + 自动开始 |
| 详情 | `MainWindow` 单实例 `DetailWindow`，`Loaded` 里 `await GetDetail`，独立日志区按 `batch_id` 过滤 |

## 六、真机验收后的修复（2-D 发现 → 已修）

| 编号 | 缺陷 | 修法 | 验证 |
|---|---|---|---|
| UI-1/2/3 | 搜索框 16×54、日志区 175×240 窄条、空结果贴左上角 | 根因是 `PlainCard` 的 `ContentPresenter` 跟随 `HorizontalContentAlignment` 默认 `Left`；三页卡片显式设 `Stretch` | STA 实测 `KeywordBox` 11×36 → **918×36**、日志 117×160 → **1014×257.4**、空结果文字居中于卡片中心 |
| SEC-1 | C# 脱敏对 `Bearer` 令牌不完整 | 按 Python 三段规则重排（先认证方案 → 再整行头 → 最后键值） | 新增**跨语言一致性测试**：同一输入同时跑 C# 与 Python，两侧都不许残留令牌 |
| DATA-1 | 页数恒 0 | 详情取专辑原始 JSON 的 `total_photos`（651712→42、565384→34，与 ZIP 条目数一致）；搜索按需有界补全（并发 3 / 3 秒封顶 / 带缓存） | 真机实测 + 15 条离线用例 |
| 可用性 | 空输入框不可见（主题透明底 + 边框同底色） | 新增 `JmlInputBox` 样式（`BasedOn=PlainTextBox`，背景取主题 `ColorBrushInputHoverBg`），应用到编号框 / 目录框 / 关键词框 | `Background.Color.A > 0` 断言 |
| 交互 | 搜索失败时按钮卡「搜索中…」 | 先恢复按钮与状态栏，再弹框；弹框抽成可注入回调 | 断言"弹框回调执行时按钮已可用"，并做了反向验证 |
| 显示 | `页数: 0` 把"未知"显示成 0 页 | `page_count<=0` 显示 `页数: -`（格式不变） | 纯函数 + 断言 |

> 用户决策（2026-10-17）：页数补全保持 3 秒封顶、能填多少算多少；空输入框加淡色背景；失败先恢复状态再弹框；未知页数显示 `-`。
