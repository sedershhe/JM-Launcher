## 4. 契约速查（写代码照抄，别凭记忆）

### 4.1 search 模板必填字段

- 必填：`search_box`、`rows`
- 强烈建议：`advanced`（`{label, default_expanded, summary}`）、`filters`、`page` / `page_size` / `total` / `total_pages`
- 通道相关：`channel`（`html`/`api`）、`capabilities`（`{time, category, sub_category}` 三布尔）、`hint`
- 结果是**卡片列表**，行字段与 list 完全一致，封面用 `thumb_book_id`（只能是 JM 本子号），另支持 `tags`

### 4.2 加载参数

| 时机 | params |
| --- | --- |
| 首次进入 | `{"page": 1}` |
| 点搜索 / 回车 | `{"page": 1, "keyword": "...", <各筛选 key>: "<值>"}` |
| 翻页 | `{"page": N, "keyword": ..., 各筛选值...}`（C# 缓存「最近一次提交」的那一套） |
| 点重置 | `{"page": 1}`（条件已清空） |

### 4.3 filters 语义（与 list 相反，最容易写错）

- list：改下拉 → 立即 `{"page":1, key:value}` 重载。
- search：改下拉只改**本地暂存**，**不重载**；点搜索/回车时 `keyword` + 全部筛选值**一次性**下发。
- 因此 `load` 必须把 `params` 里的值**回填**进 `search_box.value` 与 `filters[].value`，否则翻页后条件显示会跳回默认。

### 4.4 宿主服务签名（方案 §6.3 有完整实现要求）

```python
ctx.call_service("jm.search", 1, "search_advanced", {
    "keyword": "全彩 -人妻", "main_tag": 0, "order_by": "mr",
    "time": "a", "category": "0", "sub_category": None,
    "page": 1, "channel": "auto",
})
# → {channel, capabilities:{time,category,sub_category}, total, total_pages,
#    results:[{book_id,title,tags,page_count}]}
```

## 7. 陷阱与教训（别人已经踩过）

1. **`read` 大文件会被截断**：约 34KB 以上时返回的 `lines` 可能少于 `totalLines`，用 `read`→改→`write` 重写会**静默丢失文件尾部**（本轮就把协议规范的附录 A/B 弄丢过一次，后从 git 恢复）。→ 改大文件一律用 `edit`；确需重写时先校验 `lines.length === totalLines`。
2. **`ops_bash` 不能写工作区文件**（Permission denied，含重定向）。所有文件写入用 `write` / `edit` 工具；bash 只用来跑只读命令与 Python 探针。
3. **TS 模板字面量里不能出现反引号或反斜杠+u**（`String.raw` 也一样），会报 `Expected a semicolon` / `Expected unicode escape`。用普通字符串拼接或 `"\u0060"`。
4. **filters 是暂存的**：不重载、不分次下发、必须回填（见 4.3）。
5. **`thumb_book_id` 只能放 JM 本子号**，放别的会显示暗红十字。
6. **插件不能 import 宿主私有模块**（协议禁止，见 `plugins/favorites/main.py` 文件头），网络抓取逻辑必须放宿主的 `jm_source`。
7. **中文关键词要 URL 编码**，抓网页时带 `Referer`，否则 403。
8. **`form` 模板宿主不渲染**，别用。
9. 写命令行工具输出时注意代码页：`ops_bash` 的中文 stdout 可能显示成乱码，判断结果看数字与 ASCII 部分。
