# JML 插件协议规范 v1.0

> 适用范围：JML 主程序 `api_version = 1`。
> 本文档是 JML 插件体系的**契约说明**：插件要写成什么样、宿主会校验什么、界面会渲染什么。
> 所有规则都来自当前源码，不是设计设想；文中给出源码位置，出现分歧时以源码为准。

---

## 一、这份文档讲什么

JML 是"C# WPF 前端 + Python 后端"的组合，中间用 pythonnet 桥接。C# 层只有界面与交互，业务逻辑全在 Python。

插件是 **Python 代码 + 一份 JSON 清单**，放在主程序的 `plugins/` 目录里。宿主启动时扫描、校验、按依赖顺序装载；装载完成后，插件的页面数据以 JSON 交给 C# 渲染。

### 插件与宿主之间只有四条通道

| 通道 | 方向 | 说明 |
| --- | --- | --- |
| `plugin.json` | 插件 → 宿主 | 声明身份、入口、服务依赖、页面清单、配置 |
| `setup(ctx)` | 宿主 → 插件 | 唯一入口；插件在此注册页面钩子、注册服务、订阅事件 |
| 页面 JSON | 插件 ↔ 宿主 | 加载页返回数据，动作按钮回传数据，图片走字节通道 |
| 服务 / 事件总线 | 插件 ↔ 宿主 / 插件 ↔ 插件 | 能力复用与状态通知 |

### 阅读顺序建议

1. 先读【二、目录与文件】和【三、plugin.json】，能把插件装起来；
2. 再读【五、main.py 与 setup(ctx)】和【六、页面模板】,能把页面画出来；
3. 需要跨插件能力时读【七、服务协作】，需要通知状态时读【八、事件总线】；
4. 最后照【十、最小模板 + 自检清单】写自己的第一个插件。

### 协议版本

宿主只接受 `api_version` 恰好等于 `1` 的插件，不做降级、不做兼容转换。协议升级时这个数字会变，旧插件会被明确拒绝并说明原因：

```
插件 xxx 的协议版本不兼容: 插件 api_version=2, 宿主支持 api_version=1，拒绝加载
```

定义位置：`Python/jml/core/protocol.py` 的 `API_VERSION = 1`。

## 二、目录与文件

### 2.1 目录结构

```
plugins/
└── my_plugin/            ← 一个插件一个子目录，目录名任意（建议与 id 一致）
    ├── plugin.json       ← 必需：清单
    ├── main.py           ← 必需：入口（plugin.json 的 entry 指向它）
    ├── config.schema.json ← 可选：配置项定义（由 plugin.json 的 config.schema 引用）
    └── 其它 .py / 资源    ← 可选：入口可以 import 同目录的模块
```

- 插件目录必须是 `plugins/` 下的**子目录**；`.` 开头的目录会被跳过（给临时/禁用预留）。
- 目录名**不必**等于 `id`，但强烈建议一致：`id` 决定数据目录、配置文件、模块名，改 `id` 等于换了一个新插件（旧配置与数据不会跟过来）。
- 插件目录会被插入 `sys.path`，所以入口里可以直接 `import 同目录模块`；宿主用模块名 `_jml_plugin_{id}` 装载入口，不同插件的同名模块不会互相覆盖。

### 2.2 三个文件的分工

| 文件 | 必需 | 谁读 | 作用 |
| --- | --- | --- | --- |
| `plugin.json` | 是 | 宿主装载器 | 静态声明：身份、版本、入口、服务、页面、配置引用 |
| `main.py` | 是 | 宿主装载器（动态导入） | 提供 `setup(ctx)`；页面钩子是运行期被调用的函数 |
| `config.schema.json` | 否 | 宿主配置模块 | 定义用户可改的配置项、默认值、范围，驱动设置界面自动生成 |

### 2.3 启动时宿主做了什么

顺序固定，任何一步失败只影响该插件：

```
扫描 plugins/ 下所有子目录
  └─ 读 plugin.json 并校验（失败 → 记入失败清单，继续扫描）
       └─ 按 dependencies.plugins 拓扑排序（有环 → 整批拒绝）
            └─ 跳过被停用的插件
                 └─ 逐个：核对 services.requires → 导入 entry → 调 setup(ctx)
                      └─ 汇总为 {loaded, failed, services}
```

真源：`Python/jml/host/loader.py`（`discover` / `topo_sort` / `load_all` / `_load_single`）。

## 三、plugin.json 字段规范

### 3.1 完整字段表

| 字段 | 必需 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | ✅ | string（非空） | — | 插件唯一标识；用作数据目录名、配置路径、模块名 |
| `name` | ✅ | string（非空） | — | 界面显示名 |
| `version` | ✅ | string（非空） | — | 插件自身版本，如 `1.0.0`；仅展示，不参与比较 |
| `api_version` | ✅ | integer | — | 必须等于 `1` |
| `entry` | ✅ | string | — | 入口文件名，必须 `.py`，必须在插件目录内 |
| `services` | ✅ | object | — | `{ "provides": [...], "requires": [...] }`，可为空数组 |
| `pages` | ✅ | array | — | 页面清单，元素 `{id, title, template}`；至少一个才有界面入口 |
| `description` | ❌ | string | `""` | 插件说明，显示在插件管理页 |
| `dependencies` | ❌ | object | `{"plugins": []}` | `{ "plugins": ["其它插件 id", ...] }` |
| `config` | ❌ | object | `{}` | `{ "schema": "config.schema.json" }` 或内联 schema 对象 |
| `development_sample` | ❌ | bool | `false` | 是否为开发样例，仅供界面展示标记 |

一份最小可用的清单：

```json
{
  "id": "hello_world",
  "name": "示例插件",
  "version": "1.0.0",
  "api_version": 1,
  "description": "最小插件示例。",
  "entry": "main.py",
  "services": { "provides": [], "requires": [] },
  "pages": [
    { "id": "hello_world.main", "title": "示例页面", "template": "list" }
  ],
  "config": { "schema": "config.schema.json" },
  "development_sample": true
}
```

### 3.2 逐字段规则

#### id

- 必须是非空字符串。
- 建议用下划线小写，如 `zip_browser`。
- 它同时是：数据目录 `%APPDATA%/JML/plugins/{id}/data`、配置文件 `.../{id}/config.json`、Python 模块名 `_jml_plugin_{id}` 的组成部分。
- 页面 id 建议加 `{id}.` 前缀（如 `zip_web.main`），便于一眼看出归属。

关于字符集：宿主**只校验"非空字符串"**，不限制字符。但 `id` 会被拼进目录路径和 Python 模块名，所以请自己避开这些：

| 不要用 | 原因 |
| --- | --- |
| `/` `\` `:` `*` `?` `"` `<` `>` `|` | Windows 文件名非法字符，数据目录创建会失败 |
| 空格、中文、`#` `%` `&` | 路径与模块名可用，但在命令行、日志、URL 里容易出问题 |
| 以 `.` 开头 | 目录本身会被扫描器当成隐藏目录跳过 |
| 与现有插件重名的 id | 后加载的会覆盖前者的数据目录与配置，等于数据串台 |

推荐：`^[a-z][a-z0-9_]{1,40}$`。

#### version

非空字符串，推荐语义化版本。宿主**不做**版本比较，升级插件直接覆盖目录即可。

#### api_version

必须是整数 `1`。写 `"1"`（字符串）、`1.0`（浮点）、`true`（布尔）都会被拒绝。

#### entry

- 必须指向 `.py` 文件，相对插件目录，例如 `"main.py"` 或 `"pkg/app.py"`。
- 不允许越出插件目录（`../` 会被拒绝）。
- 文件必须真实存在，否则加载失败。

#### services

```json
"services": {
  "provides": [{ "name": "archive_reader", "version": 1 }],
  "requires": [{ "name": "jm.session", "version": 1 }]
}
```

- `provides`：本插件对其它插件**提供**的服务（在 `setup` 里调 `ctx.register_service` 真正注册）。
- `requires`：本插件**需要**的服务（宿主在导入前就核对，缺了直接不加载）。
- `version` 必须是整数；同名服务在同一数组内不得重复。
- 服务是"约定俗成的能力名"，不是类型系统：调用方只需要知道服务名、版本、方法名和返回结构。

#### pages

```json
"pages": [
  { "id": "favorites.main", "title": "收藏夹", "template": "list" },
  { "id": "favorites.detail", "title": "详情", "template": "action" }
]
```

- 每项必须有 `id` / `title` / `template` 三个字段，全部非空（`template` 见下表）。
- 同一插件内页面 `id` 不得重复。
- **页面必须在清单里声明过，才能在 `setup` 里注册钩子**。注册未声明的页面会直接让插件加载失败（这条是硬约束，防止插件注册别人的页面）。
- 页面数量决定功能入口层级：1 个页面时点插件直接进入；多个页面时先弹出页面选择列表。
- 声明了页面却没写加载钩子 → 进入页面时显示"未实现加载钩子"，不会崩。

| template | 用途 | 状态 |
| --- | --- | --- |
| `list` | 分页列表 + 筛选 + 行内按钮（收藏夹、下载历史） | ✅ 可用 |
| `browser` | 文件夹选择 + 文件列表 + 条目内翻图（ZIP 浏览） | ✅ 可用 |
| `action` | 操作台：文件列表 + 状态文案 + 一组按钮（ZIP 网页浏览） | ✅ 可用 |
| `form` | 表单 | ❌ 宿主功能页暂不渲染，写了会显示"暂不支持" |

#### dependencies.plugins

```json
"dependencies": { "plugins": ["zip_browser"] }
```

- 语义是"**装配顺序依赖**"：被依赖的插件先装载。
- 被依赖的插件被停用或装载失败时，本插件会被拒绝加载，原因写"缺少依赖插件 xxx（该插件已停用/未能加载）"。
- **注意区分两件事**：需要别人的**服务**要写 `services.requires`；需要别人的**装配顺序**要写 `dependencies.plugins`。详见【七、服务协作】里的"顺序陷阱"。

#### config

```json
"config": { "schema": "config.schema.json" }
```

- `schema` 可以是同目录文件名（字符串），也可以直接内联一个对象。
- 缺省时插件没有可配置项，设置界面也不会出现该插件的分组。

#### development_sample

布尔值，仅用于界面标记"这是开发样例"。默认 `false`。

### 3.3 校验失败信息对照表

宿主对清单的校验是"遇到第一个错误就报出来"，消息都是中文。对照表用于自查：

| 情况 | 宿主给出的消息 |
| --- | --- |
| 目录里没有 plugin.json | `插件目录 {目录名} 缺少 plugin.json，无法加载` |
| JSON 语法错误 | `插件 {目录名} 的 plugin.json 损坏或无法读取: {原因}` |
| 顶层不是对象 | `插件 {目录名} 的 plugin.json 顶层必须是 JSON 对象` |
| 缺必填字段 | `插件 {id/目录名} 的 plugin.json 缺少必填字段: {字段}` |
| api_version 不是整数 | `插件 {id} 的 api_version 必须是整数，实际为 '1'` |
| api_version 不等于 1 | `插件 {id} 的协议版本不兼容: 插件 api_version=2, 宿主支持 api_version=1，拒绝加载` |
| id 为空 | `插件 {目录名} 的 id 必须是非空字符串` |
| name/version/entry 为空 | `插件 {id} 的字段 entry 必须是非空字符串` |
| entry 不是 .py | `插件 {id} 的 entry 必须指向 .py 文件，实际为 'main.txt'` |
| entry 越界 | `插件 {id} 的 entry 不得指向插件目录之外: '../evil.py'` |
| entry 不存在 | `插件 {id} 的入口文件不存在: main.py` |
| services 不是对象 | `插件 {id} 的 services 必须是 JSON 对象` |
| provides/requires 不是数组 | `插件 {id} 的 services.requires 必须是数组` |
| 服务项缺字段 | `插件 {id} 的 services.provides[0] 缺少必填字段: version` |
| 服务版本不是整数 | `插件 {id} 的 services.provides[0].version 必须是整数` |
| 同数组内服务重名 | `插件 {id} 的 services.provides 中服务名重复: archive_reader` |
| pages 不是数组 | `插件 {id} 的 pages 必须是数组` |
| 页面缺字段 | `插件 {id} 的 pages[0] 缺少必填字段: template` |
| 页面 id 重复 | `插件 {id} 的页面 id 重复: xxx.main` |
| template 非法 | `插件 {id} 的 pages[0].template 非法: 'table', 允许值: list, browser, action, form` |
| dependencies 形状错 | `插件 {id} 的 dependencies.plugins 必须是插件 id 字符串数组` |
| config 不是对象 | `插件 {id} 的 config 必须是 JSON 对象` |
| description 不是字符串 | `插件 {id} 的 description 必须是字符串` |
| development_sample 不是布尔 | `插件 {id} 的 development_sample 必须是布尔值` |
| 依赖插件缺失 | `插件 {id} 缺少依赖插件 {dep}（已声明但未安装或被停用）` |
| 依赖成环 | `插件依赖存在环，拒绝加载整环。环成员: a, b` |
| 缺服务 | `插件 {id} 缺少服务 {name}/版本 {ver}` |
| 没有 setup | `插件 {id} 的入口模块缺少 setup(ctx) 函数` |
| 入口导入报错 | `插件 {id} 的入口模块执行失败: ValueError: xxx` |
| setup 抛异常 | `setup 执行失败: RuntimeError: xxx` |

真源：`Python/jml/host/manifest.py`（清单校验）与 `Python/jml/host/loader.py`（装配校验）。

### 3.4 小结

清单就是一份"静态声明"，能省则省：必需字段 7 个，其余按需。写清单时记住两条硬规则——`api_version` 只能是整数 1；`pages` 里没写的东西，`setup` 里也注册不了。

## 四、config.schema.json 配置规范

### 4.1 引用方式

`plugin.json` 里两种写法都行：

```json
"config": { "schema": "config.schema.json" }
```

```json
"config": {
  "schema": {
    "keep_count": { "type": "integer", "default": 200, "min": 10, "max": 10000, "label": "保留条数" }
  }
}
```

推荐用独立文件，便于阅读和校验。

### 4.2 配置项规则（每个 key 一个规则对象）

```json
{
  "keep_count": {
    "type": "integer",
    "default": 200,
    "min": 10,
    "max": 10000,
    "label": "保留条数"
  }
}
```

| 规则字段 | 必需 | 说明 |
| --- | --- | --- |
| `type` | ✅ | `string` / `integer` / `number` / `boolean` 之一 |
| `default` | 建议 | 默认值，必须符合 `type`；不写则按类型给空值（`""` / `0` / `0.0` / `false`） |
| `enum` | ❌ | 允许值数组，配合 `type: string` 使用，界面上渲染为下拉框 |
| `min` / `max` | ❌ | 数值范围（仅 `integer` / `number` 有意义，不可比较类型会跳过） |
| `required` | ❌ | 为 `true` 且没有 `default` 时，**插件加载直接失败**（配置无值可用） |
| `label` | 建议 | 界面显示名；也接受 `title`；都没有就显示 key |
| `ui` | ❌ | 显式指定控件类型：`text` / `password` / `number` / `bool` / `select` / `path` |

`ui` 的自动推导：显式写了就用写的；有 `enum` 用 `select`；否则 `string→text`、`integer|number→number`、`boolean→bool`。

真实样例（`plugins/download_history/config.schema.json`）：

```json
{
  "keep_count": {
    "type": "integer",
    "default": 200,
    "min": 10,
    "max": 10000,
    "label": "保留条数"
  }
}
```

真实样例（`plugins/favorites/config.schema.json`）：

```json
{
  "last_folder_id": { "type": "string", "default": "", "label": "上次打开的收藏夹" },
  "sort": {
    "type": "string",
    "default": "mr",
    "enum": ["mr", "mp", "mv"],
    "label": "排序"
  }
}
```

### 4.3 密码 / 敏感项

`ui: "password"` 的配置项有三条特殊规则：

1. **不能声明非空 `default`**（会直接报错：`密码项 xxx 不得声明非空 default`）。
2. 用户填写的值**永不落盘**（`config.json` 里不写这个键）。
3. 读给界面时，值恒为空字符串，另外给一个 `has_value` 表示"已设置过"。

所以密码项只适合"一次写入、运行期使用"的场景；需要持久保存的凭据（Cookie、Token）请自己放进 `ctx.data_dir`，并按项目安全红线做脱敏。

### 4.4 存储与回退

- 存储位置：`%APPDATA%/JML/plugins/{id}/config.json`，与插件数据目录同根。
- 写入方式：先写 `.tmp` 再原子替换，不会写出半个文件。
- 读取时的容错：
  - 文件不存在 / 内容坏 / 顶层不是对象 → **全部用默认值**，不报错；
  - `config.json` 里存在、但 schema 里已删除的键 → 忽略；
  - 存量值与 schema 校验不符（类型错、超出 min/max、不在 enum 内）→ 该键回退默认值。

### 4.5 插件里怎么读写配置

```python
def setup(ctx):
    keep = ctx.config_get("keep_count")   # 已校验、已回退，直接可用
    ...
    ctx.config_set("keep_count", 500)     # 校验通过后原子落盘
```

`ctx` 的完整方法表见【5.3】。

### 4.6 小结

配置 schema 管三件事：界面上出什么控件、默认值是多少、非法值怎么办。插件代码里永远拿"已经规范化过的值"，不需要自己再判类型。

## 五、main.py 与 setup(ctx)

### 5.1 setup 是唯一入口

宿主导入入口文件后，只认一个函数：

```python
def setup(ctx) -> None:
    ...
```

- 没有 `setup` 或不可调用 → 加载失败（`入口模块缺少 setup(ctx) 函数`）。
- `setup` 抛任何异常 → 加载失败（`setup 执行失败: 类型: 消息`），已注册的页面钩子会被撤销，不留半装状态。
- `setup` 里应该完成：取依赖服务、构造页面对象、注册页面/动作/图片钩子、（可选）注册服务、订阅事件。
- `setup` 里不应该做：长时间网络请求、阻塞等待、改 `sys.path`、假设只被调用一次（重新装配时会再调用一次）。

### 5.2 页面对象的一般写法

四个现有插件都是同一个套路：一个类持有 `ctx` 和依赖，`load()` 返回 JSON，动作方法各管一件事，`setup` 里做注册。

```python
class MyPage:
    def __init__(self, ctx):
        self._ctx = ctx

    def load(self, params):
        page = self._page_of(params)
        return {
            "columns": [{"key": "title", "title": "标题"}],
            "rows": [...],
            "page": page,
            "page_size": 50,
            "total": 120,
            "total_pages": 3,
            "row_actions": [{"id": "detail", "title": "详情", "primary": False}],
            "empty_text": "还没有记录。",
        }

    def action_detail(self, payload):
        row = payload.get("row") or {}
        return {"ok": True, "message": f"详情：{row.get('title', '')}"}


def setup(ctx) -> None:
    page = MyPage(ctx)
    ctx.register_page("my_plugin.main", page.load)
    ctx.register_page_action("my_plugin.main", "detail", page.action_detail)
```

### 5.3 ctx API 全表

| 成员 | 签名 | 说明 |
| --- | --- | --- |
| `ctx.plugin_id` | 属性 `str` | 本插件 id |
| `ctx.data_dir` | 属性 `str` | 可写数据目录绝对路径（宿主已创建好） |
| `ctx.get_service` | `(name: str, version: int) -> object` | 取服务对象；不存在抛 `DependencyError` |
| `ctx.call_service` | `(name, version, method, payload) -> dict` | 远程调用服务方法；自动注入 `_caller = "plugin:{id}"` |
| `ctx.register_service` | `(name: str, version: int, ref) -> None` | 注册本插件提供的服务；重名抛 `ServiceError` |
| `ctx.subscribe` | `(event_type: str, handler) -> None` | 订阅事件；未知事件类型抛 `PluginError` |
| `ctx.config_get` | `(key: str) -> object` | 读配置（已校验、已回退默认值） |
| `ctx.config_set` | `(key: str, value) -> None` | 写配置（校验后原子落盘，失败抛 `ConfigError`） |
| `ctx.register_page` | `(page_id: str, loader_fn) -> None` | 注册页面加载钩子 |
| `ctx.register_page_action` | `(page_id: str, action_id: str, handler) -> None` | 注册页面动作钩子 |
| `ctx.register_page_image` | `(page_id: str, resolver) -> None` | 注册页面图片钩子 |
| `ctx.log` | `(message: str) -> None` | 写宿主日志，自动加 `[plugin:{id}]` 前缀 |

三个注册方法的硬约束：

- `page_id` 必须是非空字符串，且**必须在本插件 `plugin.json` 的 `pages[]` 中声明过**；否则抛 `PageError`，插件加载失败。
- `action_id` 必须是非空字符串。
- 同一个 `page_id` 的同一个 `action_id` 重复注册会被拒绝。

### 5.4 生命周期时序

```
应用启动
  → bootstrap(plugins_dir)
      → 扫描 + 校验清单
      → 拓扑排序
      → 对每个插件：核对 requires → 导入 entry → setup(ctx)   ← 插件代码在这里第一次跑
  → 用户点开插件功能页
      → plugin_page_load(plugin_id, page_id, params)          ← 每次进页面/翻页都调
      → 用户点行内按钮
          → plugin_page_action(plugin_id, page_id, action_id, payload)
      → 用户翻图（browser 模板）
          → plugin_page_image(plugin_id, page_id, index)       ← 原始字节，不是 JSON
  → 用户在设置里改配置
      → 宿主直接写 config.json（插件无需参与）
```

重新装配（例如重启应用）会让 `setup` 再跑一次；插件不要在模块级放不可重入的状态，重要状态放 `ctx.data_dir` 里的文件。

### 5.5 重新装配：哪些会被清，哪些不会

`setup` 有可能被调用多次（`loader.load_all` 每跑一次就是一轮完整装配；测试和将来的热重载都会触发）。装配开始时宿主会重置：

| 会被清空 | 不会被清空 |
| --- | --- |
| 页面加载/动作/图片钩子（`PAGE_REGISTRY` 整表重置） | 事件总线（`events.BUS` 的订阅者） |
| 内存里的配置对象（`_CONFIG_STORES` 清空后按磁盘 `config.json` 重建） | 服务注册表 `REGISTRY`（宿主服务每次重新注册，插件服务不会自动注销） |
| 装载清单缓存 `_LOADED_MANIFESTS` | `sys.modules` 里的旧模块对象（模块名固定 `_jml_plugin_{id}`，会被新模块替换，但已持有旧引用的地方仍指向旧对象） |

由此产生两个真实陷阱，写插件时请避开：

1. **事件订阅会累加**。`ctx` 没有提供 `unsubscribe`，`setup` 里每 `subscribe` 一次就多一个订阅者。重装 N 次后同一个事件会被处理 N 遍，而且旧的 handler 还连着上一轮的页面对象。对策：订阅逻辑要幂等（handler 里先判断状态，或只做纯通知），别在 handler 里累积计数、写文件追加。
2. **插件注册的服务不会随重装注销**。`REGISTRY` 里同名同版本的重复注册会被拒绝并抛 `ServiceError`，所以重新装配时可能看到"服务 xxx 已被注册"。对策：`ctx.register_service` 用 try/except 兜住 `ServiceError`，或把 `ctx.register_service(...)` 放在一个"已存在就跳过"的判断里。

### 5.6 停用：用户不让你加载时

用户在插件管理页把插件停用后，宿主把 id 写进 `<数据根>/plugins/disabled.json`（默认 `%APPDATA%/JML/plugins/disabled.json`，真源 `Python/jml/host/plugin_state.py`）。

- 停用的插件**不会被导入**，`setup` 不执行，功能入口不出现；状态里 `enabled=false`、`blocked_reason` 为"插件已停用"。
- 停用**不是卸载**：目录、配置、`data_dir` 都保留，重新启用后原样恢复。
- 停用列表在**下次装配时**生效（宿主不做热卸载），所以管理页点完停用需要重启应用。
- 别的插件如果 `dependencies.plugins` 依赖它，会跟着加载失败，原因写"缺少依赖插件 xxx（该插件已停用）"；仅通过 `services.requires` 需要它的服务时，同样是这个结果。

插件自己没法主动"申请停用"，也不该在 `setup` 里读写 `disabled.json`（那是宿主的状态文件）。

### 5.7 退场：插件没有 teardown

宿主**不提供**卸载回调，没有 `teardown()` / `shutdown()` 之类要实现的函数。插件退出只有两种方式：应用进程结束，或下次装配覆盖掉旧的钩子。

所以：

- 不要在 `setup` 里起非 daemon 线程（`threading.Thread(daemon=False)` 会让进程关不掉）；确实要后台任务就 `daemon=True`，并自己设退出标志。
- 打开的文件/压缩包用 `with` 管好生命周期，别在模块级长期持有句柄（Windows 上会锁文件，用户删不掉）。
- 需要在退出前落盘的状态，别指望退场钩子——在每次变更后就写 `ctx.data_dir`。

## 六、页面模板契约

这一节是插件开发里最容易踩坑的地方：**C# 按固定字段名渲染，字段名写错不报错，只是不显示。**

### 6.1 加载参数：宿主每次传什么

`plugin_page_load` 的 `params` 是一个 JSON 对象，由 C# 端按当前界面状态构造（真源：`Pages/PluginPageHost.xaml.cs` 的 `LoadAsync`）：

| 触发场景 | 传入参数 |
| --- | --- |
| 初次进入页面 | `{"page": 1}` |
| 列表翻页（list / 文件列表） | `{"page": N}` |
| 筛选下拉变化 | `{"page": 1, "<筛选 key>": "<选中的值>"}`，仅 `list` 模板 |
| 选择文件夹（browser / action） | `{"page": 1, "folder": "<目录>", "item_index": -1}` |
| 动作后整页刷新（`refresh: true`） | `{"page": 1}`（browser 模板保留当前文件页） |

规则：

- `page` 从 1 开始；C# 已经保证不会传 0 或负数。
- `folder` 只在用户选过文件夹、或插件上次返回过 `folder` 提示时出现；**不要把 `params["folder"]` 当成一定有**，用 `params.get("folder", "")`。
- `item_index` 是"文件列表里第几项"的序号，0 起；`-1` 表示"回到列表"。
- 除以上键外，其它键都是插件自己的筛选键，直接取用即可。

### 6.2 返回信封

页面加载钩子只返回**数据对象**，`template` 和 `title` 由宿主从清单里取，插件不用管：

```python
def load(params):
    return { ... }        # 必须是 dict，否则报"加载钩子必须返回 dict"
```

宿主最终交给 C# 的是：

```json
{
  "ok": true,
  "template": "list",          // 来自 plugin.json 的 pages[].template
  "title": "收藏夹",            // 来自 plugin.json 的 pages[].title
  "data": { ...你返回的 dict... }
}
```

### 6.3 list 模板

列表模板渲染成"卡片列表"，字段如下（真源：`Bridge/Dto/PluginPageDtos.cs` 的 `PluginListPageDto`、`Pages/PluginPageHost.xaml.cs` 的行视图）：

| 字段 | 类型 | 必需 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `columns` | array | 建议 | `[]` | 列定义 `{key, title, width?}`；`width` 可省略 |
| `rows` | array | ✅ | — | 每行一个对象，键对应行数据 |
| `page` | int | 建议 | `1` | 当前页，从 1 开始 |
| `page_size` | int | 建议 | `50` | 每页条数 |
| `total` | int | 建议 | `0` | 总条数 |
| `total_pages` | int | 建议 | `1` | 总页数，用于翻页按钮启用状态 |
| `row_actions` | array | ❌ | `[]` | 行内按钮 `{id, title, primary?}` |
| `row_double_click_action` | string | ❌ | `""` | 双击行触发的动作 id；空表示不响应 |
| `filters` | array | ❌ | `[]` | 筛选下拉 `{key, label, options: [{value, label}], value}` |
| `empty_text` | string | ❌ | — | 无数据时显示的文案 |

#### 行里放什么：卡片渲染的字段约定

`list` 不是"表头 + 单元格"，而是一行一张卡片，宿主按固定的行字段拼装。**这些字段名是约定，写错就不显示**：

| 行字段 | 渲染位置 |
| --- | --- |
| `title` | 主标题（14px）；没有则用第一个有值的列 |
| `author` | 标题右侧灰色副标题（12px）；没有则用 `book_id` |
| `result` | 标签（11px） |
| `page_count` | 标签"页数 N"（值为 0 或空则不显示） |
| `click_count` | 标签"收藏数 N"（值为 0 或空则不显示） |
| `description` | 标签行右侧灰色描述；没有则用 `path` |
| `updated` | 底部元信息"更新 <时间>"（时间能解析就格式化，否则原样显示） |
| `time` | 底部元信息"下载 <时间>" |
| `book_id` | 底部元信息"本子号 N"（若已作为副标题显示则不重复） |
| `thumb_book_id` | 封面缩略图的**JM 本子号**（见下） |
| 其它列 key | 若在 `columns` 里声明且不在上述名单内，按"列名 值"补成标签，**最多 3 个** |

两个额外规则：

- 行字段的标量值支持字符串 / 数字 / 布尔；对象和数组会被忽略（显示为空）。
- `thumb_book_id` 的值会被宿主当成 **JM 本子号**去取封面图（复用搜索页的封面能力），**不是**让插件提供图片。自定义插件不要用它显示自己的图片，否则只会显示"取图失败"的暗红叉。

#### 行内按钮回传的 payload

用户点某行的按钮时，C# 传给你：

```json
{
  "row": { ...该行原始对象... },
  "row_index": 3,
  "page": 2
}
```

双击触发的 `row_double_click_action` 走同一条通道、同一个 payload 结构。

#### 筛选

```json
"filters": [
  {
    "key": "sort",
    "label": "排序",
    "value": "mr",
    "options": [
      {"value": "mr", "label": "最新"},
      {"value": "mp", "label": "最多图"},
      {"value": "mv", "label": "最多浏览"}
    ]
  }
]
```

用户改选后，宿主以 `{"page": 1, "sort": "<新值>"}` 重新加载。所以 `params` 里除了 `page` / `folder` / `item_index`，其余键都可能是筛选值。

#### 示例

```json
{
  "columns": [
    {"key": "title", "title": "标题"},
    {"key": "author", "title": "作者"}
  ],
  "rows": [
    {"title": "示例条目", "author": "某人", "book_id": "123456", "thumb_book_id": "123456",
     "page_count": 32, "click_count": 1200, "result": "成功", "time": "2026-10-20 12:30:00"}
  ],
  "page": 1,
  "page_size": 50,
  "total": 1,
  "total_pages": 1,
  "row_actions": [
    {"id": "detail", "title": "详情", "primary": false},
    {"id": "download", "title": "下载", "primary": true}
  ],
  "empty_text": "还没有记录。"
}
```

### 6.4 browser 模板

"文件夹 → 文件列表 → 条目内看图"三段式（真源：`PluginBrowserPageDto` + `PluginPageHost` 的 browser 分支）。**同一个 `load` 钩子要能返回三种形态**，靠 `params` 里的字段区分：

| 形态 | 触发 | 你应返回 |
| --- | --- | --- |
| 文件列表 | 进入页面、翻页、选文件夹 | `items` 为文件列表，`item_index = -1` |
| 条目内看图 | 双击文件（`item_index >= 0`） | `items` 仍是文件列表，`item_index` 为当前文件，`image_count` 为该条目图片总数 |
| 图片翻页 | 用户点上一张/下一张 | **不会重新调 `load`**；宿主只调 `plugin_page_image` |

字段表：

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `items` | array | ✅ | `[{name, path}]`；文件列表或条目内列表 |
| `page` | int | 建议 | 当前文件列表页 |
| `page_size` | int | 建议 | 每页文件数 |
| `total` / `total_pages` | int | 建议 | 文件总数 / 总页数 |
| `item_index` | int | ✅ | 当前打开的条目下标；`-1` 表示未打开任何条目 |
| `image_index` | int | ❌ | 当前显示第几张（0 起）；翻图时宿主用自己的序号，回传只作参考 |
| `image_count` | int | ✅ | 当前条目的图片总数（`item_index = -1` 时可为 0） |
| `empty_text` | string | ❌ | 空列表文案 |
| `allow_folder_choice` | bool | ❌ | 是否显示"选择文件夹"按钮 |
| `folder` | string | ❌ | 当前选中的文件夹，用于界面显示与下次加载 |

交互回传：

- 双击文件 → `load({"page": N, "item_index": 3, "folder": "..."})`
- 返回列表 / Esc → `load({"page": N, "item_index": -1, "folder": "..."})`
- 选择文件夹 → `load({"page": 1, "folder": "<新目录>", "item_index": -1})`
- 看下一张图 → 宿主直接把 `index + 1` 传给 `plugin_page_image`，**不重新调 load**

所以 `load` 里必须记住"当前条目有哪些图"，并让 `plugin_page_image(index)` 能按 index 取出对应字节。index 的语义完全由你定义，只要和 load 返回的 `image_index` 对得上。

### 6.5 action 模板

操作台：一个文件列表 + 一段状态文案 + 一组按钮（真源：`PluginActionPageDto`）。

| 字段 | 类型 | 必需 | 说明 |
| --- | --- | --- | --- |
| `items` | array | ❌ | `[{name, path}]`，文件选择列表 |
| `state` | string | 建议 | 状态机标识，如 `"stopped"` / `"running"`；宿主不解释，只转给你自己 |
| `status_text` | string | 建议 | 显示给用户的状态文案（中文） |
| `actions` | array | ✅ | 按钮 `[{id, title}]` |
| `port` | int | ❌ | 端口号（如 ZIP 网页浏览的本地 HTTP 端口），界面展示用 |
| `url` | string | ❌ | 可供"在浏览器中打开"的地址；**必须是 http/https**，否则宿主不显示打开/复制按钮 |
| `empty_text` | string | ❌ | 空列表文案 |
| `allow_folder_choice` | bool | ❌ | 是否显示"选择文件夹"按钮 |
| `folder` | string | ❌ | 当前选中的文件夹 |

按钮点击回传：

```json
{
  "item": {"name": "a.zip", "path": "D:/x/a.zip"},
  "item_index": 2
}
```

没选文件时 `item` 为 `null`、`item_index` 为 `-1`。

动作处理函数返回：

```python
return {
    "ok": True,
    "refresh": True,        # 让界面整页重新加载（会再调一次 load）
    "data": {...},          # 可选：直接替换当前页数据
    "message": "已启动。",   # 可选：状态栏文案
    "intent": {"kind": "download", "book_ids": ["123"]},  # 可选：见下
}
```

- `refresh` 与 `data` 二选一即可；只改状态文字的话两者都不给、给 `message` 就行。
- `message` 会显示在状态区，适合"启动成功/失败"这类反馈。

#### intent：把界面动作转发给主窗口

`intent` 是给 C# 的"转发意图"，宿主原样透传、不解释含义。当前支持的两种：

| `kind` | 附带字段 | 宿主行为 |
| --- | --- | --- |
| `detail` | `book_id` | 打开主窗口的详情页 |
| `download` | `book_ids`（数组） | 打开主窗口下载页并按这些 id 开始下载 |

收藏夹插件的"下载"按钮就是这么做的：插件自己不做下载，只回传 `intent`，由宿主走既有下载流程。这保持了"C# 不管业务、插件不复制业务"的分工，新插件要触发既有功能时优先用这个方式。

### 6.6 form 模板：暂不可用

`form` 虽然出现在允许值里，但宿主功能页没有对应的渲染器，进入会显示：

```
[NOT_IMPLEMENTED] form 模板由设置与账号界面渲染，插件功能页暂不渲染该模板
```

需要复杂表单时，用 `list` 的筛选 + `action` 的按钮组合绕开，或者把配置放进 `config.schema.json` 由设置界面自动生成。写 `form` 的插件能装上，但页面打不开。

### 6.7 图片通道：plugin_page_image

```python
def image(index: int) -> bytes | None:
    ...   # 返回图片原始字节；返回 None 表示这张没有图
```

注册方式：`ctx.register_page_image("zip_browser.main", image)`。

- 只返回**字节**，不包 JSON；C# 拿到后自己解码成图片。
- 任何失败都返回 `None`（不要抛异常），界面会显示占位图。
- `index` 的含义由插件定义；`browser` 模板下宿主传的是"当前条目内的图片序号"。
- 图片较大时不建议每次重新解码硬盘文件，可在插件内做一层小缓存。

### 6.8 数据边界：什么能返回，什么会炸

宿主把插件的返回值和动作结果原样交给 C# 反序列化（`JsonSerializer` → `JsonElement`），所以**插件返回的必须是能 JSON 化的纯数据**。

可以返回：`str` / `int` / `float` / `bool` / `None` / `list` / `dict`（键必须是字符串）。

会出问题的值（界面显示 `INVALID_DATA` 或整页报错）：

| 返回这个 | 结果 |
| --- | --- |
| `datetime.datetime` / `datetime.date` | 序列化失败，页面报 `INVALID_DATA` |
| `pathlib.Path` | 同上 |
| `bytes` | 同上（图片只能走【6.7】的独立通道） |
| `set` / `tuple` | 同上（转成 `list` 再返回） |
| `float("nan")` / `float("inf")` | JSON 不允许，反序列化失败 |
| 自定义对象（不继承 list/dict） | 同上 |
| 值本身是"很大"的整数（超过 2^63） | C# 侧读成 double 时精度丢失，界面上数字会变 |

统一做法：在钩子里就把对象转成基本类型再 return，例如

```python
def load(self, params):
    return {
        "items": [{"name": item.name, "path": str(item.path)} for item in items],
        "updated": dt.strftime("%Y-%m-%d %H:%M"),   # 不要直接返回 dt
    }
```

另外两条边界：

- **键名区分大小写**。C# 按固定字段名取值，`Page` 不会被当成 `page`。
- **不要依赖宿主保留多余字段**。你在返回里塞的自定义键会被原样带给 C#，但界面不会显示；需要跨次保留的状态请自己存 `ctx.data_dir`，或放进 `rows` 里随行回传（行 payload 的 `row` 会把你塞的键原样还给你）。

### 6.9 模板小结

记住三句话：`list` 是卡片不是表格（行字段名固定）；`browser` 的 `load` 要能同时处理"列表页"和"打开条目"两种输入；`action` 的按钮回传里带着当前选中的文件对象。字段名以【6.3】【6.4】【6.5】的表格为准，写错的字段不会报错，只是不显示。

## 七、服务协作

### 7.1 宿主提供的服务（版本均为 1）

真源：`Python/jml/services/host_services.py`。

| 服务 | 方法 | 参数 | 返回 |
| --- | --- | --- | --- |
| `jm.search` | `search` | `{keyword, page}` | 搜索结果分页数据 |
| `jm.search` | `get_page` | `{keyword?, page}` | 同上；`page > 1` 时可省略 `keyword`，沿用本会话上次的关键词 |
| `jm.detail` | `get_detail` | `{book_id}` | 本子详情 |
| `jm.download` | `start_batch` | `{book_ids, target_dir, work_dir?}` | 批次信息（含 `batch_id`） |
| `jm.download` | `cancel_batch` | `{batch_id}` | 取消结果 |
| `jm.download` | `get_progress` | `{batch_id}` | 进度 |
| `jm.account` | `login_status` / `ensure_login` / `login` / `logout` | `{}` | 登录状态 |
| `jm.session` | **不是 JSON 服务** | — | 对象服务，`get_client()` 返回客户端 |

调用方式（JSON 服务）：

```python
result = ctx.call_service("jm.detail", 1, "get_detail", {"book_id": "123456"})
```

- 方法名不在白名单 → 报错并列出允许值。
- 服务内部异常不会抛给你，而是返回一个错误信封（含 `error_code` / `error_message`）。**调用后必须检查返回**。
- `ctx.call_service` 会自动注入 `_caller = "plugin:{你的 id}"`，宿主用它隔离会话，你不用管。

对象服务（`jm.session`）用法不同：

```python
session = ctx.get_service("jm.session", 1)
client = session.get_client()        # 需要已登录，未登录抛 NOT_LOGGED_IN
```

### 7.2 插件之间提供服务

提供方：

```json
"services": { "provides": [{ "name": "archive_reader", "version": 1 }], "requires": [] }
```

```python
class Reader:
    def open(self, path): ...
    def read_page(self, path, index): ...

def setup(ctx):
    ctx.register_service("archive_reader", 1, Reader())
```

消费方：

```json
"services": { "provides": [], "requires": [{ "name": "archive_reader", "version": 1 }] }
```

```python
reader = ctx.get_service("archive_reader", 1)   # 命名空间包式对象，直接调方法
```

### 7.3 两种服务形态

| 形态 | 提供方 | 消费方 | 适合 |
| --- | --- | --- | --- |
| **对象服务** | 直接 `register_service(name, 1, 对象)` | `ctx.get_service(...)` 拿到对象后调方法 | 同进程内的 Python 能力复用（ZIP 读取、会话客户端） |
| **JSON 服务** | 对象带 `call(method, payload) -> dict` 方法，并声明 `METHODS` 白名单 | `ctx.call_service(name, 1, method, payload)` | 跨层调用、返回值需要统一错误信封 |

宿主那 5 个服务是 JSON 服务（`jm.session` 除外），因为它们要被 C# 通过桥接调用。**插件之间优先用对象服务**，简单直接。

### 7.4 顺序陷阱（重要）

- 拓扑排序只认 `dependencies.plugins`，**不认** `services.requires`。
- `services.requires` 只在"轮到该插件装载"时核对：如果提供方还没装，你会拿到"缺少服务"而加载失败。

所以：**要用别人的服务，除了写 `services.requires`，还要在 `dependencies.plugins` 里写上对方的 id**，否则装载顺序靠目录名字母序碰运气。

现有例子里 `zip_web` 只写了 `requires: archive_reader` 而没写 `dependencies.plugins`，能跑是因为 `zip_browser` 的 id 字母序在前。新插件不要依赖这种巧合。

### 7.5 小结

服务就是"把某个插件的 Python 能力借给别的插件用"。对象服务直接拿对象；JSON 服务统一 `call` 信封。提供方在 `setup` 里注册，消费方在 `setup` 里取，顺序靠 `dependencies.plugins` 保证。

## 八、事件总线

### 8.1 可用事件（白名单，只能订阅这些）

| 事件类型 | 必填 payload 字段 |
| --- | --- |
| `download.item_started` | `book_id`, `title` |
| `download.item_finished` | `book_id`, `title`, `ok`, `zip_path`, `error_code`, `error_message` |
| `download.batch_finished` | `total`, `success`, `failed`, `cancelled` |
| `download.log` | `level`, `message` |
| `search.page_loaded` | `keyword`, `page`, `total_pages`, `results` |
| `plugin.notification` | `level`, `title`, `message` |

订阅：

```python
def on_item_finished(payload):
    ...

def setup(ctx):
    ctx.subscribe("download.item_finished", on_item_finished)
```

规则：

- 订阅未知事件类型直接报错（`未知事件类型: 'xxx'，拒绝订阅`），插件加载失败。
- 派发时宿主会校验 `payload`：必须是 dict、必须有 `type` 字段且与事件类型一致、必须有上表的必填字段；不合规的派发会被拒绝。
- 你的 handler 抛异常不会影响别的订阅者：宿主会收集起来记入诊断（`EVENT_HANDLER_FAILED`），然后继续派发。
- 事件是"通知"，不是"命令"：handler 里不要做重活，阻塞会拖慢派发方。

### 8.2 主动发通知

插件要把消息显示给用户，用 `plugin.notification`：

```python
ctx.log("下载完成")   # 只进宿主日志
```

要弹到界面上的通知，由宿主的事件汇聚通道处理；插件侧只要保证事件 payload 合规即可。日志（`ctx.log`）里绝对不要出现账号、Cookie、Token——项目安全红线要求日志脱敏。

## 九、错误处理与诊断

### 9.1 三个失败点

| 失败点 | 后果 | 用户看到 |
| --- | --- | --- |
| `setup` 抛异常 | 整个插件装载失败，页面入口不出现 | 插件管理页里显示失败原因 |
| 页面加载钩子抛异常 | 该页面显示错误，其它页面正常 | 错误码 + 中文消息 |
| 动作钩子抛异常 | 动作失败，界面不刷新 | 错误码 + 中文消息，可重试 |

关键点：**装配期失败不影响其它插件**；页面期失败不影响其它页面。

### 9.2 错误码

插件抛出的异常会先经过 `Python/jml/core/errors.py` 的 `classify` 归类，变成"错误码 + 中文消息"，再由 C# 显示成 `[错误码] 消息`（真源：`Pages/PluginPageHost.xaml.cs` 的 `ShowError(result.ErrorCode, result.ErrorMessage)`）。

**先记住这条规则**：只有 `errors.AppError` 家族保留自己的错误码；`jml.core.protocol` 里的 `PluginError` 家族（`DependencyError` / `ServiceError` / `ConfigError` / `ProtocolVersionError` / `CircularDependencyError`）虽然名字像业务异常，但它继承的是 `Exception` 而不是 `AppError`，`classify` 认不出来，最终显示 `UNKNOWN_ERROR`。想在界面上看到具体错误码，就抛下面这些。

可以直接用的异常（抛了就有对应错误码）：

| 异常类 | 错误码 | 什么时候用 |
| --- | --- | --- |
| `InvalidArgumentError` | `INVALID_ARGUMENT` | 参数缺失/格式不对 |
| `NotFoundError` | `NOT_FOUND` | 找的记录不存在 |
| `ArchiveError` / `ArchiveNotFoundError` / `ArchiveClosedError` | `ARCHIVE_INVALID` / `FILE_NOT_FOUND` / `ARCHIVE_CLOSED` | 压缩包相关 |
| `PageOutOfRangeError` | `PAGE_OUT_OF_RANGE` | 页码越界 |
| `InvalidDataError` | `INVALID_DATA` | 数据不符合预期 |
| `ImageError` | `IMAGE_INVALID` | 图片解码失败 |
| `CancelledError` | `CANCELLED` | 用户取消 |
| `BatchNotFoundError` | `BATCH_NOT_FOUND` | 批次号不存在 |
| `InvalidCredentialsError` | `INVALID_CREDENTIALS` | 账号密码错 |
| `NotLoggedInError` | `NOT_LOGGED_IN` | 未登录 |

普通异常按类型映射（不用自己包）：

| 抛出的类型 | 归成 |
| --- | --- |
| `ValueError` / `TypeError` / `KeyError` / `IndexError` | `INVALID_DATA` |
| `TimeoutError` | `TIMEOUT` |
| `ConnectionError` | `NETWORK_ERROR` |
| `FileNotFoundError` | `FILE_NOT_FOUND` |
| `FileExistsError` | `FILE_EXISTS` |
| `PermissionError` | `PERMISSION_DENIED` |
| `OSError` | `IO_ERROR` |
| `MemoryError` | `OUT_OF_MEMORY` |
| `NotImplementedError` | `NOT_IMPLEMENTED` |
| 其它 | `UNKNOWN_ERROR` |

完整错误码清单（C# 侧只当字符串透传，不做分支）：

| 错误码 | 含义 |
| --- | --- |
| `INVALID_ARGUMENT` | 参数不合法 |
| `NOT_FOUND` | 目标不存在 |
| `NETWORK_ERROR` | 网络异常 |
| `TIMEOUT` | 超时 |
| `RESPONSE_INVALID` | 服务端返回无法解析 |
| `DOWNLOAD_PARTIAL` | 下载部分成功 |
| `JM_ERROR` | 业务层报错 |
| `PERMISSION_DENIED` | 无权限 |
| `FILE_NOT_FOUND` | 文件不存在 |
| `FILE_EXISTS` | 文件已存在 |
| `ARCHIVE_INVALID` | 压缩包损坏 |
| `ARCHIVE_CLOSED` | 压缩包已关闭 |
| `PAGE_OUT_OF_RANGE` | 页码越界 |
| `IMAGE_INVALID` | 图片无效 |
| `INVALID_DATA` | 数据不合法 |
| `IO_ERROR` | 读写失败 |
| `OUT_OF_MEMORY` | 内存不足 |
| `NOT_IMPLEMENTED` | 没实现（缺少钩子时宿主自动用这个） |
| `NOT_AVAILABLE` | 功能不可用 |
| `CANCELLED` | 已取消 |
| `BATCH_NOT_FOUND` | 批次不存在 |
| `INVALID_CREDENTIALS` | 凭据错误 |
| `NOT_LOGGED_IN` | 未登录 |
| `UNKNOWN_ERROR` | 未归类，消息里带原始异常文本 |

消息与脱敏：`classify` 会对消息做一次 `sanitize_text`——把 password / token / cookie / authorization / username / account / secret / api_key 之类的值打码，把 Bearer/Basic 令牌打码，超过 800 字符截断。所以**不要把需要保留的原文放进异常消息**，重要的诊断信息写 `ctx.log` 或落到 `ctx.data_dir` 的日志文件里。

建议：能预期的情况用 `jml.core.errors` 里的具体异常（消息写中文），意外情况让它抛出来即可，不用自己包一层。

### 9.3 日志与脱敏

- `ctx.log(msg)` 输出 `[plugin:{id}] msg`。
- 报错消息和日志里**不要**出现账号、密码、Cookie、Token；确需保留标识时先打码。
- 插件自己的诊断文件写到 `ctx.data_dir` 下，不要写项目目录。

### 9.4 小结

错误处理的目标是"失败要看得见、不要扩大"。装配期失败就让它失败（用户能在管理页看到原因）；运行期失败就抛出来（界面显示错误码），不要 `except: pass` 吞掉。

## 十、最小模板 + 自检清单

### 10.1 可直接复制的骨架

下面这套骨架是新建插件时的起点：三个文件放到 `plugins/hello_world/` 下就能被宿主扫到。注意项目里目前**没有** `hello_world` 这个目录，它是示例名，实际开发请换成你自己的插件 id。

`plugins/hello_world/plugin.json`：

```json
{
  "id": "hello_world",
  "name": "示例插件",
  "version": "1.0.0",
  "api_version": 1,
  "description": "最小插件示例：一个列表页 + 一个动作。",
  "entry": "main.py",
  "dependencies": { "plugins": [] },
  "services": { "provides": [], "requires": [] },
  "pages": [
    { "id": "hello_world.main", "title": "示例页面", "template": "list" }
  ],
  "config": { "schema": "config.schema.json" },
  "development_sample": true
}
```

`plugins/hello_world/config.schema.json`：

```json
{
  "greeting": {
    "type": "string",
    "default": "你好",
    "label": "问候语"
  }
}
```

`plugins/hello_world/main.py`：

```python
"""最小插件示例：一个列表页 + 一个行内动作。"""

PAGE_ID = "hello_world.main"


class HelloPage:
    def __init__(self, ctx):
        self._ctx = ctx

    def load(self, params):
        greeting = self._ctx.config_get("greeting")
        page = int(params.get("page", 1) or 1)
        return {
            "columns": [{"key": "title", "title": "条目"}],
            "rows": [
                {"title": f"{greeting} 第 {page} 页", "description": "来自示例插件"},
            ],
            "page": page,
            "page_size": 20,
            "total": 1,
            "total_pages": 1,
            "row_actions": [{"id": "say", "title": "打个招呼", "primary": True}],
            "empty_text": "还没有内容。",
        }

    def action_say(self, payload):
        row = payload.get("row") or {}
        title = row.get("title", "")
        self._ctx.log(f"用户点击了：{title}")
        return {"ok": True, "message": f"已处理：{title}"}


def setup(ctx) -> None:
    page = HelloPage(ctx)
    ctx.register_page(PAGE_ID, page.load)
    ctx.register_page_action(PAGE_ID, "say", page.action_say)
```

放好后重启主程序，在插件列表里就能看到"示例插件"。

### 10.2 自检清单

写完后逐条对：

- [ ] 目录在 `plugins/` 下，且有 `plugin.json` + `entry` 指向的 `.py`
- [ ] `api_version` 是整数 `1`（不是 `"1"`、不是 `1.0`）
- [ ] `pages[].id` 唯一，`template` 是 `list` / `browser` / `action` 之一（别用 `form`）
- [ ] 每个 `register_page` / `register_page_action` / `register_page_image` 的 `page_id` 都在 `pages[]` 里声明过
- [ ] 需要别的插件的服务时，`services.requires` 和 `dependencies.plugins` **都**写了
- [ ] `config.schema.json` 里每项都有合法 `type`，`required` 项都给了 `default`
- [ ] 页面 `load` 对缺失参数用 `.get(..., 默认值)`，不假设 `folder` 一定存在
- [ ] `list` 的行字段名与【6.3】表格一致（`title` / `author` / `book_id` / `time` ...）
- [ ] 动作返回 `dict`，需要刷新时给 `refresh: True`
- [ ] 图片钩子失败返回 `None`，不抛异常
- [ ] 日志里没有账号、Cookie、Token
- [ ] 插件自己重建过一遍（删掉 `__pycache__`、重启），确认从零也能装上

### 10.3 常见错误速查

| 现象 | 大概率原因 |
| --- | --- |
| 插件列表里根本没有这个插件 | `plugins/` 下不是子目录，或目录名以 `.` 开头 |
| 列表里有但显示失败 | 看失败原因一栏；多数是清单字段/entry 路径/setup 抛异常 |
| 点进页面显示"未实现加载钩子" | `pages[]` 声明了，但 `setup` 里没 `register_page` |
| 点进页面显示"未声明页面" | `register_page` 的 id 与 `pages[].id` 不一致 |
| 列表一片空白但没报错 | 行字段名写错（如把 `title` 写成 `name`），或 `rows` 不是数组 |
| 封面显示暗红十字 | `thumb_book_id` 不是有效的 JM 本子号（这个字段不能放自定义图片） |
| 按钮点了没反应 | `row_actions[].id` 与 `register_page_action` 的 `action_id` 不一致 |
| 加载时提示"缺少服务" | 提供方没装、被停用，或本插件不是先装载（补 `dependencies.plugins`） |
| 改了配置不生效 | 配置文件在 `%APPDATA%/JML/plugins/{id}/config.json`；无效值会被回退默认值 |
| `form` 页面打不开 | 宿主不支持，改用 `list` / `action` |
